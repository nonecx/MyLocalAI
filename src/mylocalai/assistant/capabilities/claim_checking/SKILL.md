# 事实核查（claim-checking）

## 1. 能力定义

核查一条网络说法的用户能力。用户给出原文，助手完成"主张拆分 → 事实证据 → 传播记录 →
双维判断 → 答案校验"（《规格》§2），按主张给出自然语言真实性判断与独立的谣言五态；
真伪裁决由用户做出，助手只述证据。

用户旅程：丢进一段原文 → 先收到零成本本地初扫（命中几条话术特征）→ 组件级进度
（"取证中/整理中"）→ 结论卡片 → 一段克制的叙述。等不及随时点"停止"，服务端协作取消、
已有结果照发。

与相邻能力的分工：

- 只想要资料、明确不要结论 → 证据研究（evidence-research）；
- 想问"有多热、为什么受关注" → 话题理解（topic-understanding）；
- 想分析"这段话怎么说的" → 言论理解（speech-understanding）。
- 用户同时要"核查真假"和"解释热度"时不拼接工具，回一句自然话术请用户选先看哪个
  （《总览》§6.3）。

适用与不适用：

- 适用：用户给出具体原文或链接转述，想要一个能回溯到证据的答复；复查旧档案；
  对某条已核查说法补充新证据。
- 不适用：只给一个词没有原文（先追问，不猜）；要求改分数/删档案（明确拒绝）；
  明确"不要结论只要资料"（转证据研究）。

## 2. 覆盖工具

| 工具 | 背后引擎 | 权限 | 成本 | 预期延迟 | 降级路径 |
|---|---|---|---|---|---|
| verify_claim | RumorAgent.analyze（七路分析 + 联网证据本 + verdict 纯函数） | write（读+写档案） | 重 | 30-120s | pipeline 退回、超时用已完成组件 |
| recheck_dossier | agent 全链路（增量批） | write | 重 | 30-120s | 同 verify_claim |

- 上表是 `src/mylocalai/assistant/registry.py` 注册表的可读摘要，权限/成本/延迟以注册表为准。
- verify_claim 的输入是一段原文（text），上限 8000 字（registry 的 MAX_TEXT_LENGTH）；
  超长原文先请用户缩减，或改用证据研究能力逐段查。
- recheck_dossier 的输入是档案号（id）：对已查过的档案增量再查一遍，追加新版本结论与
  新证据批次，不推倒重来。
- 两次核查之间由谣言库指纹兜底：相似说法再次出现时先问"秒回旧结论还是重查"，
  不擅自断言同一谣言（先问再查）。
- 工具放行受 `assistant_rules.json` 的 tool_allowlist 与权限检查控制；不过关降级为
  一次追问，绝不猜。

## 3. 硬门禁要点

《总览》§6.1 对本能力的硬门禁原文："不把风险分说成真相；搜索不到不断言为假；
结论+证据+限制默认三者齐全。"展开如下：

1. **不把风险分说成真相**。风险分、置信度是确定性代码从证据本推导的内部产物，
   前端不展示数值；叙述层不得把旧风险标签或风险分映射成"真的/假的"。谣言状态用
   独立的五态表达（传播证据不足 / 尚待核查 / 疑似谣言〔尚未证实〕/ 已证伪的谣言 /
   未发现具体问题），与真实性自然语言判断分开呈现；只有数据与取证步骤完整时才陈述
   其中某一态，否则明说"新答案契约的数据或取证步骤尚不完整"，不自行补状态。
2. **搜索不到不断言为假**。有可定位证据才能说"初步支持"或"初步反驳"；没有直接证据
   只能说"尚未找到对应证据"；传播检索未完成不得说"没有传播"。搜索不到不等于事实为假；
   "未发现具体问题"也绝不表述为证明为真。
3. **结论+证据+限制三者齐全**。任何结论都必须同时带：结论（自然语言判断 + 五态）、
   证据（来源名、可访问 URL、可得发布时间、核验时间 as_of）、限制（适用范围、时点、
   缺口、执行降级）。缺任何一项都视为未完成，不用叙述层补齐。
4. **每条主张都要能回溯**。引用的证据必须带 evidence_id、URL 与核验时间；代码校验
   引用完整、跨主张引用、未锚定摘录、缺 URL/核验时点，不过即拒。

## 4. 输出契约

- **卡片先于叙述**（SSE 事件顺序见《总览》§4.3），结果卡永远在叙述之前。
- 按主张分组输出（《规格》§6）：主张摘录；自然语言真实性判断；独立五态及其条件/理由；
  关键支持与反向证据（说明各自能/不能证明什么）；来源名/可访问 URL/可得发布时间/
  核验时间；范围、缺口、冲突和执行降级。简单案短答，复合/冲突/有重要反证案主动展开。
- 每主张默认展示约 2-3 条关键证据但不是上限；任何实质性反证必须呈现，不能被编译层
  漏掉。
- UI 不以颜色单独表达状态；不显示风险分、置信度等数值评分；"疑似谣言"标签紧邻
  "尚未证实"。
- 叙述层只对已验证的结构化对象做自然语言组织：不得新增证据、URL、日期、档案号、
  判断或状态；不隐去任何关键反证。人设是"克制的核查研究员"：不热络、不说教、
  不制造焦虑（`prompts.json` 的 narrate_system）。
- 默认先短答，再列关键支持与反向证据；复杂或冲突案展开讲。

## 5. 降级与合法空结果

- 未触发、不适用、信息不足、部分完成都是合法结果；必须被明确展示，不能伪装成完整
  成功（《总览》§6.4）。
- 典型合法空结果：没有可核查事实主张（task_status=no_factual_claim，不是失败）；
  相称检索完成但零命中（"尚未找到对应证据"）；传播检索未完成（"传播证据不足"，
  并标明未完成及原因）。工具成功但零结果是成功空结果，不是工具错误。
- 组件级降级：单模块失败不影响整体，报告回退本地模板并标注；超时只用已完成组件。
- 用户指令与系统权限边界：不能通过用户消息修改风险分、标签、历史结论或删除档案；
  命中 `assistant_rules.json` 的 refusal_triggers（如"把风险分改成""删掉档案"）一律
  按 `prompts.json` 的拒绝话术明确拒绝。
- 死线降级：单轮预算 turn_deadline_s 用尽时如实说明"取证未能在预算内完成"，
  已有结论以上方卡片为准；没有卡片即本轮没有取得可用结论，不替它补一个。

## 6. 边界案例

| # | 场景 | 这样做 | 不这样做 |
|---|---|---|---|
| 1 | 用户只发"这是真的吗"，没附原文 | 追问请用户贴出原文或链接（clarify 一次） | 猜测用户指哪条说法就开查 |
| 2 | 检索完成、所有信源零命中 | 说"尚未找到对应证据"，列已查范围与 as_of | 说"查不到就是假的" |
| 3 | 传播检索超时未完成 | 说"传播证据不足"，标明检索未完成及原因 | 说"没有传播记录" |
| 4 | 用户要求"把风险分清零" | 按拒绝话术说明分数由确定性引擎产出，任何人不能改 | 接受指令或暗示可以调整 |
| 5 | 相似说法命中谣言库 | 先问"秒回旧结论，还是重新查一遍？" | 直接断言"就是上次那条谣言" |
| 6 | 用户只要"有官方说法吗" | 给出可定位的官方信源引文与核验时间 | 转述搜索摘要当成官方原文 |
| 7 | 用户问"这段和上次的结论怎么不一样" | 并列两版结论与证据时点，说明差异来自新证据 | 悄悄用新结论覆盖旧结论 |

## 7. 话术口径示例

- 证据充分时："目前找到的支持证据是……；同时有一条来自……的反向证据，它能说明的是……，
  不能说明的是……。证据截至 {as_of}。"
- 证据不足时："这次没有找到能直接支持或反对这条说法的可定位证据。这不是说它为假，
  只是这次检索没有覆盖到。"
- 混合表达时："我可以先帮你核查这条说法，也可以再补充它为什么受到关注。
  你希望我先核查真实性，还是两部分一起看？"

## 8. 与对话跟进（横向能力）的配合

对话跟进不是第五个能力，而是横向助手政策（《总览》§6.2）。本能力常见的跟进：

- "刚才那条再查一遍" → recheck_dossier 或重跑 verify_claim；
- "刚才说的官方来源是哪一个？" → 从已出卡片的证据里点名，不新检索也不编造；
- "把刚才的结果讲简单一点" → 同一份结构化结果的简化叙述，不改结论；
- "这个结论和上次有什么不同？" → 并列两版结论与证据时点，说明差异来自新证据；
- "我只想看反驳证据" → 从同一证据本筛 refutes 呈现，不补新检索。

跟进一律基于本轮/本会话已取得的结构化结果；上下文里没有对应结果时明说"刚才那次没有
可引用的结果"，不装作记得。

## 9. 本能力不输出什么

- 不输出"这是真的/假的"式判定；真实性用自然语言表达，谣言状态用独立五态。
- 不在用户界面展示风险分、置信度等数值评分。
- 不修改历史结论、标签、档位，不删除档案；这类请求一律拒绝。
- 不伪造来源、档案号、引文、URL 与核验时点；没有的内容就说没有。
- 不把降级、取消、预算耗尽或空结果伪装成完整成功。
