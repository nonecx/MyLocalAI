# 信源可信度速查（source-credibility）

## 1. 能力定位

单源可信度速查的用户能力。用户给出一个网址、域名或机构名，助手产出**确定性**的信源
可信度画像：它是不是可识别、可追责的官方/权威信源，依据是哪些代码信号。判定全部由
代码完成（`skills/collect_core.py` 的来源分类与动态权威信号函数），模型不参与判定；
画像没有数值分数，也不落档案。

适用与不适用：

- 适用：拿到一个陌生链接想先问"这个网站可信吗"；想了解"xx 机构是什么背景"；
  想把内容交给核查/取证能力之前先摸一下信源的底。
- 不适用：要判断某条说法的真假（转事实核查/权威核验）；要主动调研一个主题
  （转资料收集）；一次丢一堆网址（一次只查一个，逐个来）。

## 2. 与权威核验的分工

与相邻能力的分工：

- **权威核验（authority-verification）**：verify_authority 是"多权威来源对主张"——
  拆主张、逐主张找权威证据、算 balance/lean/conclusion；本能力是"单源画像速查"——
  只看一个信源自己的身份，不看任何主张；互不替代。
- 只要官方资料、明确不要结论 → 证据研究（evidence-research）；
- 要主动收集一个主题的资料 → 资料收集（information-collection）；
- 要真实性判断与谣言五态 → 事实核查（claim-checking）。

## 3. 通道与预算

| 工具 | 背后引擎 | 权限 | 成本 | 预期延迟 | 降级路径 |
|---|---|---|---|---|---|
| check_source | assistant.skills.source.pipeline（SourceSkills.run：解析输入 → 读 1 页 → 代码信号判定 → 历史战绩 → 摘要） | read（只读，不落档案） | 中 | est_s≈15（注册表为准） | 不可达/超预算/取消如实降级，保留目录/档位口径的判定 |

- 上表是 `src/mylocalai/assistant/registry.py` 注册表的可读摘要，权限/成本/延迟以
  注册表为准；预算上限（读页页数、总时长、页面字节数等）以 `skills/source/rules.json`
  为唯一来源，改配置不改代码。
- 输入是一个 URL / 域名 / 机构名（query，1-500 字，一次只查一个）：解析顺序 URL >
  裸域名 > 目录机构名 > 无法识别；无法识别先追问补一个具体网址，不猜。
- 读页域名允许集锁定为该信源自己的域：重定向跳到别站一律拒绝——跳走了评的就不是
  用户问的那个信源。
- 外发授权 fail-closed：读页受 `external_allowed("public-web")` 控制
  （`core/privacy.py`）；未授权零外发、如实记降级，绝不假装读过。

## 4. 输出口径（"1+3"判语）

沿用权威核验的"1+3"输出口径：**只有代码判定的决定性信号达标，才允许说"官方/权威"**
（verified=true）；否则只给倾向或"未核验"，绝不因为"域名看起来像官方"或"页面自称
权威"就升级。

| 判语 | 条件（全部代码判定） |
|---|---|
| 已核实（官方/权威） | 目录锚点，或动态核验信号达标（至少 2 个代码信号） |
| 倾向 | 目录/档位有线索（如官方后缀宽匹配）但代码信号不足——只能说"倾向" |
| 未核验 | 目录外且无代码信号；页面自称权威不算信号 |
| 降级 | 页面不可达/输入无法识别——如实说明缺什么，不猜一个结论 |

- 无分数：画像没有任何数值评分字段，判语不是分；不输出"可信度 80 分"这类表达。
- 不建档：工具权限 read，不写档案、不改评分、不写回信源目录。

## 5. 信号口径

决定性代码信号与权威核验的动态核验同一套口径（实现于 `skills/collect_core.py`）：

- `official_suffix`：域名后缀命中官方后缀表（gov.cn 等）；
- `official_marker`：**已读正文**里命中官方标记（政府网站标识码/主办单位/公网安备等）；
- `inbound_link`：已核验页面正文里由代码抽出的、指向该域名的直链；
- `cross_mention`：≥2 个独立已核验来源的正文同时提到该域名。

交叉提及 ≥2 个独立已核验来源才算佐证信号，单来源提及只作线索；官方后缀、正文官方
标记这类单点信号凑不满 2 个代码信号时只给"倾向"。身份不能自封：后缀像官方只是
1 个信号，页面自称权威连信号都不算。

权威类别是七值封闭枚举：official / international_org / academic / standards /
factcheck / media / unverified；未知类别一律落 unverified，绝不猜。类别表与判定细节
以 `skills/authority/authorities.json` 与 `skills/collect_core.py` 代码为准，本文不复制。

## 6. 历史战绩

- 战绩查询由服务装配注入（如 dossier 信源战绩）；档案库中有该信源的核查记录时，
  画像附一段战绩摘要——摘要只述已有记录，不给信源加分或减分；
- 没有记录（未注入查询或查无记录）就如实说"无记录"，不编造、不用"没出过事"暗示可信；
- 本能力自身不建档、不写库：本次速查不给信源留下任何新记录。

## 7. 边界

1. **只评信源，不判内容真假**。画像回答"这个信源是什么来头"，不回答"这条内容
   是不是真的"；页面里写了什么、某条说法真假，归核查/取证能力管。
2. **不做超预算的深挖**。读页上限 1 页，不追站内链接、不做全站扫描；要对一个信源
   系统取证，请走证据研究或权威核验。
3. **页面不可达时如实降级**。取页失败/正文为空 → 判定退回目录/档位口径并写明
   "这次没读到页"；不可达不是"查过没问题"，绝不替它圆一个结论。

## 8. 限制与降级

- 输入为空/超长/无法识别 → needs_clarification，请用户补一个具体网址，不猜；
- 取页失败/正文为空/预算死线到顶 → unreachable，类别退回目录/档位口径，限制写明原因；
- 用户取消 → cancelled，保留已取得的判定；
- 摘要默认纯代码模板拼接（零模型，最稳）；注入了模型时才允许一段受约束补充说明，
  且不得新增信号、不得改变类别、不得出现真假判定词，越界即整段丢弃、退回纯模板；
- 每种降级都在卡片限制区/错误区写明原因，不把降级伪装成完整成功。

## 9. 话术口径示例

- 已核实时："该域名命中官方后缀，且这次读到的正文里有'主办单位'等官方标记，
  两个代码信号达标——画像为已核实（official）。依据见卡片信号区，读取时间见 as_of。"
- 只有单点信号时："域名后缀像官方，但本次读到的正文里没有官方标记——按口径只能给
  '倾向官方（未核验）'，不能说'官方认定'。"
- 页面不可达时："这次没有读到该站点页面（原因见卡片限制区），画像按目录/档位口径
  给出，仅供参考；想确认的话可以稍后再查一次。"
- 被要真假时："这个能力只评信源身份，不评内容真假。页面里那条说法要判断的话，
  把原文贴给我，走事实核查或权威核验。"

  本文与其描述同一套口径，冲突时以代码为准。
