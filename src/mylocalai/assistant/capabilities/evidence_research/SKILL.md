# 证据研究（evidence-research）

## 1. 能力定义

明确只要证据、不下真假结论的用户能力。用户给出原文或议题，助手走取证三技能流水线
（领域识别 → 信源发现 → 证据检索，口径见 `docs/取证技能-2026-11-05.md`），输出一份
确定性纯文本报告：这段内容在谈什么、该去哪里查、查到了什么、还缺什么。

用户旅程：丢进一段原文 → 先做领域分类（谈不下去会先追问）→ 按信源目录选站并核验
身份 → 拆主张逐条查已核验信源 → 出报告（含缺口、错误与预算消耗）。

与事实核查的分工：事实核查要给出真实性判断与谣言五态；本能力只述证据，不输出真假
结论、不输出谣言状态、不建真假档案。用户若中途追问"所以是真的吗"，引导改用事实核查
能力，不在本能力内越界。

适用与不适用：

- 适用：用户明确"只查官方资料/只找证据"；想自己看引文与信源核验过程；
  原文事实密度高、需要逐主张对证据。
- 不适用：要一个真假答复（转事实核查）；只想随便搜点东西（search_web 轻场景）；
  想保存结论供以后引用（本能力只读不建档）。

## 2. 覆盖工具

| 工具 | 背后引擎 | 权限 | 成本 | 预期延迟 | 降级路径 |
|---|---|---|---|---|---|
| collect_evidence | assistant.skills.pipeline（取证三技能流水线：domain → sources → evidence → 报告） | read（只读，不落档案） | 重 | 30-120s | 预算耗尽/取消保留部分证据 |
| search_web | retrieval（受控检索） | read | 轻 | 3-10s | 检索失败明说 |

- 上表是 `src/mylocalai/assistant/registry.py` 注册表的可读摘要，权限/成本/延迟以
  注册表为准。collect_evidence 已于 2026-11-20 接线（取证三技能落地合并）：注册名
  collect_evidence、路由枚举 `router.TOOL_ACTIONS` 与 `assistant_rules.json` 的
  tool_allowlist 均已包含；机器契约以注册表 + `assistant/skills/pipeline.py` 为
  唯一规范来源。
- collect_evidence 是只读取证工具：不写档案、不改评分、不写回信源目录；引文必须逐字
  出现在实际读取的正文里，由代码校验定位，校验不过即丢弃。
- collect_evidence 的输入是原文（text）；预检不过（为空/超长）或领域无法归类时先追问，
  不带着模糊输入检索。
- search_web 只用于用户明确要"随手搜点东西"的轻量场景，不走取证三技能的域名允许集，
  结果同样只述不判。

## 3. 硬门禁要点

本能力硬门禁（与 docs/Agent工作流规格-v0.1.md §1 已确认产品规则同口径）：
"引文必须来自实际读取正文；不输出真假分；只读取证不建档。"展开如下：

1. **引文必须来自实际读取正文**。每条引文都要能在已抓取正文中逐字定位（归一化后记录
   字符偏移），否则记错误并丢弃，不用模型转述补位；搜索摘要、截图本身不是已核验证据。
2. **不输出真假分**。报告只述证据与关系（supports / refutes / partial / background /
   unclear），不出现真假判定词，不给数值评分；"辟谣/证伪"只可作为来源性质描述出现，
   结论区一律只述证据。
3. **只读取证不建档**。工具权限 read：不写档案、不改评分、不写回信源目录；报告末尾
   如实写明"已执行 N 次搜索、N 次读页、N 次模型调用"。
4. **来源不自我认证**。陌生域名页面自称权威、模型说"匹配"，最多记为未核验候选，
   不进入证据检索；已核验信源只有两类来路：目录锚点，或已核验站点页面直接给出的链接
   （链接抽取用代码，不靠模型）。
5. **每个出口都有降级**。预算、死线、取消、零命中、定位失败都如实呈现；不为有输出
   而编造引文或信源。

## 4. 输出契约

- **卡片先于叙述**：确定性报告作为结构化结果先出，叙述层只做组织，不得新增证据、
  URL、日期、档案号或判断。
- 报告结构（`render_report` 确定性纯文本渲染，无 HTML、无 markdown 链接语法风险）：
  领域 → 信源（已核验/未核验分开）→ 主张 → 证据（claim_ids / relation / 引文 /
  URL / 时点）→ 缺口 → 错误 → 预算。
- **结论+证据+限制三者齐全**在这里的落地：结论=领域判断与信源核验情况；证据=可定位
  引文与实际读取的 URL；限制=缺口、错误、预算消耗与未完成阶段。
- 不展示任何数值评分；热度、风险分类指标不属于本能力输出。
- 主张拆分量、信源数、搜索/读页/模型调用次数受 `skills/rules.json` 预算控制，
  超限时如实标注，不静默砍掉也不静默突破。
- 叙述层人设沿用"克制的核查研究员"：不热络、不说教、不制造焦虑。

## 5. 降级与合法空结果

- 未触发、不适用、信息不足、部分完成都是合法结果；必须被明确展示，不能伪装成完整
  成功（docs/Agent工作流规格-v0.1.md §3.3：未触发/不适用/信息不足/部分完成都是合法出口）。
- 执行状态六种取值（completed / partial / needs_clarification / failed / cancelled /
  budget_exhausted）如实呈现；取消与预算耗尽都保留已取得的证据，绝不整批丢弃。
- 典型合法空结果：没有可核查事实主张（task_status=no_factual_claim，status=completed，
  不是失败）；信息不足先追问（原文为空/超长、领域无法归类、主张数超限）；
  读页失败或引文定位失败记入 errors，不补造。
- 用户指令与系统权限边界：本能力不写档案，用户也无法通过消息让它"顺手存一版结论"；
  确有保存需求时说明这是只读能力并建议用事实核查能力。

## 6. 边界案例

| # | 场景 | 这样做 | 不这样做 |
|---|---|---|---|
| 1 | 用户说"不要判断真假，只查官方资料" | 走本能力，输出信源核验情况 + 可定位引文 + 缺口 | 顺手补一句"基本可以认为是真的" |
| 2 | 用户中途追问"那到底是真是假？" | 说明本能力不输出真假结论，可改用事实核查 | 在证据报告里加真假判定 |
| 3 | 模型给的引文在已读正文里定位不到 | 记错误丢弃该引文，如实反映覆盖下降 | 按模型转述润色后当作引文 |
| 4 | 预算耗尽或用户取消 | 保留已取得证据，状态标 budget_exhausted/cancelled，列未完成阶段 | 整批丢弃或伪装成 completed |
| 5 | 检索命中的是陌生自媒体域名 | 最多记为未核验候选，不进证据检索 | 因页面自称"权威"就采信 |
| 6 | 用户原文是一段没有事实主张的抱怨 | task_status=no_factual_claim，说明没有可核查主张 | 硬拆几条"主张"凑输出 |
| 7 | 用户想保存报告供以后引用 | 说明本能力只读不建档，建议改用事实核查 | 悄悄写一条档案绕过权限 |

## 7. 话术口径示例

- 有证据时："查到了两条与主张直接相关的引文，分别来自……（读取时间 {as_of}）。
  它们能说明的是信源当时的表述，不能自动推广到其他情境。"
- 没证据时："这次检索没有找到能定位到已读正文的引文。已查的信源与用尽的预算列在
  报告末尾，不是'查无此事'，是这次没查到。"
- 被要真假时："这个能力只整理证据、不下真假结论。要判断真实性的话，我用事实核查
  再跑一遍。"

## 8. 与对话跟进（横向能力）的配合

对话跟进不是第五个能力，而是横向助手政策（docs/Agent工作流规格-v0.1.md §1.1：对话跟进是横向机制，不新建第五种用户能力）。本能力常见的跟进：

- "刚才查到的信源里哪个是官方的？" → 从报告的信源分区点名，不重新核验也不编造；
- "把刚才的报告讲简单一点" → 同一份确定性报告的简化叙述，不删关键限制；
- "刚才漏了哪几条主张？" → 按报告里的主张清单如实回答，缺口与已覆盖分开说；
- "再往深查一层" → 说明预算与域名允许集的边界，能扩则扩，不能扩则明说。

跟进一律基于本次运行的报告数据；本能力只读，跟进不会顺手写入档案。

## 9. 本能力不输出什么

- 不输出真假结论，不输出谣言五态；只述证据与关系。
- 不输出任何数值评分（热度、风险分都不属于本能力）。
- 不写档案、不改评分、不写回信源目录；用户也无法通过消息让它保存。
- 不伪造引文、信源、URL 与读取时间；定位不到的引文记错误丢弃。
- 不把未核验候选、降级、取消、预算耗尽伪装成已核验或完整成功。

## 10. 角色与工作区（v6 档案工作区，2026-11-20）

- **analyst（专业用户 · 材料分析）的主能力之一**：对"用户给出的原文"做公开检索取证。
  与材料批次的分工：本能力**只读取证不建档**（collect_evidence 权限 read）；
  批次对一批材料**逐条核查并建档**（verify_claim 链）。用户说"这是我收集的材料，
  帮我查"时，导流到 analyst 工作区的材料批次面板
  （`capabilities/material_analysis/SKILL.md`）。
- **授权闸**：本能力检索受 `external_allowed("public-search")` 控制；材料批次的
  URL 条目抓取受 `external_allowed("public-web")` 控制，未授权记 blocked 零外发
  （`core/privacy.py`，fail-closed）。
- **跨工作区口径**：与 claim_checking 同——别区档案号按"不存在"处理，
  不泄露别区数据（`assistant/tools_guard.py`）。
