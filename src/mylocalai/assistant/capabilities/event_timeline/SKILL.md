# 事件时间线（event-timeline）

## 1. 能力定位

把零散事件**按时间排开**的用户能力，是领域监测（domain-monitoring）工作区的主责之一：
用户给出一个主题，助手产出**有来源支撑**的事件序列——每条事件都带一句逐字来自已读
正文的引文和一个来源 URL，按时间排序；没有日期的事件单独成"无日期"区，不混主线。

适用与不适用：

- 适用：想知道"某话题先后发生了什么"；想把一段时间的事件按顺序摆开核对；
  给领域监测的变化摘要补一条可追溯的时间线。
- 不适用：判断某条说法的真假（转事实核查/权威核验）；评价某个信源的身份
  （转信源速查）；系统调研一个主题并写简报（转资料收集）。

## 2. 与相邻能力的分工

- **领域监测（domain-monitoring）**：面板 + REST + 调度线程的持续监测，每轮给变化
  摘要（新增/消失 URL、关注度走向）；本能力是**对话里的一次性整理**——给一个主题，
  还一条带引文的时间线；两者互补，不互相替代。
- **资料收集（information-collection）**：按主题主动调研出研究简报（子问题、关键
  发现、证据分级）；本能力只做"事件 + 时间"一维，不做综述与分级。
- **权威核验（authority-verification）/ 事实核查（claim-checking）**：判"某个主张
  能不能被证据支持/反驳"；本能力**不判真假**，只按来源记录排时间。
- 想了解某个网站可不可信 → 信源速查（source-credibility）。

## 3. 通道与预算

| 工具 | 背后引擎 | 权限 | 成本 | 预期延迟 | 降级路径 |
|---|---|---|---|---|---|
| event_timeline | assistant.skills.timeline.pipeline（TimelineSkills.run：预检 → 检索 → 读页 → 事件抽取 → 同源转载去重 → 排序汇总） | read（只读，不落档案） | 中 | est_s≈30（注册表为准） | 未授权/检索全败 → failed；读页失败/模型不可用 → partial；预算/取消 → 保留已取得事件；零事件 → completed 合法空结果 |

- 上表是 `src/mylocalai/assistant/registry.py` 注册表的可读摘要，权限/成本/延迟以
  注册表为准；预算上限（检索次数、读页页数、事件条数、引文长度、总时长等）以
  `skills/timeline/rules.json` 为唯一来源，改配置不改代码。
- 输入是一个主题（query，1-200 字，一次只整理一个主题）：空/超长先追问补一个
  具体主题，不猜。
- 读页域名允许集锁定为候选来源自己的域；重定向跳到别站一律拒绝——跳走了读的
  就不是检索返回的那个来源。
- 外发授权 fail-closed：检索受 `external_allowed("public-search")`、读页受
  `external_allowed("public-web")` 控制（`core/privacy.py`）；未授权零外发、
  如实记降级，绝不假装搜过/读过。

## 4. 输出口径（事件三件套 + 时间维度）

1. **每条事件必须带三件套**：归一后的日期（含精度 day|month|year）、一句事件
   描述、**逐字来自已读正文的引文**，外加代码填写的来源 URL 与标题。缺引文或
   引文定位失败 → 整条丢弃并记 limits（counts.dropped 如实计数）。
2. **日期归一全部由代码做**：绝对日期（`2026年11月20日` / `2026-11-20` /
   `2026年11月` / `2026年`）归一成 ISO 片段；相对日期（`昨天` / `上周` /
   `上个月` / `3年前`…）以本次运行时刻 as_of 归一并注精度；解析不出的表达按
   无日期处理，绝不猜一个日期。
3. **无日期事件单独成区**（undated），不混主线、不参与排序与时间范围统计。
4. **同源转载去重**：同一段逐字引文、或同域 + 标题近似只保留一条——**合并不并
   结论**：只去掉转载副本，不把多条事件并成一条新结论。
5. **时间范围（range）**取有日期事件的首末；零事件时为空串，不编一个区间。

## 5. 纪律（四条铁律）

- **只述有来源记录的事件**：不判真假、不外推趋势（"热度降了"不等于"事件冷了"）、
  不给数值分、不建档不写库；
- **digest/report 禁真假判定词**（"是真的/是假的/属实/不实"等一个都不许出现）；
- **检索范围如实标注**：报告写明"仅本次授权检索渠道返回的公开结果，不代表全网"；
- **不把降级说成完整成功**：没搜到、没读到、没抽到，都在缺口/错误/限制区写明。

## 6. 历史与档案

- 本能力自身**不建档、不写库、不写回信源目录**：工具权限 read，只读外部公开页面，
  产物只在当次会话的卡片与报告里；
- 想留档请走档案类能力（导出卡片/档案管理），本能力不代为落库。

## 7. 限制与降级

- 输入为空/超长 → needs_clarification，请用户补一个具体主题，不猜；
- 检索未授权/后端全败 → failed（fail-closed，一次读页都不发起）；
- 读页失败/正文为空/模型不可用 → partial，保留已取得的事件；
- 预算/死线到顶、用户取消 → 保留已取得的事件，绝不整批丢弃；
- 检索完成但零候选/零事件 → completed + 缺口写明原因（合法空结果）；
- 可选的一段模型补充说明只许转述报告里已有内容：新增事件、日期、URL 或出现
  真假判定词即整段丢弃，报告退回纯代码模板。

## 8. 话术口径示例

- 正常产出："按你给的主题，我从授权检索渠道找到 N 个来源、读到 M 页，抽出
  K 条带逐字引文的事件，已按时间排在卡片里；每条都能点回原文。"
- 只有单点信号/引文存疑时："有两条事件的引文没法在原文里逐字定位，按口径已
  丢弃并记在限制区——时间线因此短了两条，但不拿转述充数。"
- 没搜到时："这次授权渠道没返回可读取的来源（原因见卡片缺口区），时间线是空的；
  这不是'查过没问题'，可以换个主题词或稍后再试。"
- 被要真假时："这个能力只按来源记录排时间，不判真假。某条事件要判断的话，
  把原文贴给我，走事实核查或权威核验。"
