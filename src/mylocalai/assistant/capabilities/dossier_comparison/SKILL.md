# 档案对比（dossier-comparison）

## 1. 能力定位

两份档案的只读对比能力。用户给出两个档案号，助手把两侧**已经记录下来的内容**摆在一起：
最新结论的标签/as_of/置信度档位、标签从哪一版演进到哪一版、证据条目与信源域名各自多了
什么少了什么、两条声明原文的指纹相似度（只标「疑似同源」）。判定与读数全部由代码从
档案库直读派生（`skills/comparison/compare.py` 纯函数），模型不参与；输出没有数值评分，
也不落档案、不改写任何数据。

适用与不适用：

- 适用：同一条消息前后查过两次、想看看结论有没有变（`recheck` 是往同一档案追加版本，
  跨档案对比适合"同一说法被建成了两份档案"的场景）；一批材料里想挑出疑似同源的两份
  档案再看结论差在哪；复检前想先了解两份档案的证据/信源面差多少。
- 不适用：要判断某条说法的真假（转事实核查/权威核验——对比只呈现两侧已记录的结论，
  不裁定谁对）；要主动调研一个主题（转资料收集/信息收集）；要修改或合并档案
  （本能力只读，没有任何写路径）。

## 2. 与相邻能力的分工

与相邻能力的分工：

- **事实核查（claim-checking）**：verify_claim 是"一条说法进、结论出"的核查主流程；
  本能力不核查任何新内容，只对比两份既有档案已记录的结论/证据/信源。想判断真假，
  把说法交给核查流程。
- **权威核验（authority-verification）**：逐主张找权威资料给证据倾向；本能力不找任何
  新资料，证据差集只是两侧档案证据本的集合差（按 url 去重）。
- **信源可信度速查（source-credibility）**：单源身份画像；本能力的 `source_diff`
  只列域名增/减，**不评任何域名的可信度**——要给域名定性请走信源速查。
- **材料分析（material-analysis）**：一批材料的批量核查 + 跨条汇总；本能力是两份档案的
  点对点对比，不做批量、不出汇总报告。

## 3. 通道与预算

| 工具 | 背后引擎 | 权限 | 成本 | 预期延迟 | 降级路径 |
|---|---|---|---|---|---|
| compare_dossiers | assistant.skills.comparison.compare_dossiers（直读两侧档案 → 标签演进 → 证据/域名差集 → 指纹相似度） | read（只读，不落档案） | 零（无模型无网络） | est_s≈2（注册表为准） | 跨区/不存在同形拒绝；单边读失败折 partial + gaps 明示 |

- 上表是 `src/mylocalai/assistant/registry.py` 注册表的可读摘要，权限/成本/延迟以
  注册表为准；呈现裁剪量（版本历史/证据条目/域名清单条数）与相似度阈值以
  `skills/comparison/rules.json` 为唯一来源，改配置不改代码。
- 输入是两个正整数档案 id（`left_id` / `right_id`）：两个 id 相同或任一侧非正整数 →
  诚实降级（ok=False + digest 说明要怎么改 + `invalid_params=True`，相同 id 时指路
  get_dossier 看版本历史）——用户可修正的输入不摔成系统错误；路由期 registry.validate
  对非正整数的拒绝（折 clarify）不变，两层互不依赖。
- 本能力不进服务盒（`_ServiceBox`）：无模型、无网络、零检索、零取页——`rules.json`
  里没有任何页数/时限键，只有呈现裁剪量与相似度阈值。

## 4. 输出口径（只陈述，不判断）

- **标签演进**：`conclusion_delta` 取「左档案首版 → 右档案末版」为演进两端，陈述
  "标签从 X 变为 Y（as_of …）"；**不做升级/降级判断**——"从疑似谣言到谣言"是恶化还是
  缓和，归用户与后续能力判断，本能力只如实呈现两端。
- **置信度档位徽章**：两侧各带最新结论的置信度档位（高/中/低）与 as_of；档位徽章
  保留，数值不去凑——《角色Agent工作流规格》§5 同口径。
- **证据/信源差集**：证据按 url 去重后以左档案为基准列增/删（条目带 url/title/
  relation，relation 即证据条目的立场字段）；信源只列域名增/减。差集是集合差，
  不判断哪条证据更可信。
- **疑似同源徽章**：两条声明原文归一化后的指纹 Jaccard 达阈值（与谣言库指纹闸同值
  0.72）只标「疑似同源」，**不断言**两侧是同一说法；即便疑似同源，两侧结论也各自
  独立、分别审阅。
- **无分数**：输出没有任何数值评分字段；对话卡去数值（不出 risk_score）——档案库
  结论行的兼容字段由数据层保留，不归本能力呈现。

## 5. 缺章与降级口径

- 档案不存在或属于别的工作区 → 同形「档案 #N 不存在」（与 get_dossier 同一契约，
  不泄露别的工作区有哪些档案号）；
- 单边读失败（结论/证据章节读取炸了）→ partial：该侧缺字段按 absent 处理，gaps 写明
  失败原因，另一侧照常呈现；
- 缺章是常态（懒加载）：没有结论 → 标签字段为空并写明"尚无结论"；没有证据 → 差集按
  空集算；没有声明原文（未保存或已按保留策略清理）→ 相似度不可比。**不编造**；
- rules.json 缺失/写坏 → 逐键回退内置默认并夹取，对比照常产出；
- 每种降级都在卡片限制区/缺口区写明原因，不把降级伪装成完整成功。

## 6. 边界

1. **只读 diff，不核查、不裁定**。对比回答"两份档案记录的内容差在哪"，不回答"哪份
    更正确/这条说法是真的吗"；要判断真假，把说法交给事实核查或权威核验。
2. **不做升级/降级判断**。标签演进只陈述"从 X 变为 Y（as_of …）"，不给"事态升级/
    恶化/缓和"这类价值判断；as_of 只转述档案里记录的时点。
3. **不评证据与域名**。证据差集是集合差（按 url 去重），不判断证据强弱；信源差集
    只列域名增/减，不给可信度定性——要评信源走信源可信度速查。
4. **相似度只作线索**。「疑似同源」是指纹 Jaccard 达阈值的标注，用于提示"这两份
    档案可能在说同一条消息"；它不是同一性证明，也不能替代对两侧结论的分别审阅。
5. **不建档、不改写**。权限 read：不新建档案、不追加结论/证据、不修改任何一行数据
    （test_compare_tool 有不写库断言）。

## 7. 限制与降级

- 两个 id 相同 / 非正整数 id → 诚实降级（ok=False + digest 说明要怎么改 +
  `invalid_params=True`，相同 id 时指路 get_dossier 看版本历史），不抛异常、不落
  error 事件；路由期 registry.validate 对非正整数的拒绝（折 clarify）不变；
- 档案不存在/跨工作区 → 同形 not_found，不建卡、不外泄别区档案号；
- 档案库整体读失败 → ok=False + 诚实 digest，degraded；
- 单边子章读失败 → partial + gaps 明示；
- 呈现裁剪（版本历史/证据条目/域名清单超上限）→ limits 明示裁剪量，不静默；
- 对话卡去数值：卡片只出标签演进/as_of/置信度档位徽章与「疑似同源」徽章，相似度
  数值只在数据层留档（§5 分层口径）。

## 8. 话术口径示例

- 有变化时："档案 #3 首版结论「存疑」（as_of 2026-10-01…），档案 #7 末版结论「谣言」
  （as_of 2026-11-20…）——标签从「存疑」变为「谣言」。这里只陈述两端记录，是否构成
  变化的意义由你判断。"
- 无变化时："两份档案的最新结论标签相同（都是「疑似谣言」），as_of 见卡片；证据面
  新增 2 条、减少 1 条（按 url 去重）。"
- 疑似同源时："两条声明原文的指纹相似度达到阈值，标注「疑似同源」——这只是提示两份
  档案可能在说同一条消息，两侧结论仍各自独立，请分别审阅。"
- 缺章时："档案 #7 还没有跑过核查（尚无结论），这一侧没有可比的标签；证据面差异
  按空集计算，见缺口区。"
- 被要真假时："这个能力只对比两份档案已记录的内容，不判断真假。要核查的话，把说法
  原文交给我，走事实核查或权威核验。"

## 9. 与机器契约的关系

- 机器契约唯一规范来源 = `assistant.registry` 注册表 + `skills/comparison/compare.py`
  （呈现裁剪量与相似度阈值外置在 `skills/comparison/rules.json`）；本文只写人读策略，
  不复制可执行细节。
- 跨工作区防护契约（不存在与别区同形）与 `assistant/tools_guard.py` 同一套；读数口径
  与档案库单一事实源一致（工具不是第二个事实源，test_comparison 有对拍用例）。
- 判定口径以 `skills/comparison/SKILL.md` 与 `assistant/fingerprint.py` 为准；本文与其
  描述同一套口径，冲突时以代码为准。
