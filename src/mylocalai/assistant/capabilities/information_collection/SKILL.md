# 资料收集（information-collection）

## 1. 能力定义

按主题主动收集公开资料的只读能力。用户给一个主题（可带时间、地区、关注角度），助手把它拆成
少量可检索的子问题，主动多轮检索、读页、摘录，最后给出一份“资料简报”：这段主题下有哪些
可回溯的资料、各自能说明什么、哪里互相矛盾、还缺什么。本能力**不判断真假、不输出真假标签、
不建档**；资料里的说法是否成立，交给权威核验或用户自己判断。

用户旅程：说出主题 → 收到“正在确定范围/检索/阅读/整理”的进度 → 一张资料卡（关键发现 +
逐字引文 + 来源分级 + 时间线 + 分歧 + 缺口 + 执行计数）→ 一段克制的叙述。等不及可随时停止，
已完成的结果保留。

与相邻能力的分工：

- 只要“核实某条说法真假” → 事实核查（claim-checking）或证据研究（evidence-research）；
- 只要“找权威资料证明/反驳某说法” → 权威核验（authority-verification）；
- 问“有多热、为什么受关注” → 话题理解（topic-understanding）；
- 要“一句话同时收集资料 + 核验其中说法” → 复合能力 collect-and-verify（本能力与权威核验的组合）。

适用与不适用：

- 适用：主题调研、事件资料汇总、政策/行业资料的初步收集、需要逐字引文和来源清单的场景。
- 不适用：只给一个过宽词（如“美国”）且无关注角度（先追问）；要求直接下真假结论（转权威核验/
  事实核查）；要求后台定时监控（监测平台是独立能力）。

## 3. 硬门禁要点

1. **引文必须逐字来自实际读取的正文**。搜索摘要、页面标题、模型转述都不算证据；引文在已读
   正文中定位不到就丢弃并记错误，不用转述补位。
2. **每条关键发现都要能回溯到 evidence_id**。没有引文支撑的内容只能进“线索（未核验）”，
   不能进“关键发现”；未核验来源不得作为唯一依据。
3. **来源不自我认证**。陌生域名页面自称权威、模型说“匹配”都不算；来源等级由代码按信源目录
   与核验信号判定（authoritative / reliable / unverified）。
4. **不判真假、不给数值分**。资料卡只述“资料说了什么、来源是谁、时点是什么”，不输出
   “真的/假的/属实”结论，也不显示置信度、风险分、可信度评分。
5. **检索词先脱敏**。生成检索词前剥掉邮箱、手机号、身份证号、URL；模型写的 `site:`/`inurl:`
   等范围操作符由代码剥掉，域名范围由代码控制。
6. **每个出口都有降级**。授权失败、单页失败、引文定位失败、预算耗尽、取消都如实呈现；
   不把“没查”说成“查了没有”，不把“没查到”说成“不存在”。

## 4. 输出契约

- **卡片先于叙述**：资料卡先出，叙述层只组织卡片里的内容，不新增资料、URL、日期或结论。
- 卡片结构（人读口径，字段以 pipeline 输出为准）：主题与范围 → 子问题 → 关键发现（每条带
  evidence_id 与逐字引文）→ 线索（未核验）→ 来源（已核验/未核验分开）→ 时间线 → 分歧 →
  基于资料的整理/推断（明确标注）→ 缺口/错误 → “已执行 N 次搜索、N 次读页、N 次模型调用”。
- **结论+证据+限制三者齐全**在这里的落地：结论=本次资料覆盖到什么；证据=逐字引文与实际读取
  的 URL；限制=缺口、错误、预算消耗、未完成阶段。
- 默认先短答，再列关键发现；复杂主题展开讲；不写长文、不制造信息压力。
- 叙述人设沿用“克制的核查研究员”：不热络、不说教、不制造焦虑。

## 5. 工作流模式与设置

- 两个模式，**由用户在设置页“技能”里选择**，两个技能分别设置：
  - **固定流水线（pipeline）**：范围 → 检索 → 读页 → 摘录 → 综述，阶段固定、预算固定，
    模型不能增删阶段。默认模式。
  - **受限 Agent 循环（agent）**：模型只能在代码给定的候选池里选择 search / read / extract /
    finish；预算、死线、取消、URL 候选池、引文锚定全部由代码硬约束。模型只决定“下一步做什么”，
    不能改状态、结论或分数；连续非法/覆盖不足会如实标 partial。
- 设置页还可开关“研究后自动核验直接引文”：开启时，只对关键发现里的 **source_quote（原文直接
  引文）** 自动跑权威核验，**不核验助手综述句**；没有可核验引文时只出资料卡并说明原因。
- 设置只影响本能力与权威核验，不影响事实核查/证据研究；修改后下一轮生效。

## 6. 降级与合法空结果

- 未触发、不适用、信息不足、部分完成都是合法结果，必须明确展示，不能伪装成完整成功。
- 典型合法空结果：检索完成但零命中（“这次没有找到可引用资料”，并列出已查范围）；某子问题
  没有覆盖（记缺口）；所有候选都是未核验来源（只出线索，不出关键发现）。
- 失败与空结果分开：外部检索/取页未授权、检索后端全败、范围阶段模型不可用记 failed；单页失败、
  引文丢弃、部分子问题未覆盖记 partial；预算/取消保留已得结果并标未完成阶段。
- 用户指令不能改变来源等级、引文、计数或把未核验来源“升格”为权威；这类请求一律按能力边界拒绝
  或说明。

## 7. 边界案例

| # | 场景 | 这样做 | 不这样做 |
|---|---|---|---|
| 1 | 用户只发“帮我收集一下美国的资料” | 追问关注角度（时间/地区/议题），不直接检索 | 猜一个角度就开跑 |
| 2 | 检索只返回自媒体转载，没有可核验来源 | 只出“线索（未核验）”，说明来源等级不足 | 把转载当关键发现 |
| 3 | 某页正文与搜索结果摘要说法相反 | 以实际读取正文为准，摘要只当线索 | 用摘要覆盖正文 |
| 4 | 模型综述写了一句没有引文的话 | 丢弃该句，或降为“基于资料的推断”并标缺口 | 当事实写进关键发现 |
| 5 | 用户说“顺便判断一下这是不是真的” | 说明本能力只收集资料，建议转权威核验/事实核查 | 在资料卡里补真假结论 |
| 6 | 用户要求“以后每天自动收集” | 说明本能力按需运行，定时监控走监测平台 | 私自开后台任务 |
| 7 | 预算耗尽/用户取消 | 保留已得资料，标 partial/cancelled 与未完成阶段 | 整批丢弃或伪装 completed |

> 记忆点：资料卡的可信度来自“逐字引文 + 可回溯来源 + 明确缺口”，不是来自模型说得多完整。
