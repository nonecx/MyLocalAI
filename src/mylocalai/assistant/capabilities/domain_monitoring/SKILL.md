# 领域监测（domain-monitoring）

## 1. 能力定义

对**某个领域持续、自动搜集信息**的用户能力，是话题理解（topic-understanding）的
**持续（scheduled）复合形态**——不为它新开第五种用户能力，也不新开对话 action。

用户旅程：切到 monitor 档案工作区 → 左栏「领域监测」面板订阅话题（可选关键词与
域名限定、频率）→ 到点由服务内调度线程自动跑检（也可手动"立即运行"）→ 每轮一条
运行记录与变化卡（新增/消失 URL、E 分首末两点差）→ 证据落订阅专属监测档案，
可随时暂停/恢复/删除。

与相邻能力的分工：

- 只想知道某个话题**现在**多热 → 话题理解（check_heat，对话里直接问）；
- 想逐条查证具体说法 → 事实核查（claim-checking）；
- 想分析一批已有材料 → 材料分析（material-analysis）。

## 2. 覆盖工具与通道

本能力**不走对话路由**，通道是面板 + REST + 调度线程：

| 通道 | 背后模块 | 权限 | 成本 | 预期延迟 | 降级路径 |
|---|---|---|---|---|---|
| POST /api/subscriptions | dossier/subscriptions.py（v8 存储） | write | 零 | <10ms | 参数非法 → 400 |
| POST /api/subscriptions/{id}/run-now | assistant/tools_monitor.run_subscription | write（写监测档案） | 中 | 5-60s/轮 | 未授权 → blocked；检索失败 → error |
| 调度线程 | web/monitor_api.start_scheduler（lifespan，tick 60s 串行） | 同上 | 中 | — | 单订阅失败不影响其他订阅与 tick |
| GET /api/subscriptions/{id} | monitor_api（详情 + 运行历史 + 最新变化卡） | read | 零 | — | 无已完成轮次时 card 为 {} |

- 参数边界（`dossier/subscriptions.py`）：主题 ≤200 字、关键词 ≤10 个、域名 ≤3 个、
  频率 ≥300 秒（`MIN_FREQUENCY_S`，保护搜索引擎）；域名限定额同时是每轮
  `site:` 查询变体上限（`retrieval/search.py` 的 domains 参数）。
- 每轮检索：`search_all(话题+关键词, k=8, domains=订阅域名)`——域名变体由检索层
  构造，搜索引擎不支持时按实到结果呈现，**不谎报"已限定"**（结果带
  `domain_scope_applied` 标注）。
- 调度只在**服务运行期间**有效：关服即停（产品口径如实告知）；多 worker 部署时
  只有主进程调度（启动告警覆盖）。
- 防重入：同一订阅已有运行在进行时，run-now 返回 409，不叠跑。

## 3. 硬门禁要点

1. **外发授权 fail-closed**。每轮运行前查 `external_allowed("public-search")`
   （`core/privacy.py`），未过 → 该轮记 `blocked`、订阅暂停并写明原因、
   **零外发**；恢复授权后手动/到点重跑。
2. **只述变化，不做真假断言**。变化摘要只报新增/消失的 URL 与关注度 E 分首末
   两点之差；不外推趋势、不预测、不把"热度降了"说成"谣言冷了"，也不把"新增
   报道"当证据用。
3. **E 分是代理估计值**。每轮关注度用**本次检索结果**现算
   （`attention/estimate.py` 的 estimate_from_search，零额外联网），E 分来自
   确定性公式但 x/y/z 是代理口径——呈现必须注明"代理估计值"。
4. **失败不卡死订阅**。检索失败记 `error`，但 `next_run_at` 照常推进；暂停需
   用户显式操作或授权闸触发。
5. **频率下限**。低于 300 秒的订阅一律 400——自动搜集不能变成对搜索引擎的滥用。

## 4. 输出契约

- **变化卡（card_type=monitor_change）**：`subscription_id/topic/run_id/status/
  results_count/new_count/new_urls/removed_urls/e_score/prev_e_score/e_delta/
  as_of/error`；URL 一律纯文本呈现（不造可点链接——监测结果是外部内容），
  超长截断并标注。
- **运行记录**：每轮一行（started_at/finished_at/status/results_count/
  new_count/summary/error），status 封闭集合 running/ok/partial/blocked/error。
- **监测档案**：每个订阅一个档案（input_kind='topic'），证据按批次追加、
  关注度快照进 `attention_snapshots`——面板可直接跳档案详情看六章节。
- 卡片先于叙述；没有新变化时如实说"本轮没有新增"，不为有输出而编。

## 5. 降级与合法空结果

- **零结果是合法结果**：检索完成但零命中 → results_count=0、new_count=0，
  如实呈现，不是"没问题"也不是"被和谐了"。
- 未授权 → blocked + 订阅暂停 + 原因写明；恢复后重跑即可。
- 检索抛错 → error + 原因，next_run_at 照常推进（下轮再试）。
- 快照算不出（估参异常）→ 该轮无 E 分字段，不拿 0 冒充。
- 调度线程异常 → 单订阅失败被吞掉不影响其他订阅与后续 tick（循环永不退出）。

## 6. 边界案例

| # | 场景 | 这样做 | 不这样做 |
|---|---|---|---|
| 1 | 用户订了但没开外发授权 | 首轮 blocked、订阅暂停、说明去哪授权 | 静默不发也不告诉用户 |
| 2 | 用户要 30 秒刷一次 | 说明频率下限 300 秒（保护搜索引擎），拒绝 | 偷偷按高频跑 |
| 3 | 本轮一条新结果都没有 | 如实说"本轮没有新增"，给已检条目数 | 把旧结果重新算成"新增" |
| 4 | E 分比上轮低 | 只说首末两点之差与代理口径 | 说"关注度下降说明是谣言" |
| 5 | 用户问"监测到的是真的吗" | 说明本能力只述检索结果与变化，要判真假走事实核查 | 用监测结果佐证真假 |
| 6 | 服务重启后订阅还在吗 | 订阅落库（v8），重启恢复；停机期间的轮次不补跑 | 假装连续监测或悄悄补跑 |
| 7 | 用户要"全网所有消息" | 说明检索是有范围的关键词检索 + 域名限定，给不到"全网" | 暗示覆盖全网 |

## 7. 话术口径示例

- 导流时："持续关注在左栏「领域监测」面板：订阅话题、设好频率，到点我自动跑检，有新变化会写进运行记录。要判断真假的话，把具体说法贴进来走核查。"
- 有变化时：「某话题」本轮检到 12 条、新增 3 条；关注度 E 从 41.2 到 55.0（代理估计值，只述首末两点差）。只述检索结果，不判定真假。
- 零变化时：「某话题」本轮检到 9 条，没有新增。检索范围是你设的关键词与域名，不代表全网。
- 未授权时：外部检索还没授权（设置 → 隐私与授权），这一轮没有发出任何请求；授权后我重跑。

## 8. 本能力不输出什么

- 不输出真假判断、谣言状态或任何数值评分（E 分是确定性公式的代理估计，不是重要性或真实性）；
- 不预测趋势、不外推"接下来会怎样"；
- 不推送、不提醒（只在面板看；本项目不做推送通知）；
- 不把监测结果当作已核验证据用于任何结论；
- 不谎报检索覆盖范围（"已限定域名"以 domain_scope_applied 为准）。

## 9. 角色与工作区（v6 档案工作区）

- **monitor（专业用户 · 领域监测）的主能力**，入口只在 monitor 工作区可见
  （面板显隐由 `active.role === "monitor"` 决定，快照为空时隐藏）。
- 订阅与监测档案归**当前激活档案工作区**（subscriptions.profile_id）；跨工作区
  访问按"不存在"处理（`web/monitor_api._sub_or_404`）。
- 对话里的导流话术由 `assistant/prompts.json` 的 `roles.monitor.router_system_addon`
  提供；本能力不占对话路由枚举。
