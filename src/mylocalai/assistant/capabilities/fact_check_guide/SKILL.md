# 辟谣方法指南（fact-check-guide）

## 1. 能力定位

辟谣方法指南的用户能力。用户问"怎么识别谣言 / 我自己怎么查证"，助手给一套可照做的
查证方法（查证五步法）与判断框架，**零检索、纯知识**：模块内没有检索/取页的注入位，
零外发请求。它教"怎么查"，不替用户查——对具体事件/说法的真假结论一律留给核查流程。

适用与不适用：

- 适用：想知道怎么辨别一条信息是不是谣言；想学一套自己动手查证的方法；
  想理解"这条为什么看着像谣言"背后的判断框架。
- 不适用：手里有一条具体说法要核查结论（转事实核查/权威核验）；要主动调研一个
  主题（转资料收集）；要评某个真实信源可不可信（转信源可信度速查）。

## 2. 查证五步法口径

五步清单由代码锁定生成，模型只围绕它讲解、无权增删改；卡片 steps 字段原样输出
这五步：

1. **看出处**：作者/发布机构是否可识别、可追责——域名是什么、账号主体是谁、
   出了错能不能找到责任方；查无此人的"网友爆料"先存疑。
2. **交叉验证**：多个相互独立的信源说法是否一致；官方通报、权威媒体、专业机构
   口径一致才可信，只有单一来源在传、互相转来转去的先按存疑处理。
3. **查原始引用**：转述是否忠实原始出处——找到它引用的原始文件/原始发布/原始
   数据，对照原话看有没有断章取义、偷换时间地点或夸大数据。
4. **识别情绪化标题与断言强度**：绝对化措辞（100%、全都、立刻扩散）、恐吓式
   提醒（速转！不转不是中国人）、煽动愤怒或恐慌的标题——情绪越满，越要慢下来
   核实。
5. **理解证据等级**：官方文件 > 权威媒体报道 > 自媒体转述；等级越低越要存疑，
   截图、聊天记录、"听说"都不能单独当证据。

## 3. 通道与预算

| 工具 | 背后引擎 | 权限 | 成本 | 预期延迟 | 降级路径 |
|---|---|---|---|---|---|
| guide_fact_check | assistant.skills.guide.guide（GuideSkills.run：解析问题 → 一次受约束讲解 → 代码校验 → 五步法组装） | read（只读，不落档案） | 轻 | est_s≈10（注册表为准） | 模型不可用/讲解越界 → 内置五步法模板兜底 |

- 上表是 `src/mylocalai/assistant/registry.py` 注册表的可读摘要，权限/成本/延迟以
  注册表为准；预算上限（问题长度、讲解长度等）以 `skills/guide/rules.json` 为唯一
  来源，改配置不改代码。
- 输入是用户问题（question，非空字符串；可带一个想查的说法作背景）：为空/超长先
  追问，不猜用户想学什么。
- 零检索零取页：不联网、不外发，讲解里也不出现 URL/链接（教方法不需要，也避免
  引导用户点开未知站点）。

## 4. 边界

1. **不联网不检索**。纯知识任务，模块内没有检索/取页的注入位；它教方法，
   不做任何一次真实核查。
2. **不对具体事件说法给真假结论**。哪怕用户追问"所以那条消息是真是假"，也只回答
   方法并引导到核查流程；不给数值分、不给概率。
3. **示例只做方法论演示**。可以虚构一个示例说法演示五步法怎么走，但不指认真实
   机构/真实事件的真假，不点名评价任何现实信源。
4. **五步法口径不由模型改动**。steps 与下一步提示由代码生成；讲解越界（含 URL、
   真假判定词、为空）整条丢弃，退回内置五步法模板。

## 5. 限制与降级

- 模型不可用/超时/异常 → state=degraded：讲解用内置五步法模板兜底，五步清单照常
  输出——如实标注"讲解缺失、模板兜底"，不冒充讲解成功；
- 讲解越界（含 URL、真假判定词、为空）→ 整条丢弃并记 error + 缺口，退回内置模板；
- 输入为空/超长 → needs_clarification，请用户一句话说明想学哪种方法；
- 预算/死线到顶 → 保留五步法清单与内置模板；用户取消 → 保留五步法清单；
- 每种降级都如实呈现，不把模板兜底伪装成完整讲解。

## 6. 典型对话示例

- 用户："最近总看到养生类谣言，怎么识别？"
  助手："给你一套查证五步法：①看出处……⑤理解证据等级……。下次刷到可疑消息
  可以照这五步过一遍；想让我替你核查某条具体说法，把原文贴给我就行。"
- 用户："方法我懂了，这条'某地自来水有毒'你能直接查吗？"
  助手："方法你可以先照着走：看出处、查原始出处、再做交叉验证。要我替你查的话，
  用事实核查跑一遍这条说法，给你'结论 + 证据 + 限制'的卡片——方法归方法，
  结论归核查。"
- 用户："所以那条消息到底是不是谣言？"
  助手："这个问题我不能凭空回答。指南只教方法，不替具体说法下结论；把原文贴给
  我，我用事实核查/权威核验给你可回溯的判定。"

## 7. 与 claim-checking 的关系

- **一个教方法、一个查具体说法**：本能力给"怎么查"的通用方法，零检索、零结论；
  claim-checking 对用户给出的原文做真实核查，给"结论 + 证据 + 限制"三者齐全的
  卡片并建档。
- 用户只要方法 → 本能力；用户给了具体原文/链接要结论 → 事实核查；用户在方法
  讲解后想落地 → 顺势引导把说法交给核查（verify_claim）。
- 两者都是对话路由能力，用户改口就切换重跑，不在本能力内越界替核查下结论。
