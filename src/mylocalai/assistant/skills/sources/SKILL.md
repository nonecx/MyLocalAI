# 信源发现（discover-sources）

## 1. 这个技能在回答什么

只回答一个问题：**该去哪里查**。它是取证三技能的第二阶段，产出进入第三阶段证据
检索的**已核验信源**名单。它不判断原文真伪，不给来源排名打分，也不因为域名好看
（.gov/.org/名字像官方）就认定权威。

候选有三路：信源目录按领域/地区过滤后的条目、你在这些条目里做的选择、以及一次中性
机构搜索发现的目录外域名。三路候选**过同一套核验**：读首页 → 身份判断要引已读正文
→ 程序独立判定可信锚点。搜到 ≠ 可信，目录里有 ≠ 已经读过了。

## 2. 选站口径

1. **目录优先**：候选来自信源目录按 domain/region 过滤后的条目，你的任务是从中挑
   出与议题最相关的（`selected`，数量不超过代码给的上限）。
2. **一条域名一个信源**：同一域名只保留一个条目，不因为"换了个子站/镜像"就多认
   一个权威。
3. **身份与适用范围要分开说**：`identity` 说"这是什么机构/站点"，`scope` 说"它能
   覆盖什么范围的事务"。两句话都必须是能从已读正文看出来的内容。
4. **basis_quote 必须逐字摘自该候选的已读首页正文**，是"我凭什么认为它是这个身份/
   这个适用范围"的依据。代码会拿这句回正文做逐字定位，定位不到 → 该候选降级为
   unverified_candidate（未核验候选），**不得**进入证据检索。
5. 拿不准选哪些时，**少选**比多选好：目录里没有合适来源就留空，让流水线如实报告
   "没有已核验信源"，不要为了有输出而凑数。
6. 不做跨领域扩张：公共卫生的议题不要顺手选财经站点"说不定也有"。
7. 不把资料类型当权威：`material_types`（通报/新闻/科普/辟谣）只说明"这个站点通常
   发布什么"，不说明"它说的都对"。

## 3. 可信锚点由代码判定，不由你认定

代码独立判定两类可信锚点，你的"匹配/看起来权威"只作为参考：

- **目录锚点**：信源目录里 `anchor=true` 的登记条目；
- **已核验站点直接给出的链接**：在已核验页面正文里由代码抽取到的站外链接。

两者都不占的陌生域名——哪怕它页面自称"官方权威"、哪怕你判"匹配"——最多记为
`unverified_candidate`。这是"来源不自我认证"的硬约束：**身份不能自封**。

## 4. 字段口径明细

| 字段 | 这样做 | 不这样做 |
|---|---|---|
| `selected` | 只从代码给的候选清单里挑 id，宁少勿多 | 自造 source_id，或把清单外站点塞进来 |
| `identity` | 一句话说清"这是什么机构/站点" | 写"权威平台""国家级网站"这类自我描述 |
| `scope` | 说清适用范围（管什么、不管什么） | 写"什么都覆盖"或留空让代码猜 |
| `basis_quote` | 逐字摘自该候选已读正文的原句 | 用页面标题、域名后缀或常识当依据 |

## 5. 边界案例

| # | 场景 | 这样做 | 不这样做 |
|---|---|---|---|
| 1 | 候选首页正文只有导航和口号，没有一句能说明身份 | 该候选 basis_quote 留空 → 代码降级为未核验候选 | 用页面标题或域名后缀当身份依据 |
| 2 | 模型/页面自称"国家级权威平台"但目录里没有登记 | 记为 unverified_candidate，不进证据检索 | 因为自称权威就放行 |
| 3 | 同一个域名在目录里出现两次（主站与镜像） | 只保留一个信源条目 | 产出两个"权威"来源虚增覆盖 |
| 4 | 议题是地方性政策，目录里只有全国性机构 | 选最相关的一个并如实写 scope 适用范围 | 把全国机构说成"也覆盖该地，可用" |
| 5 | 一次中性机构搜索搜来个陌生域名，标题很像官方 | 按同一套规则核验：最多未核验候选 | 因为搜索排名靠前就采信 |

## 6. 预算与降级

- **读页有额度**：候选多于读页预算时按序截断，没读到首页的候选如实记为"首页未读取"，
  不假装读过；
- **已核验信源数量有上限**：到顶之后多出来的可信锚点仍然记录（verified 依据不丢），
  但本次不用于证据检索，报告里写明原因；
- **可观测**：每次读页、每次模型调用都进 audit，报告末尾如实写明执行次数；
- **合法空结果**：目录没有匹配条目、或所有候选都核验不过，都是合法输出——如实报告
  "没有已核验信源"，不为了有输出而放宽核验标准。

## 7. 与代码校验的关系（重要）

- `selected` 里的 source_id 必须来自代码给的候选清单，不在清单内的 id 被忽略；
- 每条 `notes` 的 `basis_quote` 必须能在该候选的**已读正文**里逐字定位，否则记
  error 并丢弃该条，候选随之降级；
- 抓取首页失败（超时/超体积/内容类型不支持/私网 DNS）记 errors，不当成"页面没有
  可用信息"；
- 一次中性机构搜索的结果域名也按同一套规则核验：搜到 ≠ 可信，只有代码判定为可信
  锚点才能进入证据检索。

> 记忆点：选站给依据，依据要逐字来自已读正文；身份不能自封，代码不认"自称"。
