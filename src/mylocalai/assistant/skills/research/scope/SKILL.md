# 范围与子问题（research-scope）

## 1. 这个技能在回答什么

只回答一个问题：**这次要收集什么**。它是资料收集流水线的第一阶段，产出供检索与
摘录使用的子问题清单。它不判断资料真伪、不评估立场情绪、不给分，也不对"哪条资料
更可信"提出建议——那是代码按来源分级做的事。

主题只是用户的一句话，往往过宽（"人工智能"）、过偏（"我邻居说那事"）或只有情绪
（"太可怕了"）。把范围界定清楚，比直接丢给搜索引擎更省预算，也更不容易把发散结果
当成答案。

## 2. 拆解口径

1. **先读完整主题再拆**，不要被开头一个词带跑；主题里已有明确时间/地域/角度限制时
   原样搬进 `time_window` / `region` / `scope`，不要自己补。
2. **一个子问题 = 一个可检索的问题**：能改写成检索词、有明确对象。复合主题按可独立
   检索的部分拆开，但不要超过代码给的上限（默认 4 个）；宁可少而准，不要多而散。
3. **`scope_basis` 必须是用户主题里的逐字片段**（说明"我凭什么这样界定范围"）。
   代码会拿这句回主题做逐字定位，定位不到 → 整条按 unclear 处理，先问再查。
4. **queries 是中性检索词**：子问题的核心词 + 中立改写，不带立场词（"真相""揭秘"
   "可信吗"）、不带 `site:` / `inurl:` / `intitle:` / `filetype:` 等范围操作符。
   代码在生成检索词前会做脱敏（邮箱/手机号/证件号/URL），并剥掉模型写的操作符。
5. **不替用户补限定**：主题没写时间就不要写"最近"，没写地域就不要猜"全国"。
   缺了会影响检索发散时，用 `too_broad` / `unclear` 说明，而不是猜一个继续。

## 3. 范围状态 state（三态必须如实）

| state | 含义 | 代码的后续动作 |
|---|---|---|
| `ok` | 范围可界定，可开始检索 | 进入检索与读页 |
| `too_broad` | 主题过宽（单个词/整个行业/无对象），直接检索会发散 | needs_clarification，不检索 |
| `unclear` | 范围依据不足（太短/只有情绪/说不清要收集什么） | needs_clarification，不检索 |

后两态不是失败，是"先问再查"：用户补一句时间/地域/角度，比盲目检索更省。
把 `too_broad` 报成 `ok` 是更坏的选择——那会让后面几步在错误的方向上花钱。

## 4. 字段口径明细

| 字段 | 这样做 | 不这样做 |
|---|---|---|
| `scope` | 一句具体的研究问题（含对象与角度） | 把用户原话复述一遍，或写成一个词 |
| `scope_basis` | 逐字片段，能指回用户主题 | 写"综合判断""根据经验"这类指不回原文的话 |
| `sub_questions` | 可检索的具体问题，1-4 条 | 写成观点/情绪/诉求，或自造不可检索的长句 |
| `time_window` | 用户写了的才抄（"2026年""最近三个月"） | 补一个"近期"当作时间范围 |
| `region` | 用户写了地域才填 | 填"全国""江浙沪"这类用户没说过的范围 |
| `queries` | 中性词，可含子问题核心词 | 带"真相/揭秘/可信吗"或 `site:` 等操作符 |

## 5. 边界案例

| # | 输入 | 这样做 | 不这样做 |
|---|---|---|---|
| 1 | "人工智能" | state=too_broad；给出"影响/数据/政策/争议"等收窄方向 | 直接检索"人工智能"，把海量结果当资料 |
| 2 | "啊啊啊那个事太离谱了" | state=unclear，说明缺对象与时间 | 硬拆几个"子问题"凑输出 |
| 3 | "2026年杭州余杭区自来水水质争议" | state=ok；time_window/region 原样搬；按"事件经过/官方通报/检测数据"拆子问题 | 把时间或地域改写成"最近""某地" |
| 4 | "某明星离婚事件的最新进展" | state=ok；时间范围用"最新进展"，子问题按"官宣/时间线/各方回应"拆 | 替用户补一个具体月份或预测后续 |
| 5 | 主题里带一个链接 | 只把它当作用户给的线索，不作为权威依据；必要时在子问题里说明要核对官方发布 | 直接抓链接内容当作结论 |

## 6. 与代码校验的关系（重要）

本指令的输出**不直接进入流水线结果**，代码会逐项校验：

- `state` 只接受上表三个取值，出现别的值按 unclear 处理；
- `scope_basis` 必须能在用户主题中逐字定位（归一化后），定位不到 → 记 error 并丢弃该值，
  state 随之按 unclear 处理（先问再查）；
- `sub_questions` 超过代码上限时，代码保留前 N 条并记 error；
- `queries` 统一过 `strip_pii` + 范围操作符剥离，外发前不含用户主题全文；
- 模型没有可用（未配置/调用失败）时，阶段一直接判失败——没有范围就没有检索依据，
  盲目检索比不检索更糟。

> 记忆点：本技能只界定"收集什么"，范围依据必须能在用户主题里指出来；
> 指不出来的一切范围，代码都会当成没说过。
