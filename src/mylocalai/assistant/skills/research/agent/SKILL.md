# 资料收集：受限循环

## 1. 这一步在做什么

范围确定后，由你一步一步决定怎么把资料找齐：先检索拿候选，再挑页面读，再从读过的正文里
摘引文，觉得够了就收尾。程序会把候选池、已读页面、已摘录证据和剩余预算摆在每一步的
提示里——**你只能在这份状态之上做选择**，不能凭空引用没出现过的地址或原文。

## 2. 四种动作怎么用

1. **search**：给检索词，拿到候选列表。检索词用中性词，不带 `site:` 之类范围操作符
   （代码会剥掉）；一次不要贪多。
2. **read**：只能读候选池里出现过的地址；读过的页不要重复读，同一域名有页数上限。
3. **extract**：只能从已读过的页面里摘，引文必须逐字来自该页正文；一句顶用即可。
4. **finish**：子问题都有对应引文、或继续查也只会重复同一批页面时收尾；不要为了凑步数硬查。

## 3. 决策顺序（经验，不是硬性）

1. 先看子问题清单：哪些还没覆盖，就针对哪条检索。
2. 候选池里优先读官方/权威与可靠来源；未核验域名只在需要线索时读。
3. 读到能回答子问题的句子就摘，不要等“读完所有页面再统一摘”。
4. 连续两次检索都只返回同一批候选时，说明该换说法或该收尾了。
5. 剩余预算不多时，优先把已有页面摘完，而不是再开新检索。

## 4. 边界案例

| # | 场景 | 这样做 | 不这样做 |
|---|---|---|---|
| 1 | 想读一个搜索结果里没出现过的地址 | 先 search 把它带进候选池 | 直接 read 一个凭印象拼的 URL |
| 2 | 正文里找不到想引用的那句话 | 换一句确实存在的，或放弃这页 | 把意思相近的改写句当引文 |
| 3 | 同一页已经读过一次 | 直接 extract，或换下一页 | 反复 read 同一地址刷步数 |
| 4 | 检索结果全是同一篇文章的转载 | 只读其中一两篇，局限里注明转载 | 把每篇都读一遍当成多来源 |
| 5 | 页面读取失败 | 换候选池里的下一个 | 反复重试同一个失败地址 |
| 6 | 预算/步数快用完 | 摘完已读页面后 finish | 继续开新检索把预算烧光 |
| 7 | 模型想“给个结论” | 只摘引文；结论由确定性收口生成 | 在动作里写判断或打分 |

## 5. 与代码校验的关系

- 代码会校验：read 的地址是否在候选池、extract 的引文是否已锚定、动作是否重复、预算与步数；
- **read 只允许候选池里的地址**：不在池子里、已读过、该域名读满，都会被拒绝并记错误；
- **extract 的引文必须能在已读正文里逐字定位**：定位不到直接拒绝，不会进证据；
- 同一组动作重复提交会被拒绝；连续多次非法动作会让循环提前停止（结果如实标部分完成）；
- 步数、搜索数、读页数、模型调用数、死线与取消都由代码检查，到顶即停；
- 结束后的要点、线索、时间线、不一致与报告仍走同一套确定性收口，
  你摘的引文只是原料，**不能直接决定卡的字段**。

## 6. 预算与降级

- 每一步都花 1 次模型调用；预算用尽时循环停下，已读页面与已摘引文全部保留。
- 用户取消 / 死线到点：立刻停止发起新动作，状态记 cancelled / budget_exhausted。
- 页面读不到、引文定位失败、动作被拒：都是正常降级，如实记录，不影响已经取得的资料。
- 没有找到任何资料也是合法结果：报告会写明缺口，不会编内容填空。

> 记忆点：你只决定“下一步做什么”，能不能做、算不算数由代码说了算。
