# 阅读摘录与综述（research-digest）

## 1. 这个技能在回答什么

回答两个问题：**这段正文里有什么可引用的原话**，以及**这些原话合起来说明了什么**。
它是资料收集流水线的第三、四阶段：先逐页摘录（一段一条，逐字），再基于证据清单
组织简报（关键发现 / 线索 / 时间线 / 分歧 / 分析）。

两个硬约束贯穿本阶段：引文必须逐字来自**实际读取过的正文**（不是搜索摘要、不是你的
记忆转述）；综述里的每一条发现都必须能追到证据 ID——说不清依据的内容只能进线索区。

## 2. 摘录口径（阶段 3）

1. **quote 必须逐字摘自已读正文**，不改写、不翻译、不概括、不拼接两段。代码会拿这句
   回正文做逐字定位并记录归一化字符偏移；定位不到 → 记 error 并丢弃，不用转述补位。
2. **一段只摘一条**，单页最多 3 条；挑最能回答研究问题的原话，不要把整页抄一遍。
3. **summary 是"这句说明了什么"**，一句话，只复述引文内容，不延伸推测、不评价可信度。
4. **role 只能取三值**：`fact`（具体事实/数据/发布内容）、`context`（背景/同类现象）、
   `conflict`（与其他资料说法不一致）。拿不准用 `context`。
5. **找不到就找不到**：正文通篇没有可引用原话 → 该页不产摘录，代码记 error；
   不换一个"看起来对得上"的句子凑数。

## 3. 综述口径（阶段 4）

1. **关键发现（key_findings）必须引用已存在的 evidence_id**，且至少一条。
   代码会按证据来源的核验方式定支撑等级：目录锚点 / 已核验站点直链 / 会话内动态核验
   → `authoritative`；其余可靠来源 → `reliable`。
2. **只有未核验证据的"发现"必须降级为线索（leads）**，并写清 `reason`（例如"仅见于
   未核验域名""无第二来源印证"）。线索单独成区展示，不与关键发现混排。
3. **不得新增任何 URL、日期或证据 ID**：代码按白名单校验，新增的一律丢弃并记 error。
4. **timeline 只收录能追到证据的事件**，日期以证据里的发布时间/正文日期为准；
   没有日期就留空串，代码按"日期未知"展示——不要为了好看补一个。
5. **conflicts 只陈述分歧本身**（谁说了什么、差在哪），不评判谁对谁错。
6. **analysis 标"基于资料的整理/推断"**：可以把证据连起来说，但必须引用证据 ID，
   且不得出现真假判定词（"是真的""假的""属实"等）。推断就是推断，不说成结论。
7. **followups 是"还能继续追问什么"**，不超过 5 条；不评价资料、不承诺结果。

## 4. 字段口径明细

| 字段 | 这样做 | 不这样做 |
|---|---|---|
| `quote` | 已读正文里的原句 | 跨两段拼接、加省略号、改写润色 |
| `summary` | 一句话复述引文内容 | 写"证据充分""可信度高"这类评语 |
| `role` | fact/context/conflict 三选一 | 自造角色名或留空让代码猜 |
| `statement` | 基于证据的具体发现 | 写成观点、情绪、行动建议 |
| `evidence_ids` | 只引用清单里已存在的 ID | 引用不存在的 ID，或在正文里写 URL |
| `reason` | 写清为什么只作线索 | 写"不可信"这种无依据的判断 |

## 5. 边界案例

| # | 场景 | 这样做 | 不这样做 |
|---|---|---|---|
| 1 | 已读正文通篇是导航与口号，没有实质原话 | 该页不产摘录，代码记 error | 用页面标题当引文 |
| 2 | 模型想摘的句子其实跨了两段，中间有省略 | 只摘其中一段逐字可定位的原话 | 用"……"拼接后当成引文 |
| 3 | 发现只引用了未核验域名的内容 | 降级为线索并写 reason | 当成关键发现，让简报看起来更满 |
| 4 | 两个信源对同一件事说法不一致 | 进 conflicts，各自引用各自证据 | 二选一，或平均成"大致如此" |
| 5 | 资料里没有日期 | timeline 的 date 留空 | 按发布渠道猜一个日期填上 |
| 6 | 综述想写"由此可见该说法是真的" | 删掉判定，只写证据支持什么 | 让判定词进简报 |

## 6. 预算与降级

- **每页摘录有上限**（默认 3 条），总摘录数受 `max_evidence` 控制；到顶即停，
  不无限加摘录；
- **模型调用预算到顶或用户取消**：保留已取得的摘录，综述不执行，代码如实记
  budget_exhausted / cancelled，**绝不整批丢弃**；
- **综述失败但摘录成功**：状态 partial，简报只呈现摘录，不补一个"综述"充数；
- **合法空结果**：所有页面都没有可定位引文 → 关键发现为空、缺口写明原因，
  这是正常输出，不是失败。

## 7. 与代码校验的关系（重要）

- 引文 `quote` 必须逐字定位已读正文，并记录归一化字符偏移，定位失败即丢弃并记 error；
- `role` 必须命中封闭枚举，否则记 error 并按 context 处理；
- 综述的 `evidence_ids` 全部按白名单校验：不存在的 ID 记 error 并丢弃；引用被丢空的
  发现/分析整条丢弃；
- 只引用未核验证据的发现会被代码降级为线索（模型无权覆盖这个降级）；
- 综述阶段外发前不含用户主题全文，只含证据清单与研究问题；
- "检索被降级/未授权"与"检索过但无结果"是两回事，代码分别记 error + 缺口 与 纯缺口，
  绝不把"没搜"表现成"搜过了没找到"。

> 记忆点：引文逐字来自已读正文，发现必须追得到证据 ID；
> 追不到的一律进线索区——查不到是合法结果，编不出来不是。
