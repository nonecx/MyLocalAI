# 辟谣方法指南（fact-check-guide）

## 1. 这个技能在回答什么

只回答一个问题：**怎么自己动手辨别一条信息是不是谣言**。它教方法、给步骤、给
判断框架，不替用户对某个具体事件/说法下"是真的/是假的"结论——那是核查流程
（verify_claim / verify_authority）的事。用户带着具体说法来问"这是不是谣言"时，
正确姿势是：教完方法，引导他把说法交给核查流程。

## 2. 查证五步法（口径固定，代码锁定）

讲解必须围绕这五步展开；`steps` 字段原样输出这五步，模型无权增删改：

1. **看出处**：作者/发布机构是否可识别、可追责——域名是什么、账号主体是谁、
   出了错能不能找到责任方；查无此人的"网友爆料"先存疑。
2. **交叉验证**：多个相互独立的信源说法是否一致；官方通报、权威媒体、专业机构
   口径一致才可信，只有单一来源在传、互相转来转去的先按存疑处理。
3. **查原始引用**：转述是否忠实原始出处——找到它引用的原始文件/原始发布/原始
   数据，对照原话看有没有断章取义、偷换时间地点或夸大数据。
4. **识别情绪化标题与断言强度**：绝对化措辞（100%、全都、立刻扩散）、恐吓式
   提醒（速转！不转不是中国人）、煽动愤怒或恐慌的标题——情绪越满，越要慢下来核实。
5. **理解证据等级**：官方文件 > 权威媒体报道 > 自媒体转述；等级越低越要存疑，
   截图、聊天记录、"听说"都不能单独当证据。

## 3. 硬边界

- **不联网、不检索、不取页**：本技能是纯知识任务，模块内没有检索/取页的注入位，
  零外发检索请求；讲解里也不出现 URL/链接（教方法不需要，也避免引导用户点开
  未知站点）。
- **不对具体事件说法给真假结论**：哪怕用户追问"所以那条消息是真是假"，也只回答
  方法，并引导到核查流程；不给数值分、不给概率。
- **示例只做方法论演示**：可以虚构一个示例说法演示五步法怎么走，但不指认真实
  机构/真实事件的真假，不点名评价任何现实信源。

## 4. 降级行为（每个出口都有）

| 场景 | 行为 |
|---|---|
| 模型不可用/超时/异常 | `state=degraded`，answer 用内置五步法模板（五步清单照常输出） |
| 讲解越界（含 URL / 真假判定词 / 为空） | 整条丢弃并记 error + 缺口，退回内置模板 |
| 输入为空/超长 | needs_clarification，请用户一句话说明想学哪种方法 |
| 死线/预算到顶 | budget_exhausted，保留五步法清单与内置模板 |
| 用户取消 | cancelled，保留五步法清单 |

`state=degraded` 表示"模型讲解缺失、内置模板兜底"，五步法清单仍然完整可用——
如实标注，不冒充"讲解成功"。

## 5. 与代码校验的关系（重要）

- `steps` 与 `follow_up_hint` 由代码生成，模型无权改动；代码也不读模型对这两个
  字段的意见；
- `answer` 过三道校验：非空、无 URL、无固定真假判定词（是真的/是假的/属实/
  谣言为真/基本属实/不实），任何一道不过整条丢弃，降级为内置模板；
- 讲解只产出方法文本，不产出对具体说法的判定；判定的权力只在核查流程的代码里。

> 记忆点：教方法不判真假；五步法是代码锁定的固定口径；零检索零取页；模型讲解
> 越界就整条丢弃，用内置模板兜底。
