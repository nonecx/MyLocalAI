# 信源可信度速查（assess-source）

## 1. 这个技能在回答什么

只回答一个问题：**这个信源本身可不可信**。输入一个网址、域名或机构名，速查给出
"它是不是可识别、可追责的官方/权威信源"。它**不读内容下结论**：页面说了什么、
某个说法是不是真的，都不归本技能管——那是 verify_claim / verify_authority 的事。

## 2. "1+3"输出口径（判语只有四种）

**只有拿到决定性代码信号，才允许说"官方/权威"**（`verified=true`）；否则只给
倾向或"未核验"，绝不因为"域名看起来像官方"或"页面自称权威"就升级。

| 判语 | 条件（全部代码判定） |
|---|---|
| ① 已核实（官方/权威） | 目录锚点（`skills/sources.json` 里 `anchor=true` 的人工登记），**或**动态核验信号达标：官方后缀 / 正文官方标记 / 已核验站点直链 / 多来源交叉提及，至少 2 个代码信号 |
| ② 倾向 | 目录/档位有线索（如 gov.cn 宽匹配、目录登记的非锚点可靠来源）但代码信号不足，只能说"倾向"，不能说"官方认定" |
| ③ 未核验 | 目录外且无代码信号；页面自称权威不算信号 |
| ④ 降级 | 页面不可达 / 输入无法识别：如实说明缺什么，不猜一个结论 |

决定性代码信号明细（与权威核验的动态核验同一套口径，代码实现于
`collect_core.dynamic_authority_signals`）：
- `official_suffix`：域名后缀命中官方后缀表（gov.cn 等）；
- `official_marker`：**已读正文**里命中官方标记（政府网站标识码/主办单位/公网安备等）；
- `inbound_link`：已核验页面正文里由代码抽出的、指向该域名的直链；
- `cross_mention`：≥2 个独立已核验来源的正文同时提到该域名。

身份不能自封：后缀像官方只是 1 个信号，凑不满 2 个就只能是"倾向"。

## 3. 速查流程与预算

1. **解析输入**：URL > 裸域名 > 目录机构名（`sources.json` 精确/包含匹配）>
   无法识别。无法识别 → `state=unclear`，请用户补一个具体网址。
2. **读 1 页**（`max_pages=1`，不做超预算深挖）：域名允许集锁定为该信源自己的域，
   重定向跳到别站一律拒绝——跳走了评的就不是用户问的那个信源。
3. **信号判定**：目录/档位分类 + 动态核验信号全部由代码完成；"已核验站点直链 /
   交叉提及"只认**实际读取过正文**的已核验页面（本会话注入的上下文），搜索摘要
   与页面自称都不算。
4. **历史战绩**：只有构造时注入了战绩查询函数（如 dossier 信源战绩）且查到记录
   才输出 `history`，否则一律"无记录"。本技能自身不建档、不写库。
5. **摘要**：默认纯代码模板拼接（零模型，最稳）；注入了模型时才允许一段不超过
   100 字的受约束补充说明，且不得新增信号、不得改变类别、不得出现真假判定词，
   越界即丢弃、退回纯模板。

## 4. 降级行为（每个出口都有）

| 场景 | 行为 |
|---|---|
| 输入为空/超长/无法识别 | needs_clarification，请用户补一个具体网址，不猜 |
| 取页失败 / 正文为空 / 取页不可用 | `state=unreachable`，类别退回目录/档位口径，limits 写明原因 |
| 预算/死线到顶（还没读到页） | budget_exhausted，保留目录/档位口径的判定，limits 写明 |
| 用户取消 | cancelled，保留已取得的判定 |
| 模型补充说明越界/不可用 | 丢弃补充说明，摘要退回纯代码模板（主结论不受影响） |

注意：`state=unreachable` 不是"查过没问题"，是"这次没读到"；报告与摘要都会把
这一点写在明处。

## 5. 边界案例

| # | 场景 | 这样做 | 不这样做 |
|---|---|---|---|
| 1 | 域名是 `xxx.gov.cn` 但正文无任何官方标记 | 单点信号 → "倾向官方（未核验）" | 因为后缀像官方就说"官方认定" |
| 2 | 正文有"主办单位"等官方标记且域名命中官方后缀 | 两个代码信号达标 → 已核实（official） | 看见标记就忽略域名边界 |
| 3 | 伪装域名 `xinhuanet.com.evil.com` | 域名边界后缀匹配失败 → 未核验 | 当新华网采信 |
| 4 | 页面通篇自称"权威发布""官方指定" | 自称不是信号 → 未核验/倾向 | 把自述当身份依据 |
| 5 | 两个已核验页面都提到该域名（交叉提及） | 与其他信号合并计数，达标即已核实 | 单凭提及就认官方 |
| 6 | 用户只给机构名 | 先查目录；未登记 → unclear，请补网址 | 按名字听起来像官方就给结论 |
| 7 | 页面 302 跳到另一个域名 | 拒绝跳站，按页面不可达降级 | 评跳过去的那一站 |

## 6. 与代码校验的关系（重要）

- `authority_category` / `verified` / `signals` 全部由代码产出
  （`classify_source` + `dynamic_authority_signals`），模型不参与判定；
- 类别是七值封闭枚举，未知类别一律落 `unverified`，绝不猜；
- 可选的模型补充说明只许转述代码判定：新增 URL、真假判定词、未核验时出现
  "官方认定/权威认定/已核实"等升级表述，一律整段丢弃并记 limits；
- 本速查只评信源身份，不对任何具体说法给真假结论，也不给数值分、不建档。

> 记忆点：只评信源不评内容；决定性代码信号够了才说"官方/权威"，否则只给倾向
> 或"未核验"；页面不可达就如实降级，绝不替它圆一个结论。
