# 证据检索（retrieve-evidence）

## 1. 这个技能在回答什么

只回答一个问题：**查到了什么**。它是取证三技能的第三阶段，产出逐条主张的**可定位
引文**与**初步关系**。它不下真假结论、不汇总成"基本属实/不实"、不给任何数值分，
也不把检索范围扩到未核验域名之外。

两个硬约束贯穿本阶段：引文必须逐字来自**实际读取过的正文**（不是搜索摘要、不是模型
转述）；关系只能描述"这条资料对这条主张意味着什么"，不能升级成"所以这是真的/假的"。

## 2. 主张拆分口径

1. **一条主张 = 一个可独立判断的陈述**。复合句按可独立判断的部分拆开；拆不开的
   整句作为一条，不要臆造拆分。
2. **text 必须是原文逐字片段**（含标点，不改写、不翻译、不概括），代码会拿回原文
   做逐字定位并记录字符偏移；定位不到 → 该条主张记 error 丢弃。
3. **claim_status**：`checkable` = 可核查的事实陈述；`not_checkable` = 观点、情绪、
   诉求、预测、价值判断（"太可怕了""应该严查""我觉得会涨"）。后者不检索，只在报告
   里列出。
4. **qualifiers** 只填原文里明确写出的限定：时间、地点、实体（机构/人物/产品）。
   原文没写就填 null，不要根据常识补。
5. **queries 是中性检索词**：主张的核心词 + 中立改写，不带立场词（"谣言""假的"
   "揭秘"）、不带范围操作符。代码在生成检索词前会做脱敏（邮箱/手机号/身份证号/URL），
   并剥掉模型写的 `site:` / `inurl:` / `intitle:` / `filetype:` 等操作符——
   域名范围由代码按已核验信源拼接，不归模型管。

## 3. 引文抽取口径

1. **quote 必须摘自实际读取的正文**，逐字、不改写、不拼接两段。代码会拿这句回已读
   正文做逐字定位并记录归一化字符偏移；定位不到 → 该引文记 error 丢弃，不用转述
   补位，也不用搜索摘要顶替。
2. **relation 只能取**：`supports`（该资料直接陈述的内容与主张一致）/ `refutes`
   （直接指出主张不实或存在误解）/ `partial`（部分一致，条件或范围不同）/
   `background`（同主题背景，不直接对主称作证）/ `unclear`（读了仍无法判断关系）。
   只依据引文本身能支撑的程度选，不做延伸推测。
3. **limitations 写这一条证据的局限**：引文过短、正文可能被截断、时点不明、
   与另一条正文相同（转载/镜像）等。没有局限就给空数组，不要编。
4. **找不到就找不到**：某主张在某信源没有对应内容 → 记缺口，不换一个未核验域名
   继续找，也不用同主题的别处内容充数。

## 4. 字段口径明细

| 字段 | 这样做 | 不这样做 |
|---|---|---|
| `text` | 原文逐字片段，代码可定位 | 概括句、翻译句、拼接句 |
| `claim_status` | 事实陈述 checkable，观点情绪 not_checkable | 把"应该严查"也标成可核查 |
| `qualifiers` | 原文写了的才填，没写填 null | 用常识补时间/地点/主体 |
| `queries` | 中性词，可含主张核心词 | 带"谣言/假的/揭秘"或 site: 等操作符 |
| `quote` | 已读正文里的原句 | 跨两段拼接、加省略号、改写润色 |
| `relation` | 只看引文能支撑到什么程度 | 因为资料来自辟谣平台就默认 refutes |
| `limitations` | 写真实的局限，没有就空数组 | 写"证据充分""可信度高"这类评语 |

## 5. 边界案例

| # | 场景 | 这样做 | 不这样做 |
|---|---|---|---|
| 1 | 已读正文通篇在讲同类现象，没有一句对主当作证 | relation=background 或 unclear，limitations 说明"未直接对主当作证" | 硬选 supports/refutes 让报告"有结论" |
| 2 | 模型想摘的句子其实跨了两段，中间有省略 | 只摘其中一段逐字可定位的原句 | 用"……"拼接后当成引文 |
| 3 | 主张是"专家称某药副作用明确"这类转述 | 仍按原文逐字拆出 claim，检索时用中性词 | 改写成"某药有副作用"再当主张文本 |
| 4 | 已核验信源里查不到，未核验域名上有"看起来对得上"的内容 | 记缺口，停止该主张 | 把未核验域名拉进证据链 |
| 5 | 同一篇通报被两个已核验站点同时转载 | 两条都留，但归并成同一条证据链并注明转载 | 当成两份独立证据虚增覆盖 |

## 6. 预算与降级

- **每主张有查询数与读页数上限**（`per_claim_max_queries` / `per_claim_max_pages`）：
  到顶即停该主张，不无限加查询；
- **总预算到顶或用户取消**：保留已取得的证据，状态分别记 budget_exhausted / cancelled，
  绝不整批丢弃，也不把"提前停止"说成"查完了没有"；
- **引文超长**（超过 `max_quote_chars`）会先被截断再重新定位，定位不上才丢弃并记 error；
- **主张数超限**（超过 `max_claims`）：请求用户缩小范围，已拆出的主张保留；
- **合法空结果**：某主张在所有已核验信源里都没有对应引文 → 记缺口，这是正常输出。

## 7. 与代码校验的关系（重要）

- 主张 `text` 必须逐字定位原文；引文 `quote` 必须逐字定位已读正文，两处都记录
  归一化字符偏移，定位失败即丢弃并记 error；
- `relation` / `claim_status` 必须命中封闭枚举，否则记 error 并按保守值处理；
- 检索词统一过 `strip_pii` + 范围操作符剥离，`site:` 由代码拼；外发前不含原文
  全文，只含主张短句与中性改写；
- 检索被降级/未授权（外部检索不可用）与"检索过但无结果"是两回事，代码分别记
  error + 缺口 与 纯缺口，绝不把"没搜"表现成"搜过了没找到"。

> 记忆点：引文逐字来自已读正文，关系只看引文能支撑的程度；查不到是合法结果。
