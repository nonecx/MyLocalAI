# 事件时间线（event-timeline）

## 1. 这个技能在回答什么

只回答一个问题：**这段时间里，有公开来源记录的事件按时间排开是什么样**。用户给一个
主题，助手去授权检索渠道找来源、逐页读正文，把"某日发生了某事（原话在此、出处在此）"
抽出来排成线。它**不判断任何事件真伪、不推断走向、不给评分**：没有来源记录的事件不进
时间线，读不到正文的页面不贡献事件。

## 2. 抽取口径（本文件约束的模型行为）

1. **event 是一句事件描述**：说清"谁、在什么时候、做了什么"，只复述正文内容，
   不评价、不推测后果、不写"由此可见/说明"式的延伸。
2. **quote 必须逐字来自上面给的已读正文**：不改写、不翻译、不概括、不拼接两段。
   代码会拿这句回正文做逐字定位并记录归一化字符偏移；定位不到 → 整条丢弃，
   不用转述补位，也不换一个"看起来对得上"的句子凑数。
3. **一段只抽一条，单页最多 3 条**：挑最能回答主题的原话，不要把整页抄一遍。
4. **date 给日期原样**（`2026年11月20日` / `2026-11-20` / `上周` / `3年前`…），
   归一与精度标注全部由代码做；没有把握就留空串——无日期事件单独成区，
   **不要为了好看补一个日期**。
5. **不得出现真假判定词**（"是真的/是假的/属实/不实"等），**不得新增 URL**：
   来源 URL 一律由代码按实际读到的页面填写。

## 3. 代码校验（模型输出之后的漏斗）

- 描述为空 / 含真假判定词 / 含 URL → 丢弃，记 error + limits；
- 引文缺失、超长且截断后仍无法定位、未在已读正文中逐字定位 → 丢弃，记 error + limits
  （counts.dropped 如实计数）；
- 日期字段无法归一时，代码再从引文里抽一次；仍抽不到 → 进 undated 区，不猜日期；
- 同一段逐字引文、或同域 + 标题近似 → 判同源转载副本，只保留一条（**合并不并结论**：
  不把多条事件并成一条新结论）；
- 有日期事件按时间排序、受 `max_events` 上限约束；无日期事件同样受上限约束，
  且永远不进主线。

## 4. 字段口径明细

| 字段 | 这样做 | 不这样做 |
|---|---|---|
| `date` | 正文/字段里的日期原样 | 按发布渠道猜一个日期填上 |
| `event` | 一句具体事件描述 | 写成观点、情绪、行动建议、趋势判断 |
| `quote` | 已读正文里的原句 | 跨两段拼接、加省略号、改写润色 |
| `source_url` / `source_title` | 代码按实际读到的页面填写 | 模型自行补一个链接 |

## 5. 边界案例

| # | 场景 | 这样做 | 不这样做 |
|---|---|---|---|
| 1 | 正文通篇是导航与口号，没有实质原话 | 该页不产事件，代码记 error | 用页面标题当引文 |
| 2 | 事件发生在"上周"这类相对时间 | 给原样"上周"，代码按 as_of 归一并注精度 | 自己换算后写成一个具体日期 |
| 3 | 两个站点发同一篇通报 | 同域转载/同文副本合并为一条，limits 写明 | 当成两个独立事件各占一行 |
| 4 | 综述想写"由此可知该事件是真的" | 删掉判定，只写来源记录了什么 | 让判定词进时间线 |
| 5 | 资料里没有日期 | 进 undated 区 | 为了主线整齐补一个日期 |
| 6 | 检索没授权/全败 | 如实 failed，一次读页都不发起 | 把"没搜"表现成"搜过了没找到" |

## 6. 预算与降级

- 检索/读页/模型调用各有上限（`rules.json`：`max_searches` / `max_pages` /
  `max_llm_calls`，另有 `max_events` / `max_quote_chars` / `total_deadline_s`）；
  到顶即停，**保留已取得的事件**，代码如实记 budget_exhausted / cancelled；
- 未注入事件描述模型 → 只完成检索，不读页、不产事件，状态 partial；
- **合法空结果**：检索全部成功但零候选/零事件 → completed + 缺口写明原因，
  这是正常输出，不是失败；
- 汇总默认纯代码模板（零模型，最稳）；注入模型时才允许一段不超过 120 字的受约束
  补充说明，且不得新增事件、日期、URL，不得出现真假判定词，越界即整段丢弃。

## 7. 与代码校验的关系（重要）

- 日期归一、引文锚定、同源去重、排序与上限全部由代码完成，模型无权覆盖；
- `state` 是封闭枚举（`ok` / `unclear` / `search_unavailable` / `extract_unavailable` /
  `page_unavailable`），未知值不会出现；
- 运行 status 用 `collect_core.STATUSES` 六态：completed / partial /
  needs_clarification / failed / cancelled / budget_exhausted；
- "检索被降级/未授权"与"检索过但无结果"是两回事，代码分别记 error + 缺口 与 纯缺口，
  绝不把"没搜"表现成"搜过了没找到"。

> 记忆点：每条事件都要追得到一句逐字原话和一个出处；追不到的就丢掉或进无日期区——
> 查不到是合法结果，编不出来不是。
