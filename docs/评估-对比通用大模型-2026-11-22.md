# 评估报告：本项目 vs 通用大模型（DeepSeek 等）在谣言核查相关功能上的对比

> 日期：2026-11-22
> 环境：feature/user-profiles-roles @ 53569d5，worktree 测试库，服务 127.0.0.1:8000
> 实测方式：API 逐功能体验（脚本与原始数据在 worktree `.tmp/`，不入库）
> 诚实声明：本机未配置任何大模型 API 密钥（`LONGCAT_API_KEY` 为空值），API 级
> 结构化对比未做——已交付可直接运行的对比脚本（`scripts/compare_llm.py`，见 §8）。
> **通用大模型一侧已做真机实测**：2026-11-22 用用户登录的 DeepSeek 网页版
> （chat.deepseek.com）对同一组 5 条说法逐条提问并记录（见 §2b）。
> 本机网络对中文搜索引擎有反爬干扰，本项目联网功能的部分结果受此影响（已如实标注）。

## 1. 结论速览

**本项目与通用大模型不是竞争关系，而是"增强层"与"底座"的关系**：DeepSeek 等大模型
擅长开放域理解与表达，但直接拿它判谣言有四个硬伤——幻觉（无证据也会给结论）、不可
复现（采样漂移）、无记忆（每次从零开始）、隐私（明文上云）。本项目把这四点逐一补上：
**大模型只负责"理解与表达"，判定交给确定性代码，证据必须可核验，结论可复现，数据留在本机**。

| 维度 | 通用大模型直接问 | 本项目流水线 |
| --- | --- | --- |
| 判定可信度 | ⚠️ 会编造"研究证明…"+ 假出处 | ✅ 无证据不出结论，证据逐字可核验 |
| 同输入同输出 | ❌ 采样漂移 | ✅ 纯函数打分 + 进程内缓存（实测 0.03s 秒回） |
| 证据 | ❌ 常无 URL 或编 URL | ✅ 证据本带链接/时点/立场，信源分级 |
| 隐私 | ❌ 明文上云 | ✅ fail-closed：未授权零外发 |
| 成本与延迟 | ⚠️ 按 token 计费、延迟波动大 | ✅ 双预算封顶 + 缓存 + 确定性部分零成本 |
| 记忆与积累 | ❌ 无状态 | ✅ 档案库/指纹秒回/个人画像（纯 SQL 聚合） |
| 持续监测 | ❌ 不会自己跑 | ✅ 订阅调度 + 平台巡检 + 变化摘要 |
| 开放域理解 | ✅ 强 | ⚠️ 依赖底层 LLM（理解层），判定层不依赖 |
| 语言/多模态泛化 | ✅ 强 | ⚠️ 聚焦中文言论核查单领域 |
| 部署 | ✅ 开箱即用 | ⚠️ 本地单进程演示级（127.0.0.1 无鉴权） |

## 2. 实测体验记录（2026-11-22，本机）

以下为 API 实测（原始数据 `worktree/.tmp/experience_results.json`）：

| 功能 | 时延 | 结果 | 说明 |
| --- | --- | --- | --- |
| classic 分析（确定性判定链） | **0.03s** | 四档结论 + 话术标记 | LLM 缺席 → 情感/攻击模块如实记 error，报告走本地模板，**判定不受影响** |
| agent 联网核查（5 条说法） | 5.9-6.2s/条 | 存疑待核实 37 / 31、无可核实陈述 0 / 0、低风险 10 | **没有 LLM 仍给出差异化确定性结论**（话术标记 + 规则引擎独立打分）；degraded=True 如实 |
| 热度算分（manual） | 0.03s | E、S、三分项 | 纯公式，同输入必同输出 |
| 热度联网估参 | 3.12s | x=0 → E≈0 | 检索层受反爬影响 0 命中，**如实返回 0 不编造** |

| 订阅 run-now（run 8） | 202 + ~12s | ok、results=0、next_run_at 推进 | 检索降级导致 0 结果，状态机照常推进不卡死 |
| 参谋三聚合（patterns/sources/weekly） | 0.00-0.03s | 10 档案聚合：存疑待核实×6 等 | **零 LLM**，纯 SQL 聚合，数据少时如实空 |
| 稳定性对拍（同文本×2） | 0.03/0.04s | 结论逐字一致 | 缓存命中，成本增量 0 |
| 直探百度对照 | 0.26s | HTTP 200 但仅 2689 字节 | 搜索引擎返回反爬验证页——**定位到检索层降级根因** |

## 2b. 真机实测：DeepSeek 网页版（2026-11-22 补测）

**测试方式**：用户登录的 chat.deepseek.com（网页版 v2.8.0），同一组 5 条说法逐条
**原话直接粘贴**（不带任何提示词引导，模拟真实用户"直接问大模型"），每条新开对话
保持独立；"深度思考"与"智能搜索"开关保持默认状态（DeepSeek 自动决定是否联网）。
同一说法（第 1 条）追加问一次测稳定性。时延为发送到生成完成的粗粒度观测。

| # | 说法 | DeepSeek 网页版行为 | 联网 | 引用 | 时延 |
| --- | --- | --- | --- | --- | --- |
| 1 | 隔夜茶致癌 | 明确辟谣："缺乏科学依据的谣言"；亚硝酸盐 0.02mg/kg、比米粉限量还低、要中毒需喝 210 升 | **自动搜 12 网页** | 人民网科普/科普中国/市场监管报等真实可点链接 | ≤20s |
| 2 | 自来水被下毒 | "没有任何官方权威信息可以证实…典型的谣言"；列举成都龙泉驿/杭州余杭/广东肇庆等多地辟谣先例 | **自动搜 22 网页** | 央视/澎湃/地方媒体链接 | 25s |
| 3 | 红酒延寿十年 | "并不成立，属于对研究结论的夸大和误读"；观察性研究≠因果、孟德尔随机化、白藜芦醇剂量、WHO/IARC 1 类致癌物 | 未联网 | 无 URL（纯知识推理），无编造出处 | 25s |

| 稳定性 | 第 1 条重问 | 结论方向一致；**搜索集变化（12→14 网页）、支撑数据口径变化（WHO 4.2mg vs 国标 1mg/L）、措辞不同** | 14 网页 | 引用集不同 | 25s |

**本项目对照**（同一组说法，降级态实测）：存疑待核实 37 / 存疑待核实 31 / 无可核实
陈述 0 / 无可核实陈述 0 / 低风险 10——0 结果来自检索层被反爬拦截 + 无 LLM，结论
保守且不复述谣言内容；若检索层正常，结论卡会带真实证据链接（机制如此，本机未复现）。

**真机实测得出的增量结论**：

1. **网页版 DeepSeek 的自动联网搜索在本机网络下完全可用**（12-22 网页/次）——与
   本项目自建爬虫式检索源被反爬拦到 0 结果形成鲜明对比。这印证 §4.3 的定位：
   弱点在"本地爬搜索引擎"这一实现方式，不在网络本身；**解决方向（P0-2 换结构化
   检索 API 源/RSS）的正确性被实测加强**。
2. **幻觉测试通过**：刻意模糊的"某知名品牌"没有诱发编造，DeepSeek 用检索把模糊
   说法锚定到真实事件并分清批次/渠道，还如实补充"未发现中毒确诊病例"。这与 API
   裸调用的幻觉风险不同——**网页版自带的检索增强正是它防幻觉的机制**（也正是
   本项目给底层模型配证据链的同一思路）。
3. **稳定性实测**：结论方向可复现，但搜索集/引用/支撑数据每次不同——"同输入同
   输出"在网页版上不成立（与本项目结论卡逐位复现形成对照）。对"要留存、要复盘、
   要对质"的场景，这是实质差异。
4. **表达力优势明显**：第 3 条（红酒延寿）DeepSeek 给出五层递进的科学解读
   （观察性研究≠因果、白藜芦醇剂量、1 类致癌物），本项目同说法的降级输出只是
   "无可核实陈述 0 分"——严格但不教育。**面向"想要弄懂"的用户，大模型体验更好**；
   面向"要留存证据"的场景，本项目更硬。
5. **时延**：DeepSeek 网页版带搜索 20-25s/条，**快于本项目 agent 模式的满血口径
   （README：30-120s）**——因为本项目还要走受控浏览/逐条校验。诚实记录这一劣势。

## 3. 本项目的优势（对比"直接问大模型"）

1. **判定不靠模型自觉**：`verdict.assess` 与四档分层是纯函数（输入只有确定性数字与
   封闭标签集），大模型文本进不了打分链——变异测试锁定。直接问 DeepSeek 得到的
   "risk_score" 是模型主观输出，换次对话就变。
2. **证据纪律**：collect_evidence 三阶段编排里，信源身份不可自我认证、引文逐字定位
   校验、正文哈希去重、PII 剥离；结论卡的每条证据带链接与时点。通用大模型无检索时
   靠参数知识作答，幻觉率随说法的长尾程度上升，且**无法自查**。
3. **可复现与缓存**：同进程内同输入只真正调一次上游（single-flight 在失败路径也共享），
   实测同文本两次 0.03/0.04s 秒回同结论；缓存 TTL/分区（deep_read 独立命名空间）
   防串味。大模型对话即使 temperature=0 也无此保证（且部分提供方不认 seed）。
4. **隐私 fail-closed**：三类数据保存、外部提供方、public-search/public-web 全部
   显式授权，未授权零外发（实测 URL 未授权 → blocked 徽章，零请求发出）。对话式
   大模型明文上云，无本地授权面。
5. **成本与预算封顶**：请求级时长预算（JUDGE_DEADLINE_S）→ 批次双预算（条目 90s +
   整批 900s）→ 未跑条目标 not_run 不装"没发现"；真实成本计数（缓存命中不计、
   usage 取不到如实 0）。直接用大模型没有这些闸门，长尾请求与并发放大全靠自己兜。
6. **记忆与越用越聪明**：核查落库 → 指纹秒回（相似说法先问再查，不擅自断言同一谣言）→
   信源画像反哺抬分 → 话术模式库/周报（纯 SQL 聚合零 LLM）。大模型对话无状态，
   用户每次都要重新交代上下文。
7. **持续监测自动化**：订阅调度（300s 下限、fail-closed 授权闸、变化摘要只述事实）+
   平台巡检（两阶段成本控制、纯函数传播风险分级）。这是对话式产品结构性做不到的。
8. **降级诚实**：本机没有可用 LLM key，全链路照常运行且处处如实标注（degraded 徽章、
   error 字符串、本地模板回退、as_of 未知高亮）——**坏数据不装好数据**，这是直接
   问大模型时最缺的品质（它不知道自己不知道）。

## 4. 本项目的劣势 / 通用大模型的优势

1. **理解层依赖单一 LLM**：本机 key 缺失时情感/攻击/逻辑三模块、深查叙述全部降级；
   确定性骨架虽能给出结论，但**证据发现的质量**（选站、检索词、正文甄别）依赖底层
   模型的语言理解。DeepSeek 等的开箱理解能力远强于"无 LLM 的本项目"。
2. **领域聚焦**：中文言论核查单一领域；换行业要重配规则 JSON。通用大模型天然开放域、
   多语言、多模态（DeepSeek-VL 等可读图）。
3. **检索层韧性不足（本次实测暴露）**：中文搜索引擎反爬导致发现层/估参层 0 结果
   （百度直探返回 2689 字节验证页，解析层正确拒收但无备选源）；RSS/结构化检索源
   缺位。直接用 DeepSeek 时其自带联网检索（部分产品线）不受此影响。
4. **部署形态**：127.0.0.1、单进程、无鉴权、单 writer 假设；多 worker 下缓存/调度
   各自独立。DeepSeek 网页/App 开箱即用。
5. **交互表达**：结论卡结构化但表达力受限于模板与底层模型叙述；通用大模型的对话式
   追问、多轮澄清、长文写作更强。
6. **用户门槛**：需要 Python 环境、密钥配置、授权理解；DeepSeek 注册即用。

## 5. 通用大模型的劣势（本项目已经解决的部分——即"用本项目包住大模型"的理由）

| 大模型直接用的坑 | 本项目的对应解法 |
| --- | --- |
| 幻觉与编造出处 | 证据逐字定位校验 + 信源分级名单 + 无证据不出结论 |
| 采样漂移、同问不同答 | 纯函数打分 + 进程内缓存 + 变异测试锁判定链 |
| 长尾请求挂死、并发放大 | 请求预算 + 重试/超时闸 + single-flight 失败共享 |
| 无用户记忆 | 档案库 + 指纹 + 画像 + 会话持久化（SQLite） |
| 隐私不可控 | 授权闸 fail-closed，密钥/地址成组绑定不串提供方 |
| 成本失控 | 双预算 + 真实计数 + 缓存 |
| 无法持续盯梢 | 订阅/巡检/调度线程 + 变化摘要 |
| 提示词注入改判定 | 路由四层防护链 + 权限分级 + 15 变异用例锁注入无效 |

## 6. 解决方案（按优先级）

### P0（立即可做，成本≈0）

1. **补密钥，先让理解层满血**：`.env` 里 `LONGCAT_API_KEY=` 是空值——填入任一可用
   提供方即可让全部降级组件恢复。`providers.json` 已内置 `deepseek`/`openai` 条目：
   加 `DEEPSEEK_API_KEY=…` 后，`.env` 设 `LLM_PROVIDER=deepseek`（模型 deepseek-chat）
   即整体切换；或保持 longcat 为主、用 `LLM_FALLBACKS` 配备用链（llm_client 的成组
   绑定与备用链机制已存在，密钥与提供方不匹配会启动自检报错，不会静默发错家）。
2. **检索源韧性**：本机实测中文引擎反爬。短期用平台已有的"用户自建信息源"机制挂
   RSS 源（RSS 无反爬，发现层即可用）；中期在 `retrieval/sources.py` 增加结构化
   检索 API 源（博查/Bing API/SerpAPI 类，按查询计费但结果稳定），配置外置 JSON
   与现有纪律一致。

### P1（本周可做）

3. **把对比实验固化成例行评测**：`scripts/compare_llm.py` 已就绪（用法 §8）——
   填 key 跑基线，之后每次换模型/换规则重跑，追踪 verdict 分布、延迟、稳定性、
   成本四条曲线；发现 LongCat 漂移或 deepseek 更优时用数据说话切提供方。
4. **"何时用哪个"的决策口径写进使用说明书**：单条陌生说法→直接问大模型快速参考；
   需要证据/要落档/要复现/涉隐私→走本项目；批量材料→材料批次面板；持续盯梢→订阅/平台。
5. **给 DeepSeek 侧的增强建议**（若用户选择以大模型为主力）：检索增强（RAG，把本项目
   证据本喂给它）、结构化输出（JSON schema 约束）、temperature=0、要求引用可核验 URL
   并逐条复核——这四件事本项目都已实现，等效于"把大模型装进本项目的笼子里"。

### P2（规划项）

6. **多模态/跨语言扩展**：截图谣言、视频字幕核查——底层换多模态模型，判定层复用。
7. **多 worker 与鉴权**：若要局域网多人使用，补鉴权与缓存共享层（当前演示级口径
   如实写在 README）。
8. **领域迁移包**：换行业只改 `verdict_rules.json`/`sources_registry.json`/提示词
   的既有纪律，可做成"行业配置包"分发。

## 7. 一句话定位

> **大模型是"会说话但会编造的证人"，本项目是把证人关进程序笼子的法庭**：
> 证据必须可核验、打分必须可复现、支出必须有预算、记忆必须可积累——
> 这四件事通用大模型产品形态上给不了，也正因此两者组合（本项目编排 + DeepSeek 等执行
> 理解层）优于任何单独一侧。

## 8. 附录：对比实验脚本用法（填 key 即可复现实测）

```bash
# 1) 配置密钥（本机 .env 或环境变量，勿提交）
set DEEPSEEK_API_KEY=sk-xxxx

# 2) 启动本项目服务（已运行可跳过）
my_website\start.bat

# 3) 跑对比（默认 5 条内置说法；可 --claims-file 换自己的）
.venv\Scripts\python.exe scripts\compare_llm.py

# 换其它 OpenAI 兼容提供方：
.venv\Scripts\python.exe scripts\compare_llm.py --base-url https://api.moonshot.cn/v1 --model moonshot-v1-8b --api-key sk-xxx
```

指标口径：延迟（两端实测）、两次输出一致性（SequenceMatcher 比率，仅 LLM 侧）、
JSON 结构合法率（结构化提示下）、可核验 URL 数、不确定表述计数（"可能/不确定/待核实"
等）、token 用量；项目侧另记 degraded 与 evidence 数。结果落 `.tmp/compare-llm/report.json`。

## 9. 局限
