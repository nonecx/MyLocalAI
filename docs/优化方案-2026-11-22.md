## 1. P0：当天可做，立即让"优势更稳、不足变优势"

### P0-1 检索源结构化升级（针对 E1/E2，补齐最大短板）

**问题**：自建爬虫式搜索源（so360/baidu）被反爬拦到 0 结果，导致发现层、估参层、
agent 取证、平台巡检四处同时失血；而同网络下服务端检索畅通（E1/E2）。

**方案（两步走，互相独立）**：
1. **检索源抽象加"API 型源"**：在 `retrieval/search.py` 的 provider 注册机制里新增
   一类 `api` 协议源（候选：博查 API / Bing Web Search API / SerpAPI——均按查询计费
   但结果稳定、无反爬），配置沿用现有纪律：源清单外置 JSON（新增
   `retrieval/search_sources.json` 或复用 `platform_rules.json` 的源段），密钥走
   `.env`/`model_secrets.json` 既有优先级。
2. **零成本过渡**：无需任何 API key 的当下，用平台"用户自建信息源"机制（已实测可用，
   E7 同链路）把科普中国/人民网辟谣等 **RSS 源**挂进发现层，缓解"0 结果"；
   RSS 无反爬，`platform/sources.py` 已支持。

**改动点**：`retrieval/search.py`（provider 协议分支）、`retrieval/sources.py`
（域名分级对新源的适配）、`platform/sources.py`（RSS 已有，验证即可）。
**验收**：同一说法下估参/巡检/agent 取证非 0 结果；反爬页被自动跳过且计入
degraded 计数（不报错、不硬编）；"不传参数时逐位不变"守卫测试保持全绿。
**优先级**：P0——它同时是"不足补齐"和"让大模型增强层成立"的前提。

### P0-2 密钥健康度显性化（针对 E8，把"配了没配"变成一眼可见）

**问题**：四处配置位（.env/providers.json key_env/设置面板/环境变量）+ 无任何页面
提示，连真实用户都以为配了 key（E8），所有分析静默降级。

**方案**：
1. **服务状态 chip 增加 LLM 维度**：`shell.js` 的状态区在 `/api/health` 的
   `llm.usable=false` 时显示"⚠ 模型未配置（分析降级）"并可点进设置；`usable=true`
   时显示提供方名。`/api/health` 已有 `llm{usable,provider,error}` 字段，纯前端改动。
2. **设置弹层"密钥体检"卡**：`settings.js` 模型 Tab 顶部加一行当前
   `key_source`（env / secrets / none，`/api/models` 的 runtime 段已返回该字段），
   none 时红字"未配置密钥——分析将以降级模式运行，证据发现不可用"。
3. **降级不再"只在不显眼处"**：结论卡的 degraded 徽章（已有）旁补一行可操作文案：
   "模型未配置：去设置 → 模型管理 填写密钥"（区分"没配 key"与"上游临时故障"两种
   degraded 原因，health 的 error 字段可区分）。

**改动点**：`web/static/shell.js`、`web/static/settings.js`、`web/static/cards.js`
（一行文案）、`web/static/chat.css`（少量样式）。
**验收**：无 key 启动 → 顶栏出现降级警示并可跳设置；填 key 保存（写后
`reset_cache()` 已存在）→ 不重启服务 chip 变绿、下一次分析不再 degraded。

### P0-3 填 key 即满血（针对 E5/E6，一条命令的事）

**方案**：`.env` 填 `LONGCAT_API_KEY`（或加 `DEEPSEEK_API_KEY` + `LLM_PROVIDER=deepseek`）；
这是本方案里唯一需要用户提供密钥的项，其余全部不依赖密钥。填完后重跑
`scripts/compare_llm.py` 得到"本项目满血 vs DeepSeek 网页版"的完整对比数据，
替换评估报告中的降级态基线。

**验收**：`/api/health` 的 `llm.usable=true`；同一说法的 agent 模式返回非空
evidence 数组且结论卡带真实链接。

## 2. P1：稳定性核心（一周内）

### P1-1 多提供方备用链（针对 E12/E6，机制已有，只差配置与验证）

**方案**：`.env` 配 `LLM_FALLBACKS=deepseek,openai`（机制已存在：成组绑定 + 备用链 +
预算继承 + 4xx 才回落），并跑一次"主提供方断连演练"（临时改错 LONGCAT_BASE_URL）验证
切换与 degraded 标注。补一条守卫测试：主链 5xx → 备用链接管 → `degraded_components`
如实记录。

**验收**：主链故障时请求不失败、响应带备用链标记；预算不翻倍（每次成功调用各计一次，
真实计数口径已有）。

### P1-2 LLM 输出质量闸门指标化（针对 LongCat 空 content 前科）

**方案**：`llm_client` 已有 JSON 稳健解析与重试/回落；新增进程级"空 content/解析失败
计数器"并入 `/api/health`（如 `llm.empty_content_streak`），连续 N 次空 content 时在
health 里给"建议切换提供方"信号——把 README 里"LongCat 有空 content 前科"从文字
变成可观测指标。

**验收**：stub 连续返回空 content → health 出现非零 streak 与建议字段；正常时为 0。

### P1-3 注入防御固化为持续回归资产（针对 E3——把"实测免疫"变成"永远免疫"）

**方案**：把本次实测的注入语料（角色扮演确认器/忽略设定/越权改分/删档指令）沉淀进
mock 闸门或离线套件的变异用例组（现有 15 个变异用例 + 28 条 mock 闸门的扩容），
覆盖：改分数、删档案、越权工具调用、身份重置、组合注入。每条断言：refuse/clarify +
零成本 + 数据完好。

**验收**：`scripts\ci.cmd` 的闸门条数增加且全绿（README 计数同步）。

### P1-4 状态机时序窗口系统排查（针对 E11 的经验教训）

**方案**：以批次"停止竞态"为样本，审计其它"前端状态翻转 vs 后端异步收尾"的窗口：
订阅 run-now（已修 R2）、平台巡检触发/单飞、SSE 重连。对每个窗口补两类测试：
竞态用例 + 前端"终态后延迟刷新"兜底。产出一张"异步状态窗口清单"进 docs。

**验收**：新增竞态测试全绿；清单文档入库。

### P1-5 检索结果多源融合与复用（针对 E2 的启示）

**方案**：多源（API 源 + RSS + 爬虫源）结果按既有正文哈希/URL 去重合并（evidence
去重机制已有），`external_cache` 保留期（7 天）内同查询复用；按源健康度动态降权
（连续失败源暂时跳过并记数，恢复后自动回归）。

**验收**：单源全挂时其余源顶上（结果非 0）；全部挂时如实 0 + degraded；重复查询
命中缓存（零外发）。

## 3. P2：优势更强（规划项）

### P2-1 确定性打分依据可视化（强化 E5 这一独有卖点）

**方案**：结论卡新增"打分依据"折叠区：本次命中的话术标记（六类风险特征 + 可信度
线索）与各自分值——数据在初扫 markers 里已结构化沉淀（dossier_markers 表），
补前端展示即可。**这是任何大模型产品给不出的东西：为什么是这个分数，逐项可解释。**

### P2-2 与大模型的互补引导（把竞品变成下游）

**方案**：结论卡尾部加"核查要点复制"按钮——把本项目的结论 + 证据链接序列化为一段
可粘贴文本，引导用户"拿去任何大模型对话深入追问"。实测证明 DeepSeek 网页版能很好
消化此类输入（T7/T9 的引用质量）；本项目的硬结论 + 它的表达力 = 互补闭环。

### P2-3 例行评测资产化

**方案**：`scripts/compare_llm.py` 纳入"换模型/换规则必跑"清单；可选加 `--json-only`
供定时任务；评估报告随数据更新（评估报告的时效性声明已写明）。

### P2-4 部署硬化

**方案**：按 README 已知局限逐项落地——多 worker 缓存共享策略、局域网鉴权（当前
127.0.0.1 无鉴权）、`data/` 备份指引已有（使用说明书）——先做鉴权与多 worker 文档。

## 4. 实施顺序建议（依赖关系）

```
P0-3 填 key ──────────────► 全链满血，其它项的验收才有完整口径
P0-2 密钥健康度 ─► 独立可做（纯前端）
P0-1 检索源升级 ─► 是 P1-5 多源融合的前置
P1-1 备用链 ─► 依赖 P0-3 的 key（至少一把备用）
P1-3 注入回归 ─► 独立可做（纯测试资产）
P1-2/4、P2-* ─► 随后
```

## 5. 明确不做（保持既定边界）

- 判定语义不放宽（`verdict.assess` 纯函数 + 变异锁不动）；大模型永远不进打分链。
- 不做账号体系/云端部署（单用户本地工具口径不变）。
- 不把网页版大模型的能力复刻进本项目（如自动浏览 23 页）——本项目做"可审计的
  受控取证"（预算/白名单/逐字校验），不追"搜得多"。
