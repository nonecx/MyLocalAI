# 巡检报告技能 · 实施规格（2026-11-24）

> 状态：已实施（分支 `feature/patrol-report-skill`，代码在工作树、由集成方统一提交）。
> 本文是「巡检报告」阶段的**人读实施规格**：记录决策、三段式口径、payload 契约、
> LLM 角色三分、降级矩阵、四个出口、测试矩阵与已知局限。体例沿
> 《第五波专用技能-2026-11-23.md》。
> 范围：`platform/report/` 技能（`PatrolReport` + `SKILL.md`）、schema v12
> `scan_reports` 表、runner 收尾接线（`_build_report`）、
> `GET /api/platform/reports` 与 `GET /api/platform/reports/{scan_id}` 两端点、
> 平台页报告卡（`#platformReport`）、CLI 报告输出段、助手工具
> `platform_feed` 的 `kind="report"`。
> 读者：项目作者、后续执行会话、评审者。
> 原则延续：**不判真假，只述证据**；**大模型不参与打分/分类/选站/计数**；
> **每个出口都有降级**；**隐私 fail-closed**；全离线可测（所有 IO 可注入，
> 测试一律 stub，零网络零 LLM）。

## 1. 决策记录

| # | 决策 | 理由 |
|---|---|---|
| D1 | 巡检报告是**巡检主流程的收尾阶段**（`runner.scan()` 里 status 定稿后、`_finish` 前跑一次），**不是新的对话能力**、不新开对话 action | 报告回答"这一轮巡检看到了什么"，数据全部来自本轮巡检自身；做成对话能力就要重新检索或重新读库拼上下文，与"巡检收尾即出报告"的产品形态不符，还会把平台内部阶段暴露成用户能力枚举 |
| D2 | 三段式契约冻结：`_aggregate` 纯代码汇总（零 LLM）→ `_narrate` 一次 LLM 调用 → **代码校验器**（安全闸 + 截断 + 白名单） | 计数/分级/排序/环比全部代码算（铁律：大模型不参与打分与计数）；LLM 只做语言组织与逻辑判断；模型产物必须过代码闸才能进 payload，越界即丢弃并记 error |
| D3 | `llm_status` **七态封闭集**（`ok`/`disabled`/`unavailable`/`budget_exhausted`/`cancelled`/`skipped_empty`/`error`），`report/pipeline.py` 与 `platform/store.py` 的 `REPORT_LLM_STATUSES` 逐字同值，`save_report` 按同一集合校验 | LLM 到底有没有成功组织报告必须如实记账；两处任一处漂移即写库失败（`ValueError`），用测试对拍锁定 |
| D4 | **四个出口共用同一份 payload**（平台页 / CLI / REST / 对话卡），各出口只做呈现裁剪，不改写、不补造 | 同一轮报告在四个出口说法不一致比没有报告更糟；API 只读 `scan_reports` 原样返回，前端不重组 |
| D5 | 平台内部技能 `patrol-report`（`platform/report/SKILL.md`）**不占十三项用户能力枚举**、不进 `capabilities/` 目录、不占 `router.TOOL_ACTIONS` | 它是平台巡检阶段的内部执行技能（参照 `platform/domains.py` 的领域分类助理提示词）；对话侧只经既有只读工具 `platform_feed`（kind 封闭枚举追加 `report`）触达，不新增用户能力 |
| D6 | 口径全部外置 `platform_rules.json` 的 `report` 段（`enabled`/`max_llm_calls`/`max_entries`/`max_chars_per_entry`/`deadline_s`/`max_tokens`），改配置不改代码；坏值逐键夹取回退默认并告警 | 与平台其余段（screen/deep_verify/risk）同一机制；预算越界时"夹到安全区间"而不是炸掉巡检 |
| D7 | 报告是**增益面**：技能不可用/LLM 失败/落库失败都只落 warning 与 payload 里的 `llm_status`/`gaps`，scan 状态与返回绝不被拖累；`skipped` 与"无监控词"两条早退路径没有可汇总的一轮，**不产报告** | runner 主流程绝不因新阶段抛异常（仓库铁律）；没有一轮数据时硬出一份空报告等于编造 |
| D8 | 报告 LLM 调用有**独立预算面**（`report.deadline_s`，默认 60s，`llm_cache.deadline_scope` 机制），与深查预算互不占用 | 深查预算（`deep_verify.deadline_s`）已可能吃紧；报告再挤占会导致深查被提前掐断，两类调用分开记账 |

## 2. 定位与边界

**定位**：把一轮巡检**已经算好的**确定性汇总（计数、分监控词的 E 与环比、重点条目、
深查结论 label 与风险分、与上一轮的计数差）组织成一份人能读的结构化报告——标题、
执行摘要、分话题观察、分析要点、传播风险综述、后续建议。

**边界（四条，全部由代码结构保证而非模型自觉）**：

1. **不检索**：输入全部由 runner 传入（监控词清单 + counts + 条目清单），本技能不自行
   检索、不使用未传入的条目；缺输入依据的字段留空，由代码兜底。
2. **不评分/不计数**：E、环比、风险档位、深查结论、全部计数由 `_aggregate` 与上游
   runner 算好，LLM 只原样转述。
3. **不判真假**：真假归证据链（rumor 引擎 / 档案库），本技能只**引用**深查结论 label、
   **不生产**结论；模型文本命中真假判定词/过度断言词/URL 即整条丢弃。
4. **不自造**：数值/URL/日期/未传入的条目一律不许出现；`entry_ids` 与 `query` 只能来自
   传入清单（白名单收敛），没有就如实写缺口，不为有输出而编。

**隐私口径**：报告不新增任何外发通道（唯一一次 LLM 调用走既有 `chat_json`，
namespace=`platform_report`）；外部检索授权门在巡检主流程已把关，未授权时整轮 skipped、
根本走不到报告阶段。

## 3. 三段式契约（`platform/report/pipeline.py`，顺序锁定）

```
build(scan_id, scan_status, entries, queries, counters, warnings, prev_scan, cancel_check)
  ├─ (1) _aggregate()  纯代码汇总，零 LLM
  │     counts（五标量 + risk/verdicts/domains 三分布）
  │     topic_stats（分监控词：E/环比/候选数/最高风险档/代表标题前 3）
  │     highlights（风险档降序 → E 降序，前 5）
  │     changes（与上一轮 scan_runs 的计数差；无基准 → {}）
  │     gaps（降级计数、未深查计数——只述事实，不猜原因）
  ├─ (2) _narrate()    LLM 一次调用（预算 report.max_llm_calls，默认 1）
  │     system = SKILL.md 原文 + 机器契约（JSON 键名锁定）
  │     user    = 监控词清单 + counts 摘要 + 条目清单（≤max_entries 条、
  │              每条 ≤max_chars_per_entry 字，超出明说"仅展示前 N 条"）
  └─ (3) 代码校验器（纯函数，与 assistant/skills/research/pipeline.py 同口径**内嵌**
        实现——平台包不 import assistant）
        安全闸（真假判定词/过度断言词/URL 命中 → 整条丢弃记 error）
        截断（title 80 / summary 600 / note 300 / point 400 / risks 600 / followup 120）
        白名单（topic_notes.query ⊆ 本轮监控词；analysis.entry_ids ⊆ 本轮落库 id；
                followups ≤5 条）
```

`build()` **永不抛**：最外层还有一道兜底出口（`_emergency_payload`），任何意外都落成
合法空结果 + `llm_status="error"` + `errors`/`gaps` 如实标注，绝不为有输出而编。

## 4. payload 契约与字段口径

payload 键名冻结（16 键，缺一不可、不多不少）：

| 字段 | 口径 |
|---|---|
| `scan_id` | 轮次 id（坏值规整为 0 并记 `bad_scan_id` error） |
| `as_of` | 报告生成时刻（时钟可注入；本地 ISO 秒级带偏移） |
| `scan_status` | 本轮巡检的定稿状态（completed/partial/cancelled/…） |
| `llm_status` | 七态封闭集（见 §6 降级矩阵）；store 按同一集合校验 |
| `title` | 报告标题；LLM 未出（或整条被闸掉）时代码兜底「第 N 轮巡检报告」 |
| `summary` | 执行摘要；代码兜底为确定性概述（几个话题/几条候选/几条深查/高危紧急各几条） |
| `counts` | `{queries, candidates, verified, deduped, degraded, risk{notice,suspect,high,urgent}, verdicts, domains}`；风险档缺失/越界按 notice 保守计 |
| `topic_stats[]` | `{query, e, growth, candidates, max_risk_level, top_titles}`；growth 优先取 queries 带的 `growth`（runner `_scan_query` 现算），否则用该词条目 e/e_prev 现算，两者皆缺 → 0.0（不猜） |
| `highlights[]` | `{entry_id, title, risk_level, e_score, verdict_label, topic_domain}`；前 5 条，排序键 =（风险档降序, E 降序）稳定排序 |
| `changes` | `{prev_scan_id, candidates_delta, verified_delta, degraded_delta}`；首轮/无基准 → `{}`（不假装有对比） |
| `topic_notes[]` | LLM 产出，`{query, note}`；query 必须逐字在本轮监控词清单内 |
| `analysis[]` | LLM 产出，`{point, entry_ids[]}`；entry_ids 只保留本轮清单内真实落库 id |
| `risks` | 传播风险综述（按档位与领域分布说"风险集中在哪"，不判定真伪） |
| `followups[]` | 至多 5 条可执行的观察/核实动作 |
| `gaps[]` | 缺口与降级原因（含 runner warnings，前缀「巡检告警：」） |
| `errors[]` | `{stage:"report", category, detail}`——模型越界/坏输入的如实记账 |

**落库形状**（`scan_reports`，v12）：`save_report(scan_id, *, title, llm_status,
status, payload)` upsert——`scan_id` 唯一约束即"一轮一报"，重复保存覆盖四列、
行 id 不变、`created_at` 保留首建时刻；`get_report(scan_id)` / `latest_report()`
（id 倒序第一条）/ `list_reports(limit)`（limit 夹取 ≥1）按同一形状读回，
payload 由 JSON 文本还原（坏 JSON 兜底 `{}`）。

## 5. LLM 角色三分（对照表）

| 交给模型（语言组织 / 逻辑判断） | 不交给模型（真假判断 / 编造 / 越界） |
|---|---|
| 把多条条目组织成"同一事件多源报道"的一段话 | "该事件是真的/是假的/属实"之类真假判定 |
| 指出两条信源表述存在分歧并各自引用条目 id | 裁定分歧双方谁对 |
| 描述"热度环比上升与深查结论同时出现，风险档被 floors 抬到高危" | 把深查结论解释成真假佐证、把 label 改写成"基本可信" |
| 用"可能/倾向于/表现为"写推断语气 | 用"证明/足以说明/无疑是/铁证/实锤/盖棺定论"下断论 |
| 按传入数值**原样转述** E/环比/风险分/计数 | 四舍五入到好听、换算单位、自造数值/URL/日期 |
| 指出领域分布集中、信源档位分布 | 预测"接下来会爆发"、外推趋势 |
| 引用深查结论 label 作为数据 | 生产新结论（结论只能引用不能生产） |

> 记忆点：**数字原样转述，条目靠 id 回溯；判真假、下断论、造数据，三条都不归这个技能管。**
> 代码汇总（counts/topic_stats/highlights/changes/gaps）**零 LLM**，LLM 状态再差也不影响。

## 6. 降级矩阵（每个出口都有降级，build 永不抛）

| 触发条件 | llm_status | 行为 |
|---|---|---|
| `report.enabled=false` | `disabled` | 零调用；报告只有代码汇总，gaps 写明"报告功能未启用" |
| entries 为空（无候选） | `skipped_empty` | 零调用；**合法空结果，不是失败** |
| 生成前已取消（`cancel_check`） | `cancelled` | 零调用；不白烧一次 LLM |
| 模型调用预算为零 | `budget_exhausted` | 零调用；双保险（夹取保证 ≥1） |
| 模型返回预算耗尽（err 含 budget） | `budget_exhausted` | 已调用一次；记 error + gaps |
| 模型不可用 / 返回非 JSON 对象 / 缺全部关键键 | `unavailable` | 记 error + gaps；title/summary 走代码兜底 |
| 模型调用抛异常 | `error` | 记 error + gaps；同上兜底 |
| 模型产物命中安全闸 / 越界白名单 / 超截断 | `ok`（状态按"模型是否正常组织"如实记账） | **该条丢弃**并记 error；其余字段照常落值，被丢字段由代码兜底或留空 |
| build 主体意外异常 | `error` | 兜底出口：合法空壳 payload + `unexpected_exception` error |
| 报告技能未注入且 import 失败 | —（无 report 键） | runner 只留 warning「巡检报告未生成：报告技能不可用」 |
| 报告落库失败（`save_report` 抛） | 不变 | 报告已进 summary 照常呈现；只留 warning「巡检报告落库失败：…」 |

**降级不等于编一个报告顶上**：非 ok 时叙事四区（topic_notes/analysis/risks/followups）
本就是空，平台页/CLI/对话卡先如实说明"本轮未生成叙述性报告（中文原因）"，再展示
代码兜底的标题/摘要与计数汇总。

## 7. 四个出口（同一份 payload，只做呈现裁剪）

| 出口 | 入口 | 口径 |
|---|---|---|
| 平台页 | `platform.js` `#platformReport` 报告卡，数据来自 `GET /api/platform/reports?limit=1` | 徽章「巡检报告」+ title + summary + 分话题观察 + analysis 前 3 + risks + followups + meta 一行（计数 + as_of + 口径行「传播风险分级不判定真假；E 为代理估计值；巡检报告不做真假判断」）；`llm_status≠ok` 时叙事区整体不渲染并注明原因；加载失败与"没有报告"分开呈现（失败出失败行，没有则隐藏卡片） |
| CLI | `python -m mylocalai.platform --once`（`__main__._print_report`） | 计数行后出报告段：非 ok 先打「巡检报告：本轮未生成叙述性报告（{中文原因}），以下为代码汇总」，再依次 title/summary/topic_notes/analysis 前 3（带条目 id）/risks/followups；`--json` 路径不变（payload 原样进 summary） |
| REST | `GET /api/platform/reports?limit=10`（limit 夹取 1–50，返回 `{reports, external_authorized}`）；`GET /api/platform/reports/{scan_id}`（None → 404「巡检报告不存在: {id}」，否则 `{report, external_authorized}`） | 只读 `scan_reports`，不重组不改写；空库是合法输出（`reports=[]`） |
| 对话 | 助手工具 `platform_feed` `kind="report"`（`tools_platform._report_view`，10 键视图，零 LLM 只读）+ `cards.js renderPlatformReport` | 轻量卡：徽章 + title + summary + analysis 前 3 + meta（计数 + as_of + 口径行）；digest 带口径行「传播风险分级不判定真假；E 为代理估计值；巡检报告不做真假判断」；空库合法空卡 + 「暂无巡检报告（还没有生成过巡检简报数据）」；坏 store → 诚实降级（`ok=False` + `degraded=True`） |

另：`scheduler.status()` 的 `last_summary` 只带 `{"title", "llm_status"}` 两个标量
（payload 不背进状态响应，走 `/reports` 端点取）；无 report 键（早退路径/技能不可用）
时不加该键。

## 8. 与 research-digest 的分界

| | research-digest（资料收集 · 综述） | patrol-report（巡检报告） |
|---|---|---|
| 阶段 | **对话内**资料收集阶段（用户给主题 → 主动检索读页 → 综述） | **平台巡检**阶段（巡检跑完 → 收尾出一份报告） |
| 触发 | 用户消息经路由进 `collect_research` 工具 | runner `scan()` 收尾自动跑，无需用户触发 |
| 输入 | 本次授权检索渠道返回的来源正文 | 本轮巡检的代码汇总（零新检索） |
| 能力归属 | **十三项用户能力枚举**之一（information-collection，通用，全部角色） | **平台内部技能**，不占用户能力枚举、不进 `capabilities/`、不占 `router.TOOL_ACTIONS` |
| 出口 | 对话卡 + 叙述 | 平台页 / CLI / REST / `platform_feed kind="report"` 对话卡 |

两者的**代码校验器同口径**（真假判定词表逐字相同、白名单与截断思路一致），但
`platform/report/pipeline.py` 是**内嵌实现**——平台包不 import assistant（依赖方向
铁律：platform 只准被 assistant 消费，不准反向 import）。改校验口径时两处都要改，
并由各自测试锁定。

## 10. 已知局限与后续

1. **报告引用的 `entry_id` 可能随 results 保留期清理失效**：`analysis.entry_ids` 指向
   本轮落库的 `feed_entries.id`，而 `feed_entries.result_expires_at`（默认 90 天）到期后
   由 `purge_expired_feed()` 清理——清理后按 id 回查原条目会查不到，**报告文本仍然有效**
   （数字与叙述已冻结在 payload 里），只是"条目回溯"这一环断掉。报告自身不设保留期
   （与 scan_runs 同属巡检元数据），删 scan_runs 行会级联删掉挂在它上面的报告。
2. **一次 LLM 调用、一个截止面**：`report.max_llm_calls` 默认 1，模型一次组织不出
   全部字段时没有第二次机会——缺字段由代码兜底或留空，不用套话填满。
3. **`topic_stats` 的 E 是话题级代理值**：与巡检主流程同口径（整批共享一个 E），
   只适合同口径相对排序；环比为 0/暂实时如实写 0%/暂无，不猜趋势。
4. **平台页只取最近一份报告**（`limit=1`）：历史报告经 `GET /reports/{scan_id}` 按轮次取，
   平台页不做翻页（产品取向：打开页面看到"这一轮怎么样"就够）。
5. **报告不推送**：延续预警只在平台页内呈现的口径——打开页面才看到，不制造新压力。
6. **测试基线**：本轮新增用例全绿后由集成方统一跑全量套件与 CI（`scripts\ci.cmd`）；
   mock 闸门条数不随本轮变化。
