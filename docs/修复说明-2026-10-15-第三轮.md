# 修复说明（2026-10-15 · 第三轮）—— 档位角色真正随配置走

> 由**另一个会话**（19:00–20:15）继续完成，本文是该轮的工作记录。
> 起因：`docs/检验报告-2026-10-15.md` 的泛用性 ①（P1）只做了一半——"哪几档可靠/可抓/可扩链"
> 已经从 Python 挪进 `sources_registry.json`，但档名**字面量**还留在几处判定里，而且已回归的
> 常驻契约测试没测 `source_kind` 与排序。本文是那一半的收尾。

## 一、之前那半留下了什么

第二轮把 `RELIABLE_TIERS` / `FETCH_TIERS` / `LINK_TIERS` / `channel_score` 挪进 JSON，是对的；
但下面几处仍是旧写法，换行业重命名档位时依然会静默走错：

| 位置 | 原写法 | 问题 |
| --- | --- | --- |
| `sources.py::source_kind` | `if tier == TIER_OFFICIAL` / `if tier == TIER_MEDIA` / `if tier in (TIER_PORTAL, TIER_UGC)` | "官方"与"权威媒体"按固定字面量判，档位一改名，"官方（政府/权威机构）"就再也不会返回，新名单里的权威档只能落到"其他" |
| `search.py` 合并排序 | `{"官方权威": 0, "权威媒体/辟谣平台": 1}.get(r.domain_tier, 2)` | 排序优先级写死两个档名，新名单的档位全部并列在末尾 |
| `opinions.py` | `CHANNEL_SCORE.get("未知来源", 0.5)`、`best_tier = "未知来源"` | 用字面量当兜底键，档名变体下取不到正确权重 |
| `search.py::SearchResult` | `domain_tier: str = "未知来源"` | 同上 |
| `tests/test_stability_config.py` | 改名测试只断言 `RELIABLE/FETCH/LINK` 三套集合 | 没有覆盖 `source_kind`、也没有覆盖"同一域名在五个面上结论一致"，因此上面两处漏网 |

## 二、改动

1. **`rumor_agent/sources.py`**
   - 新增 `OFFICIAL_TIERS`（哪几档算官方，按档名从配置读）、`DECLARED_TIERS`（按 `tiers` 的
     **声明顺序**取档名）、`tier_rank()`（排序位次）。
   - 新增 `_resolve_roles(key, depth)` 统一解析四个角色集合：
     配置里列了档名 → 只认确实在 `tiers` 里声明过的那些（顺带把过时档名报成告警）；
     配置没写、或写的档名一个都不在名单里 → **按声明顺序取前 depth 档兜底**，并留告警。
     第 2 条兜底的意义：换行业时"名单换了、角色段忘了改"不会再退化成"哪个档都不可靠"。
   - `source_kind()` 改为 `tier in OFFICIAL_TIERS` / `tier in RELIABLE_TIERS`；
     "名单里认得但不是官方/权威媒体"统一判"非官方"（用"是否在声明里"判断，不再列举门户/UGC 档名）。
2. **`rumor_agent/search.py`**：合并排序改用 `tier_rank(r.domain_tier)`；`SearchResult.domain_tier`
   默认值改用 `TIER_UNKNOWN` 常量。
3. **`rumor_agent/opinions.py` / `evidence.py`**：兜底权重与未知档名、未知档位的展示兜底
   改用 `TIER_UNKNOWN` 常量（不再写中文字面量），与 `search.py` 对齐。
4. **`rumor_agent/sources_registry.json`**：补上 `official_tiers`（之前文档提到、JSON 里还没有），
   并把 `_tier_roles_comment` 写清"四项都可省略、省略时按声明顺序前 1/2/3/2 档兜底"。
5. **`rumor_agent/rules.py`**
   - `RUMOR_SOURCES_PATH` / `RUMOR_RULES_PATH` **按文档语义真正做成"整套替换"**：给了它就不再以
     内置默认为底稿。否则换行业的名单没写到的档位会从内置默认漏进来，出现"新档位认得了、旧档位
     还在"的混合名单。
   - 替换文件缺了哪些段会写进 `load_warnings()`（不静默）；`official_tiers` 纳入类型校验。
   - 坏配置/缺文件仍整段退回内置默认并报警（第二轮的行为不变）。

## 三、验证

新增/加强的常驻契约（都在 `tests/test_stability_config.py::TestConfigShapeContract`）：

- `test_tier_roles_are_configurable_by_name`：换一套**重命名档位**的名单后，逐域名核对
  **六个面**给出一致结论——`classify_domain` / `source_kind` / `OFFICIAL_TIERS` / `RELIABLE_TIERS` /
  `_FETCH_TIERS` / `LINK_TIERS`，并断言 `tier_rank` 与声明顺序一致、显式角色不产生兜底告警、
  伪装域 `nhc.gov.cn.evil.com` 六个面全部拒绝；用例结束先还原环境变量再重载模块（原写法会在进程里
  留下替换名单，把后续用例带偏——这是本轮实测到的真问题，已修）。
- `test_stale_role_names_fall_back_to_declaration_order`：名单已换成新档位、角色段还写着旧档名时，
  四个角色集合按声明顺序兜底且留告警，不得退化成空集。

`harness.py` 新增常驻闸门 **「档位角色随配置走」**（`contract` 模式采集、`digest` 汇总）：

- 子进程带一份重命名名单跑六个面，跨面比对同一域名的结论；判据不通过会列出具体哪一面不一致。
- **变异检查**（确认这条判据真能抓到旧 bug）：把角色集合改回"写死档名"的旧语义后，
  `nhc.gov.cn` / `dxy.cn` 的可靠档判定双双变假，闸门判红；不改则通过。

## 四、残留

1. **默认名单下先声明者优先**：`tier_rank` 用 `tiers` 的声明顺序，当前 JSON 里"官方权威"在
   "权威媒体/辟谣平台"之前，因此排序与原来一致。这是一条**默认约定**，不是写死的档名。
2. **`evidence.py` 里仍是 `domain_tier in RELIABLE_TIERS`**：它只引用集合、不引用档名，
   换行业自动跟着走，无需改动。
3. **计分权重、四档规则、枚举仍在外置计划外**（报告 ②，P1）：与 ① 同源但会牵动
   `core_judge` 与 `verdict` 两处等价性契约（现有 200/200 网格），仍留给单独一轮。
4. 本轮只改了库代码与测试/检验器；`docs/检验报告-2026-10-15.md` 的正文（含"发现 1 未修完"
   的表述）保持原样，由本文作为后续记录；报告结论与闸门计数以本文的 26/26 为准。
5. `tests/rumor_agent_e2e_results.json` 与 `_fault.json` 被本轮真实复跑刷新（跑前备份在
