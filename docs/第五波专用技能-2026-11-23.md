# 第五波专用技能 · 实施规格（2026-11-23）

> 状态：已实施（基线分支 `agent-claim-checking-v02`，代码在工作树、由集成方统一提交）。
> 本文是这三条新能力的**人读实施规格**：记录决策、三条流水线口径、预算/状态/失败矩阵、
> 测试矩阵与已知局限。体例沿《信息收集与权威核验技能-2026-11-20.md》。
> 范围：`statistical-claim-checking`（统计说法核查）、`dossier-comparison`（档案对比）、
> `event-timeline`（事件时间线）三条**专用只读对话能力**；不动既有十项能力的提示词、
> 状态、卡片与 REST 契约，也不动判定语义（`verdict.assess` / RumorAgent 引擎提示词）。
> 读者：项目作者、后续执行会话、评审者。
> 原则延续：**不判真假，只述证据**；**大模型不参与判定**；**每个出口都有降级**；
> 全离线可测（所有 IO 可注入，测试一律 stub，零网络零 LLM）。

## 1. 决策记录

| # | 决策 | 理由 |
|---|---|---|
| D1 | 三条候选（统计说法核查/档案对比/事件时间线）从《Skill分类与提示词规范-v1.0.md》§7「留扩展位」**落地为三条专用只读对话能力**，按角色绑定各归一个主角色，不并入既有能力 | 分类体系 §2 的既有承诺：claim-checking 要真实性判断与档案、authority-verification 是"多权威来源对主张"、information-collection 是"主动调研综述"。三条新需求分别是"核数字口径""比两份档案""按时间排事件"，硬塞进任一个都会破坏其现有契约 |

| D4 | 数值判定（抽取/归一/比对）与日期归一、引文锚定**全部由代码完成**，LLM 只做摘录结构化、段落定位、事件描述抽取 | 与既有铁律同口径：模型报的数字必须等于代码从同一摘录抽到的某一个；引文不逐字锚定即丢弃；模型越界产物整条丢弃，主结论不受影响 |

| D8 | 角色工具白名单按专用技能**分发到主角色**：`verify_claim`/`recheck_dossier`/`check_statistics` 仅 layperson+full，`compare_dossiers` 仅 analyst+full，`event_timeline` 仅 monitor+full——**analyst 与 monitor 不再同集** | 单条说法核查与统计说法核查是普通用户工作区的主责；档案对比是专业用户·材料分析的主责；事件时间线是专业用户·领域监测的主责。缺段/缺角色回落全局（fail-open）与 full 恒全量的既有口径不变 |

             未收到死线时按各自 rules.json 的 total_deadline_s 自建

           · 模型段：assistant_rules.json 的 statistics_model / timeline_model

           → 逐主张检索读页 → 代码口径比对 → 汇总）

           → 事件抽取 → 同源转载去重 → 排序汇总）
           └── 两条流水线共用 skills/collect_core.py（预算/六态/引文锚定/提示词装配/纯文本渲染）
        → skills/comparison/compare.py（compare_dossiers 纯函数，档案库直读派生）

- 三条都是**对话能力**（channel=对话），占路由枚举；材料分析/领域监测两个面板复合能力
  仍旧不占枚举（角色 Agent 工作流规格 §2）。
- 用户可见进度用中文阶段名，不暴露内部技能名：统计说法核查 = 解析输入/抽取数字主张/
  检索资料/阅读正文/口径比对/汇总输出；事件时间线 = 确定主题/检索来源/阅读抽取/整理时间线。
- 依赖方向不变：`assistant` 只准 import core/llm/retrieval/classic/rumor/attention/
  dossier/config/util，禁 import web；不 import platform。

## 3. 统计说法核查流水线（statistical-claim-checking）

**定位**：单源数字口径速查的用户能力（专用，主角色 layperson）。用户贴一段含数字的说法
（百分比/百分点/倍数/带单位绝对值/年份），助手逐条回答"这个数字与已读来源正文对得上吗"。

**六阶段（顺序锁定）**：

1. **预检**：非空与长度预检（≤4000 字，一次只查一段）；空/超长 → needs_clarification，不猜。
2. **抽取数字主张**：代码正则抽取（百分比/百分点/倍数/翻番/带单位绝对值/四位年份）；
   原文一个数字表达都没有 → `task_status=no_factual_claim` + completed（**合法空出口，不是失败**）；
   模型报的数字必须等于代码从同一摘录抽到的某一个，否则整条丢弃。
3. **逐主张检索**：每主张最多 2 个检索词（先 `strip_pii`，再剥 `site:` 等范围操作符）；
   检索受 `external_allowed("public-search")` 控制，未授权零外发。
4. **逐主张读页**：每主张最多 2 个页面；读页受 `external_allowed("public-web")` 控制；
   引文必须逐字定位已读正文，定位失败该条不比对。
5. **口径比对**：千分位剥离、小数精度、单位进率（万亿 1e12/亿 1e8/万 1e4）、约数容差
   （约/近/左右 ±10%；超过/以上/至少 → 来源不低于主张；不足/以下/以内 → 来源不高于主张；
   无约数表述 → 精确相等）；口径族（percent+percentage_point 同族、money、people、
   multiple、year、generic）同族异单位判"口径不一致"，跨族不作数值比对。**全部代码判定**。
6. **汇总**：代码模板即报告；可选一段受约束模型补充说明只许转述报告已有内容，
   新增判语/URL 或出现真假判定词即整段丢弃，报告退回纯模板。

**输出要点**：`text / state(ok|unclear|unreachable) / claims[] / limits[] / counts`；
`claims[] = {claim_id, excerpt, number, unit, metric, qualifiers, verdict, source_number,
source_url, source_title, quote, as_of, basis}`；`verdict` 四态
（consistent/inconsistent/caliber_mismatch/unverifiable）；
`counts = {claims, searches, pages, llm_calls}`（报告末尾如实输出执行次数）。

**相邻分工**：与权威核验（"多权威来源对主张"，看证据强弱）互不替代；要判断说法内容的
真假 → verify_claim / verify_authority；要主动调研主题 → collect_research；要评信源身份 →
check_source。

## 4. 档案对比（dossier-comparison）

**定位**：两份档案的只读对比能力（专用，主角色 analyst）。用户给两个档案号，助手把两侧
**已经记录下来的内容**摆在一起，**不重新核查任何东西**。

**口径（全部代码从档案库直读派生，模型不参与）**：

- **标签演进**（`conclusion_delta`）：取「左档案首版 → 右档案末版」为演进两端，陈述
  "标签从 X 变为 Y（as_of …）"；**不做升级/降级判断**。
- **置信度档位徽章**：两侧各带最新结论的置信度档位（高/中/低）与 as_of；缺结论为 null
  并写明"尚无结论"，**不编造**。
- **证据/信源差集**：证据按 url 去重后以左档案为基准列增/删（条目带 url/title/relation，
  relation 即库里的 stance 立场字段）；信源只列域名增/减，**不评任何域名的可信度**。
- **疑似同源徽章**：两条声明原文归一化后的指纹 Jaccard 达阈值（与谣言库指纹闸同值 0.72）
  只标「疑似同源」，**不断言**两侧是同一说法。
- **无分数**：输出没有任何数值评分字段；对话卡去数值（不出 risk_score，相似度数值只在
  数据层留档）。

**输入与拒绝**：两个正整数档案 id（`left_id`/`right_id`）。两个 id 相同或任一侧非正整数 →
诚实降级（`ok=False` + digest 说明要怎么改 + `invalid_params=True`，相同 id 时指路
`get_dossier` 看版本历史）——用户可修正的输入不摔成系统错误；档案不存在或属于别的工作区
→ 同形「档案 #N 不存在」（与 get_dossier 同一契约，不泄露别的工作区有哪些档案号）。

**相邻分工**：与事实核查（"一条说法进、结论出"）互不替代——本能力不核查任何新内容；
与信源可信度速查（给域名定性）分工——`source_diff` 只列域名增减；与材料分析（一批材料的
批量核查 + 跨条汇总）分工——本能力是两份档案的点对点对比。

## 5. 事件时间线流水线（event-timeline）

**定位**：把零散事件**按时间排开**的用户能力（专用，主角色 monitor），是领域监测工作区的
主责之一。用户给一个主题，助手从授权检索渠道找来源、逐页读正文，把"有来源记录的事件"
（日期 + 一句描述 + 逐字引文 + 来源 URL）按时间排成一条线。

**四阶段（顺序锁定）**：

1. **确定主题**：一个主题原文（≤200 字，一次只整理一个主题）；空/超长 → needs_clarification，
   请用户补一个具体主题，不猜。
2. **检索来源**：代码生成检索词 → 多查询检索 → URL 去重；读页域名允许集锁定为候选来源
   自己的域，重定向跳到别站一律拒绝——跳走了读的就不是检索返回的那个来源。
3. **阅读抽取**：逐页读正文，模型从已读正文抽"日期原样 + 一句事件描述 + 逐字引文"
   （一段只抽一条、单页最多 3 条）；引文逐字定位失败 → 整条丢弃并记 `limits`
   （`counts.dropped` 如实计数）。
4. **整理时间线**：日期归一全部由代码做（绝对日期归一成 ISO 片段；相对日期以本次运行
   as_of 归一并注精度 day|month|year；解析不出的按无日期处理，**绝不猜一个日期**）；
   无日期事件单独成 `undated` 区，不混主线、不参与排序与时间范围统计；同源转载去重
   （同一段逐字引文、或同域 + 标题近似只保留一条）；`range` 取有日期事件的首末，
   零事件时为空串，不编一个区间。

**输出要点**：`query / state(ok|unclear|search_unavailable|extract_unavailable|
page_unavailable) / events[] / undated[] / range / limits[] / counts`；
`events[] = {date, precision, event, source_url, source_title, quote, evidence_id}`；
`counts = {searches, pages, llm_calls, events, dropped}`。

**纪律（四条铁律）**：只述有来源记录的事件（不判真假、不外推趋势、不给数值分、不建档
不写库）；digest/report 禁真假判定词；检索范围如实标注（"仅本次授权检索渠道返回的公开
结果，不代表全网"）；不把降级说成完整成功。

## 6. 预算、状态与失败矩阵

- **预算外置**：三条流水线的全部上限都在各自 `rules.json`（改配置不改代码，写坏的值逐键
  回退默认或夹到安全区间，不让流程崩）：
  - `skills/statistics/rules.json`：输入长度 4000、主张数 5、总量检索 8/读页 8/模型调用 12、
    每主张 2 检索词 + 2 页面、总时长 90s、单次 IO 10s、页面字节与字符上限、重定向跳数、
    引文长度 300。
  - `skills/timeline/rules.json`：输入长度 200、事件条数 20、检索 6/读页 8/模型调用 10、
    总时长 90s、单次 IO 10s、页面字节与字符上限、重定向跳数、引文长度 300。
  - `skills/comparison/rules.json`：**只有呈现裁剪量**（版本历史 10/证据条目 20/域名清单 20）
    与相似度阈值 0.72——没有任何页数/时限键（零网络零模型）。
- **计数键**（max_searches / max_pages / max_llm_calls）由 `collect_core.CollectBudget`
  记账，报告末尾如实输出"已执行 N 次搜索、N 次读页、N 次模型调用"。
- **执行状态六态**：completed / partial / needs_clarification / failed / cancelled /
  budget_exhausted；**任务状态三态**：completed / no_factual_claim / needs_clarification。
  取消与预算耗尽优先判定且保留已取得结果；没有可核查的数字主张/没有可检索的主题不是失败。

| 触发条件 | 统计说法核查 | 档案对比 | 事件时间线 |
|---|---|---|---|
| 输入为空/超长 | needs_clarification | —（id 非法走 invalid_params） | needs_clarification |
| 原文没有数字表达 | no_factual_claim + completed（不检索不读页） | — | — |
| 两个 id 相同 / 非正整数 id | — | invalid_params 诚实降级（指路 get_dossier） | — |
| 档案不存在 / 跨工作区 | — | 同形 not_found（不建卡、不外泄别区档案号） | — |
| 外部检索未授权 / 后端全败 | failed（零外发，主张全部未核实到） | —（零网络） | failed（fail-closed，一次读页都不发起） |
| 读页失败 / 正文为空 / 定位失败 | partial（保留已取得的比对结果） | 单边读失败 → partial + gaps 明示 | partial（保留已取得的事件） |
| 模型结构化/定位/补充说明越界 | 丢弃该次模型产物，主结论不受影响 | —（无模型） | 整条丢弃记 limits；补充说明越界退纯模板 |
| 预算/死线到顶、用户取消 | budget_exhausted / cancelled（保留） | —（本地计算） | 保留已取得的事件 |
| 检索成功但零候选/零结果 | 主张保留"未核实到" | 缺章按 absent 处理，不编造 | completed + 缺口（合法空结果） |

## 8. 已知局限与后续

1. **统计口径族是封闭表**：percent+percentage_point 同族、money/people/multiple/year/
   generic；冷门口径（如"千分点""bps""基点"）未入表，会被判"未核实到"而不是硬换算——
   这是有意的保守取向，要扩口径先改口径族表再登记测试。
2. **档案对比只看已记录内容**：没跑过核查的一侧只能给出"尚无结论"，不能现查；要判断真假
   把说法交给核查流程。缺章是常态（懒加载），相似度在声明原文缺失时不可比。
3. **事件时间线只依据本次授权检索渠道**：报告如实标注"仅本次授权检索渠道返回的公开结果，
   不代表全网"；相对日期以本次运行 as_of 归一，跨会话复跑同一主题可能得到不同的归一结果。
4. **三条能力都不建档**：产物只在当次会话的卡片与报告里；想留档请走档案类能力
   （导出卡片/档案管理），本组能力不代为落库。
5. **专用工具按角色分发后的可达性**：monitor 工作区要对比档案需切到 analyst 或 full
   （产品决策，与材料批次/领域监测面板闸同一套角色口径）；analyst/monitor 不再同集。
6. **测试基线**：本轮新增 221 例全绿后由集成方统一跑全量套件与 CI（`scripts\ci.cmd`）；
   mock 闸门条数不随本轮变化（28 条口径不变）。
