# 信息收集与权威核验技能 · 实施规格（2026-11-20）

> 状态：已实施（分支 `feature/info-collection-skills`）。本文是这两条新能力的**人读实施
> 规格**：记录决策、流程、算法口径、状态/失败矩阵、测试矩阵与已知局限。
> 范围：`information-collection`（资料收集）与 `authority-verification`（权威核验）
> 两条只读对话能力；不动既有六项能力的提示词、状态、卡片与 REST 契约。
> 读者：项目作者、后续执行会话、评审者。
> 原则延续：**不判真假，只述证据**；**大模型不参与判定**；**每个出口都有降级**；
> 全离线可测（所有 IO 可注入，测试一律 stub，零网络零 LLM）。

---

## 1. 决策记录

| # | 决策 | 理由 |
|---|---|---|
| D1 | 新增两个**只读对话能力**，不并入既有能力 | 既有能力各有明确承诺：claim-checking 要真实性判断与档案；evidence-research 只查目录内官方资料且逐主张对证据。新需求是"给主题主动调研"与"给说法找权威资料"，硬塞进任一个都会破坏其现有契约 |
| D2 | 两能力均 **permission=read、不建档、不出真假结论、不给数值评分** | 产品规则：不扩权。返回 `dossier_id=None` + `not_saved=True` + `save_reason=read_only_capability_no_dossier`；卡片不出现 score/confidence 类字段 |
| D3 | 判定全部由代码：来源类别、动态权威信号、balance/lean、conclusion、状态、预算 | LLM 只做拆解、选源建议、摘录、受约束分析；模型不得改 conclusion，不得新增 URL/日期/证据 ID |
| D4 | **动态权威发现开放**（用户已选），但只按代码信号、只对可动态核验类别、有候选数上限 | "身份不能自封"：页面自称权威、模型说"匹配"、域名好看都不算信号 |
| D5 | **"1+3"输出口径** | 权威证据充分才允许"可以证明/直接反驳"；否则只能说"不能据此证明/反驳"或"没有找到"；永不给固定真假标签 |
| D6 | 与材料分析/领域监测**分流不拼工具** | 多条材料批量核查 → analyst 材料批次面板；订阅领域持续监测 → monitor 领域监测面板；对话里一句话导流（规格 §1.3） |
| D7 | 机器契约唯一来源 = `assistant.registry` 注册表 + 两套 pipeline + 各自 `rules.json` / `authorities.json` | 能力 SKILL.md 与本文只写人读策略，不复制可执行细节（规格 §2 防双维护） |

## 2. 总架构

```
用户消息 → router（TOOL_ACTIONS 追加 collect_research / verify_authority）
        → loop._real_service 工厂（research_skills / authority_skills）
           · 死线：llm_cache.deadline_at() 与流水线自建死线取更紧者
           · 外发授权门：public-search / public-web（core/privacy.py，fail-closed）
           · 模型段：assistant_rules.json 的 research_model / authority_model
        → skills/research/pipeline.py（ResearchSkills.run）
        → skills/authority/pipeline.py（AuthoritySkills.run）
           └── 共用 skills/collect_core.py（预算/状态/来源分类/动态信号/去重/引文锚定/提示词装配/纯文本渲染）
        → tools_research / tools_authority（卡片 + digest + 只读元数据，永不抛）
        → cards.js renderResearch / renderAuthority（徽章/分级/折叠，无数值展示）
```

- `collect_core` 是共享底座：两套流水线只做编排，不各写一份预算/状态/来源判定。
- 用户可见进度用中文阶段名，不暴露内部技能名：资料收集 = 确定范围/检索资料/阅读摘录/
  整理简报；权威核验 = 拆分主张/核验权威来源/阅读取证/整理分析。
- 依赖方向不变：`assistant` 只准 import core/llm/retrieval/classic/rumor/attention/
  dossier/config/util，禁 import web；不 import platform。

## 3. 资料收集流水线（information-collection）

**四阶段（顺序锁定）**：

1. **确定范围**（`research/scope/SKILL.md`）：LLM 输出范围状态、一句研究问题、
   `scope_basis`（必须是用户主题里的逐字片段）、时间/地域、1-N 个可检索子问题。
   `scope_basis` 定位不到 → 先问再查；`too_broad`/`unclear` → needs_clarification，
   给确定性收窄建议，**不检索**。
2. **检索资料**：代码为每个子问题生成检索词（先 `strip_pii`，再剥 `site:` 等范围操作符）
   → 多查询检索 → URL 去重 → 按来源等级排序 → 逐候选读页（每域页数 + 总页数双上限）。
   检索全部不可用/降级 → failed（不把"没搜"说成"搜过了没找到"）。
3. **阅读摘录**（`research/digest/SKILL.md`）：逐页抽 1-3 条引文，引文必须
   `anchor_quote` 逐字定位已读正文，失败即丢弃并记 error；正文哈希 + 引文归一化去重，
   转载只记局限。
4. **整理简报**：LLM 基于证据清单出关键发现/线索/时间线/分歧/分析；代码按白名单校验
   evidence_ids、定支撑等级（authoritative/reliable），只引用未核验证据的发现**降级为
   线索**；缺口存在且预算允许时补检索一轮。

**输出要点**：`scope / sub_questions / key_findings / leads / evidence / sources /
timeline / conflicts / analysis / counts`；卡片另带 `followups`（确定性派生的下一步建议）。
**状态口径**：未授权/检索全败/阶段一模型不可用 → failed；读页/摘录/综述失败 → partial；
预算/取消保留；主题过宽或范围依据未锚定 → needs_clarification；检索成功但无可定位引文
→ completed + 缺口（合法空结果）。

## 4. 权威核验流水线（authority-verification）

**五阶段（顺序锁定）**：

1. **预检与原文读入**：非空与长度预检；纯链接输入安全抓取该页作为**待核验原文**，
   来源一律记"用户提供链接，未核验"——不作证据、不回头给自己作证。
2. **拆分主张**（复用 `skills/evidence/SKILL.md`）：主张 text 必须逐字定位原文；
   无 checkable 主张 → `task_status=no_factual_claim` + status=completed（合法空出口）；
   超过主张上限 → 保留前 N 条 + needs_clarification（请用户指定先核哪条）。
3. **权威源发现**（`authority/authority/SKILL.md`，全部代码判定，见 §5）：候选分类 →
   目录锚点直接采信；目录外只对可动态核验类别尝试动态核验；未核验候选仍进 sources
   列表作线索，但绝不进决定性证据；已核验页面正文里**由代码抽链**可把候选升级为
   `verified_site_link`；按核验硬度排序后受权威来源数上限约束。
4. **阅读取证**：`site:` 由代码拼接；每主张查询/读页有上限；引文必须逐字定位已读正文；
   relation 取封闭枚举（supports/refutes/partial/background/unclear，后三者只作背景）。
5. **整理分析**：代码按决策表算 balance/lean，按模板逐字生成 conclusion；LLM 写受约束
   分析（`authority/adjudicate/SKILL.md`），只能引用已存在的 evidence_id，新增 URL/
   日期/证据 ID、出现真假判定词一律丢弃记 error；最后去重 + 确定性报告。

**balance/lean 决策表（纯函数，代码）**：

| 条件 | balance | lean |
|---|---|---|
| 决定性 supports 存在、无决定性 refutes | supported | supports |
| 决定性 refutes 存在、无决定性 supports | refuted | refutes |
| 决定性 supports 与 refutes 同时存在 | contested | mixed |
| 无决定性证据；可靠证据 supports 且无 refutes | insufficient | supports |
| 无决定性证据；可靠证据 refutes 且无 supports | insufficient | refutes |
| 无决定性证据；可靠证据既有 supports 又有 refutes | insufficient | mixed |
| 无可靠证据/无证据 | insufficient | none |
| claim_status=not_checkable | not_checkable | none |

**conclusion 模板口径（代码逐字生成，LLM 无权改动）**：supported/refuted 形如
"在{scope}范围内，权威资料可以证明/可以直接反驳该说法：{摘要}。"（scope 取原文限定，
缺失写"可核查"；摘要取最高等级证据的标题或引文前 80 字，代码裁剪）；contested 为
"权威资料之间存在直接冲突，目前既不能证明也不能反驳。"；insufficient 四种分别为
"现有可靠证据倾向支持/反驳，但缺少权威确认，不能据此证明/反驳"、"现有可靠证据互相矛盾，
不能证明或反驳"、"没有找到能证明或反驳该说法的权威资料。"；not_checkable 为
"这不是可核查的事实主张，不做证据倾向判断。"。

**"1+3"输出口径**：允许说"证明/反驳"的充分条件 = 有**决定性来源**的支持/反驳证据；
其余一律"不能据此证明/反驳"或"没有找到"；lean 只作倾向展示，不能单独升级。

## 5. 动态权威发现算法（§4 阶段 3 的口径展开）

1. **候选来源**：只来自本次检索结果；目录命中（`skills/sources.json` 锚点域名）→
   `catalog_anchor`，直接采信。
2. **类别封闭枚举**：official / international_org / academic / standards / factcheck /
   media / unverified；**决定性类别只有前五类**（`authorities.json.decisive_classes`），
   媒体只作倾向，未核验不作决定性证据。类别按域名档位 + 类别覆盖表由代码判定。
3. **可动态核验类别 = 决定性类别 − 媒体类**；未核验类连尝试资格都没有。
4. **代码信号（至少 2 个才记 `session_verified`，缺一即 unverified）**：
   - `official_suffix`：域名后缀命中官方后缀表（gov.cn / gov / mil.cn）；
   - `official_marker`：**已读正文**命中官方标记（政府网站标识码/网站标识码/主办单位/
     公网安备/ICP备）；
   - `inbound_link`：已核验页面正文里由代码抽出的、指向该域名的直链；
   - `cross_mention`：≥2 个独立已核验来源的正文同时提到该域名/机构。
5. **单点不决定性**：动态核验来源要作决定性证据，还需 ≥1 个独立已核验来源交叉佐证，
   或存在 ≥2 个独立动态来源互为佐证；只有信号没有佐证 → 只作倾向。
6. **会话内有效**：`session_verified` 不写回信源目录，下次运行重新核验。
7. **不算信号的**：页面自称权威、模型说"匹配"、域名好看、搜索摘要里出现的域名。
8. **候选数上限**：单次运行动态候选数受 `max_dynamic_domains` 约束，身份核验不烧取证预算。
9. **域名边界匹配**：按域名边界后缀最长命中，`xinhuanet.com.evil.com` 这类伪装不当新华网。
10. **伪造站点测试口径**：`.gov.cn` 后缀但正文无官方标记 → unverified；非官方后缀但正文
    有官方标记 → unverified；通篇自称"权威发布" → unverified。

## 6. 预算、状态与失败矩阵

- **预算外置**：两套流水线的全部上限（输入长度、子问题/主张数、来源数、候选数、搜索/
  读页/模型调用次数、每主张查询与读页、总时长、单次 IO 超时、页面字节与字符上限、
  重定向跳数、引文长度、动态候选数与信号下限）都在各自 `rules.json`；类别覆盖、决定性
  类别、官方后缀/标记、动态开关在 `authority/authorities.json`。改配置不改代码；
  写坏的值逐键回退默认或夹到安全区间，不让流程崩。
- **计数键**（max_searches / max_pages / max_llm_calls）由 `collect_core.CollectBudget`
  记账，报告末尾如实输出"已执行 N 次搜索、N 次读页、N 次模型调用"。
- **执行状态六态**：completed / partial / needs_clarification / failed / cancelled /
  budget_exhausted；**任务状态三态**：completed / no_factual_claim / needs_clarification。
  取消与预算耗尽优先判定且保留已取得结果；没有可核查主张不是失败。

| 触发条件 | 资料收集 | 权威核验 |
|---|---|---|
| 输入为空/超长 | needs_clarification | needs_clarification |
| 主题过宽 / 范围依据未锚定 | needs_clarification（不检索） | — |
| 主张数超上限 | — | needs_clarification（保留前 N 条） |
| 外部检索未授权 / 后端全败 | failed | failed |
| 阶段一（范围/拆主张）模型不可用 | failed | failed |
| 读页/引文/综述(分析)失败 | partial（保留摘录） | partial（balance 照常，缺分析） |
| 预算/死线到顶、用户取消 | budget_exhausted / cancelled（保留） | 同左 |
| 无 checkable 主张 | — | no_factual_claim + completed |
| 检索成功但无资料/无决定性证据 | completed + 缺口 | insufficient + completed |
| 纯链接读取失败 | — | 按链接本身作原文 + 缺口 |

卡片与报告不得出现 score/confidence 类数值。

## 8. 已知局限与后续

1. **动态核验只在本会话有效**：`session_verified` 不写回信源目录，重复主题每次重新核验；
   长期运行后是否把"多次独立会话都通过信号"的域名沉淀为目录锚点，留待产品决策。
2. **媒体类永不作决定性证据**：高利害领域的权威媒体报道也只给倾向——这是写死的口径，
   不因话题重要性放宽；需要"媒体佐证 + 权威确认"的两段式呈现时，由用户在两者间自行权衡。
3. **conclusion 摘要取标题或引文前 80 字**：极端情况下摘要可能丢掉关键限定，
   完整上下文以卡片里的逐字引文与来源链接为准。
4. **检索后端降级即失败**：引擎全败时判 failed 而不是"没找到"，用户看到的是"没有检索
   依据"，需要重试或检查授权。
5. **主张/子问题上限内**：超出上限先问再查，不擅自挑选；一次核多条说法请分批或用材料
   分析面板。
6. **测试基线**：本轮以既有 1410 用例（skipped=3）为基线，新增用例全绿后由集成方统一
   跑全量套件与 CI。

## 9. 机器契约唯一来源

- 工具注册（名称/参数/权限/成本/est_s/描述/校验）：`assistant/registry.py` 注册表；
- 路由枚举与放行：`assistant/router.py` 的 `TOOL_ACTIONS` + `assistant_rules.json`
  的 `tool_allowlist`；模型段 `research_model` / `authority_model` 同文件；
- 流水线契约（输入/输出/阶段/状态/决策表/模板）：`skills/research/pipeline.py`、
  `skills/authority/pipeline.py`，共享口径 `skills/collect_core.py`；
- 预算与开关：`skills/research/rules.json`、`skills/authority/rules.json`、
  `skills/authority/authorities.json`；
- 阶段提示词：`skills/research/{scope,digest}/SKILL.md`、
  `skills/authority/{authority,adjudicate}/SKILL.md`；
- 人读能力策略：`capabilities/information_collection/SKILL.md`、
  `capabilities/authority_verification/SKILL.md`。

本文与两份能力 SKILL.md 均**不复制**上述可执行细节；发现不一致时以上述来源为准，
并回头修正文档。
