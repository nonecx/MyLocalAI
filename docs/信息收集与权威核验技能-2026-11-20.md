# 信息收集与权威核验技能实施规格（2026-11-20）

> 状态：**已实现**（`feature/info-collection-skills-v2`；资料收集 40 例、权威核验 53 例、
> 共享底座/Agent 循环/工具/设置/UI 等另有覆盖，全量离线套件 1662 例）。
> 读者：项目作者、后续执行会话。
> 机器可执行契约的唯一规范来源：`assistant.registry` 注册表 +
> `assistant/skills/research/pipeline.py` / `assistant/skills/authority/pipeline.py`；
> 本文只做人读口径，不复制可执行细节。

---

## 1. 定位与边界

在既有八类用户能力（四类基础 + material_analysis/domain_monitoring + 本次两类）之上新增：

| 能力 ID | 工具 | 用户目标 | 边界 |
|---|---|---|---|
| `information-collection` | `collect_research` | 按主题主动收集/整理/调研公开资料 | 只读、不建档；不判真假；未核验来源只能作线索 |
| `authority-verification` | `verify_authority` | 找权威资料证明/反驳用户说法并分析 | 只读、不建档；无决定性证据不得写“证明/反驳”；无真假标签/数值分 |
| `collect-and-verify` | `collect_and_verify` | 一句话同时收集资料 + 核验某说法 | 已登记复合形态；两段互不吞并；失败不自动换能力 |

三个工具都是 `permission="read"`、`cost="heavy"`；结果只随会话卡片存在，不写档案、不写回
信源目录、不做后台定时收集（后台监控走独立的监测平台能力）。

## 2. Agent 调用流程

### 2.1 首轮

```text
用户消息
→ pre_refuse（拒绝词表）
→ route LLM（带最近档案卡 + 最近一张 research/authority/composite 卡摘要）
→ action ∈ {collect_research, verify_authority, collect_and_verify, ...}
→ 工具 handler
   → 读 skills_preferences（本技能 mode + 协同开关）
   → 若追问：从本会话最近卡片找 prior（composite 取对应子卡）
   → 跑 pipeline（pipeline / agent 模式）
   → 若 collect_research 且 auto_verify_findings 开启：
        只取 key_findings 里带 source_quote 的 1-2 条直接引文 → 跑权威核验 → composite 卡
   → card / digest / status
→ card（先）→ narrative（后）→ tool_end → done
```

- 路由拿不准 → `clarify`，不自由拼工具；用户明确拒绝词表 → `refuse`。
- `collect_and_verify(topic, claim)`：先研究、再核验，**内部顺序执行**；任一失败保留另一段；
  只产一张 `composite` 卡。
- 无 `public-search`/`public-web` 授权 → `failed` + 明确指引，零外发，不伪装空结果。

### 2.2 追问

```text
“补充/再深一点/换个角度/只看反驳/第二条再查”
→ 找同会话上一张同类型卡（composite 取子卡）
→ 只跑缺口/新增部分；旧 evidence_id 保留并合并
→ 新卡 incremental=true、base_as_of=旧卡 as_of
→ “重新查/换主题” → followup=false，完整重跑
```

- `loop` 给工具 ctx 提供 `session_id` 与 `user_text`；工具从 `kind="card"` 消息里找 prior。
- 结果保存关闭时卡片内容为空串（SessionStore 隐私策略）→ 找不到 prior，工具必须如实说明
  “上一张卡不可用”，请用户重述或完整重跑，不能假装记得。

## 3. 两种工作流模式（设置页“技能”）

### 3.1 固定流水线（`pipeline`，默认）

| 能力 | 固定阶段 |
|---|---|
| 资料收集 | 预检 → 范围/子问题 → 检索/去重 → 按来源等级读页 → 逐页摘录/锚定 → 综述（引用已存在 evidence_id）→ 报告/卡 |
| 权威核验 | 预检/纯链接抓取 → 拆主张 → 权威源发现（目录 + 动态核验）→ 逐主张检索/读页/摘录 → 代码算 balance/lean → 受约束分析 → 报告/卡 |

模型不能增删阶段；每阶段有预算与死线；失败保留已完成阶段。

### 3.2 受限 Agent 循环（`agent`）

允许动作（封闭枚举）：

- `search(query)`：查询过 `strip_pii` + 操作符剥离；结果进入候选池。
- `read(url)`：URL 必须在候选池；经 `SafeTransport`；研究允许开放候选，权威只允许权威候选。
- `extract(quote, claim_id|sq_id, relation/role)`：引文必须锚定已读正文；否则拒绝。
- `finish(summary)`：结束；代码检查覆盖度，不足记 gap/partial。

硬约束：`max_steps`、搜索/读页/LLM/死线/取消全部沿用 rules；重复动作、非法动作、候选池外
URL 直接拒绝；连续 3 次非法 → 停止并 `partial`。模型只能决定“下一步做什么”，不能改
`status/task_status/balance/lean`、不能写数值分、不能新增未读 URL、不能把未锚定引文当证据。
两种模式产出**同一卡 schema**；卡上 `execution.mode/steps/stop_reason` 如实展示。

设置：`data/skills_preferences.json`（环境变量 `MYLOCALAI_SKILLS_PREFERENCES_PATH` 可覆盖），
`GET/PUT /api/skills/preferences`（全量校验，非法 400）。两个技能分别选模式；`composite.enabled`
控制复合能力；`research.auto_verify_findings` 控制研究后自动核验（复合关闭时强制关闭）。

## 4. 资料收集

### 4.1 流程

预检（非空、≤`max_input_chars`、授权）→ 范围/子问题（LLM，≤4，`scope_basis` 必须逐字来自
用户输入）→ 代码生成检索词（剥 PII/操作符）→ 多查询检索 → URL + 标题近似去重 → 按来源
等级与相关度读页（每域≤2）→ LLM 逐页摘录（`quote` 必须逐字锚定已读正文）→ 综述（每条发现
必须引用已存在 evidence_id）→ 确定性报告 + 卡；预算允许时 1 轮补检索。

### 4.2 来源等级

- `authoritative`：目录锚点、已核验站点直链、会话内动态核验通过；
- `reliable`：目录内权威媒体/一般可靠媒体；
- `unverified`：陌生域名，只能进“线索（未核验）”，不得进“关键发现”。

### 4.3 卡字段

`topic / scope / sub_questions / key_findings / leads / evidence / sources{verified,unverified} /
timeline / conflicts / analysis / followups` + 工具层补 `status/task_status/as_of/degraded/
execution/incremental/base_as_of/gaps/errors/counts`。

硬门禁：`key_findings` 每条至少 1 个 evidence_id；`source_quote` 必须是所引 evidence 的 quote
之一；引文未锚定即丢弃并记 error；未核验来源不能支撑关键发现；不输出真假判定词/数值分。

## 5. 权威核验

### 5.1 流程

预检（非空、≤4000 字；纯链接先安全抓取并标“用户提供链接，未核验”）→ 拆主张（复用
`skills/evidence/SKILL.md` 指令；`text` 逐字定位原文；无 checkable → `no_factual_claim`）→
权威源发现（目录 + 动态核验）→ 逐主张 `site:`/组合检索、读正文、抽引文与 `relation ∈
supports|refutes|partial|background|unclear`（引文必须锚定）→ 代码算 `balance/lean` →
LLM 受约束分析（只能引用已存在 evidence_id）→ 报告/卡。

### 5.2 权威类别与动态核验

| 类别 | 例子 | 可否决定性 |
|---|---|---|
| `official` | 政府/部委/官方辟谣平台 | 可（目录锚点或会话核验） |
| `international_org` | WHO 等 | 可（目录） |
| `academic` / `standards` | 中科院、Nature、标准机构 | 可（目录/核验） |
| `factcheck` | 联合辟谣平台等 | 可（目录） |
| `media` | 新华网/央视等 | **不可单独定论**，只作可靠倾向 |
| `unverified` | 陌生域名 | 不可，只能作线索 |

动态权威：目录外仅对官方/标准/事实核查类尝试；代码信号至少 2 个（`official_suffix` /
`official_marker` / `inbound_link` / `cross_mention`），结果仅会话内 `session_verified`，不写回
目录；作决定性还需 ≥1 个独立已核验来源交叉佐证（或 2 个独立动态来源）。页面自称权威、模型说
“匹配”、域名好看都不单独构成信号。

### 5.3 证据倾向与结论模板

`balance ∈ supported|refuted|contested|insufficient|not_checkable`（只由决定性证据决定）；
`lean ∈ supports|refutes|mixed|none`（全部可靠证据的倾向）。结论由代码模板逐字生成：

- supported：“在{scope}范围内，权威资料可以证明该说法：{摘要}。”
- refuted：“在{scope}范围内，权威资料可以直接反驳该说法：{摘要}。”
- contested：“权威资料之间存在直接冲突，目前既不能证明也不能反驳。”
- insufficient+lean：“现有可靠证据倾向{支持/反驳}，但缺少权威确认，不能据此证明或反驳。”
- insufficient+none：“没有找到能证明或反驳该说法的权威资料（或可靠证据互相矛盾）。”
- not_checkable：“这不是可核查的事实主张，不做证据倾向判断。”

LLM 只能写 `analysis`，不得改结论/状态；卡不显示数值分；高利害领域（公共卫生/财经/政策法规）
决定性只认官方/国际/学术/事实核查。

### 5.4 卡字段

`claims[{claim_id,text,origin,claim_status,balance,balance_label,lean,lean_label,conclusion,
supporting_ids,refuting_ids,context_ids,authority_basis,limitations}]`、`evidence[{...authority_class,
verification,authority_basis,quote,...}]`、`sources{verified,unverified}`、`conflicts`、`analysis`、
`limitations` + 工具层补 `status/task_status/as_of/degraded/execution/incremental/base_as_of/
gaps/errors/counts`。

## 6. 自动接力与复合

### 6.1 显式复合 `collect_and_verify`

一句话同时有“收集/整理某主题资料”和“核实/证明/反驳某说法”时触发；缺主题或缺说法 → clarify。
研究段强制不做自动接力（避免二次核验），权威段用用户 claim；两段独立执行、状态聚合：
两段 completed → completed；一段 partial/failed、另一段有产物 → partial；两段 failed → failed。
复合卡：`card_type="composite"`, `kind="research_authority"`, `research`, `authority`, `summary`,
`gaps`, `errors`, `counts`, `as_of`。

### 6.2 研究后自动核验

只对 `key_findings` 中带 `source_quote`、`support_level ∈ authoritative|reliable` 的 1-2 条执行；
传给权威核验的是**引文原文**，标 `origin="auto_from_research"`，卡上写“由资料收集的直接引文
自动核验，非用户原话”。无可核验引文 → 只出 research 卡 + `handoff_skipped` 原因；权威段失败 →
composite partial，研究卡照发，不自动改走别的能力。

## 7. 预算、状态与失败矩阵

| 项 | 资料收集 | 权威核验 |
|---|---:|---:|
| 单跑死线 | 90s | 90s |
| 复合总死线 | 150s（按剩余预算分配） | 同左 |
| Agent 步数 | 12 | 16 |
| 搜索/读页/LLM | 10/10/16 | 12/12/20 |
| 动态权威 | — | `dynamic_enabled=true`、`min_signals=2`、`max_domains=4` |

状态沿用六态 + 三任务态：`needs_clarification`（主题过宽/太短）、`failed`（授权拒绝/检索全败/
范围或拆主张 LLM 不可用）、`partial`（部分读页/引文丢弃/后续 LLM 不可用）、`budget_exhausted`/
`cancelled`（保留结果）、`no_factual_claim`（无 checkable，不是失败）。零结果：研究 completed+
gaps；权威 insufficient，均不是失败。

失败矩阵：授权拒绝零网络；单次 IO 失败继续并记 error/gap；引文未锚定丢弃；动态信号不足/单点
伪造不决定性；注入页文本只作引文不改状态；纯链接抓取失败不猜；预算/取消保留。

- 共享底座 37 例、Agent 循环 37 例、工具/复合 16 例、真实 pipeline→卡 3 例、偏好/追问 27 例、
  设置 API/UI 17 例、三卡 UI 49 例；全量离线套件 1662 例（README 守护数）。
- 验收口径：全量 `unittest discover` 绿；`scripts\ci.cmd` 绿（mock 闸门缺失如实 SKIP）；
  页面/静态资源冒烟；`GET/PUT /api/skills/preferences` 正常；三卡历史回放正常。

已知局限：动态权威仍可能被高仿站点欺骗（信号+佐证+会话内+可配置关闭）；不解析 PDF/JS/付费墙；
综述是 LLM 组织，代码只保证引用存在与引文锚定；权威结论是证据倾向而非法律/医学/金融定论；
预算有限时明确报缺口；两能力不建档、不后台、不写回目录。
