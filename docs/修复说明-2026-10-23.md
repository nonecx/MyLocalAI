## 二、行为变化（需要知道的）

1. **单次全链路更快**：三个模块从串行改为并行，真实上游实测 **17.36s → 10.65s**（约 -39%）。
2. **空输入彻底零开销**：`judge("")` 实测 **4.27s → 0ms**。
3. **配置多了一处入口**：提供方表（`shared_core/providers.json`）、提示词（`rumor_agent/prompts.json`）、言论分层阈值（`verdict_rules.json` 的 `speech_tier` 段）都可以改文件而不改 Python。
4. **言论分层只有一处实现**：`core_judge` 与 `verdict.speech_tier` 共用 `rumor_agent/tiering.py`；阈值改了两者一起变（此前各写一遍 if-else）。
5. **经典链路新增两个依赖**：`core_judge` 现在 import `rumor_agent.tiering`（只带 stdlib，不带 langchain——`rumor_agent/__init__.py` 是延迟导入）。
6. **`requirements.txt` 现在包含网站依赖**（fastapi/uvicorn），`my_website/requirements.txt` 改为引用根文件；`pip install -r requirements.txt` 一次装全。
7. **`/api/health` 的 `llm_cache` 多了 `instance` 字段**；classic/agent 记录多了 `cache_hits` / `cache_instance` / 三维字段（均为新增，向后兼容）。
8. **Agent 的 LLM 超时/重试口径与 classic 统一**（30s / 1，可用 `LLM_TIMEOUT_S` / `LLM_MAX_RETRIES` 覆盖）。
