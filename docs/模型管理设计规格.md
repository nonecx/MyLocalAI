# 模型管理设计规格（2026-11-19）

> 本文件是「网站设置面板 · 模型管理」并行开发的**唯一事实来源**。任何实现与本文冲突，
> 以本文为准；确需变更，先改本文再改代码，并在最终答复里说明。
>
> 目标（用户原话）：图片一（本站对话单页）里没有**添加和设置模型**的功能，
> 要像图片二那样能添加提供方（Provider ID / 显示名称 / API 地址 / API 协议 / API 密钥），
> 并且能**获取可用模型**、像图片三那样对**单个模型**做设置
> （上下文窗口、最大输出 token 数、输入类型、推理等级档位与 API 参数值、恢复默认、删除）。

---

## 0. 不变量（谁都不能破坏）

1. **不落敏、不外泄**：API 密钥只写本地文件，**任何 GET 响应、日志、页面都不出现明文密钥**，
   只回 `api_key_set` / `api_key_source` / `api_key_masked`（形如 `sk-…4f2a`）。
2. **fail-closed 外发授权**：`/discover`（获取可用模型）会真的发一次 HTTP 到提供方，
   因此**必须先过 `mylocalai.core.privacy`**：
   `load_preferences().require_provider(provider, base_url)`；被拒 → **HTTP 403**，不发请求。
   `localhost/127.0.0.1/::1` 视为本地、自动放行（沿用既有口径）。
3. **fail-soft 配置**：`data/models.json` 缺失/损坏/版本不符时**退回内置提供方表**并留告警，
   绝不抛异常拖垮分析链路；损坏文件**不被静默覆盖**（只有用户显式保存时才写）。
4. **默认行为零变化**：没有 `data/models.json` 时，`llm_client` 的
   provider / base_url / model / 缓存键**与改动前逐字节一致**
   （`tests/test_llm_gateway.py` 的金样本键必须继续通过）。
5. **内置提供方不可删**：来自 `providers.json` 的 longcat / deepseek / openai 可以改、可以选，
   但不能被删除（`DELETE` → 400）。
6. 全中文注释与用户可见文案；错误信息说清"哪一步、为什么、怎么办"。

## 1. 存储

| 用途 | 默认路径 | 环境变量覆盖 | 入库 |
| --- | --- | --- | --- |
| 模型/提供方配置 | `<repo>/data/models.json` | `MYLOCALAI_MODELS_PATH` | 否（`data/` 已 .gitignore） |
| 密钥 | `<repo>/data/model_secrets.json` | `MYLOCALAI_MODEL_SECRETS_PATH` | 否 |

写入一律**原子**（同目录 `mkstemp` → `fsync` → `os.replace`），密钥文件权限尽力收紧到
`0o600`（Windows 上失败不报错，只忽略）。

### 1.1 `data/models.json` schema（`schema_version = 1`）

```json
{
  "schema_version": 1,
  "active": { "provider": "deepseek", "model": "deepseek-chat" },
  "providers": {
    "deepseek": {
      "display_name": "DeepSeek",
      "base_url": "https://api.deepseek.com/v1",
      "protocol": "openai",
      "key_env": "DEEPSEEK_API_KEY",
      "enabled": true,
      "models": [
        {
          "id": "deepseek-chat",
          "display_name": "deepseek-chat",
          "context_window": 65536,
          "max_output_tokens": 8192,
          "input_types": ["text"],
          "enabled": true,
          "reasoning": {
            "enabled": false,
            "param": "reasoning_effort",
            "active_tier": "off",
            "tiers": [
              { "tier": "off", "api_value": null },
              { "tier": "low", "api_value": "low" }
            ]
          }
        }
      ]
    }
  }
}
```

### 1.2 `data/model_secrets.json` schema

```json
{ "schema_version": 1, "secrets": { "deepseek": "sk-..." } }
```

`data/models.json` 里**只存 `key_env` 的名字**，不存密钥值。密钥来源优先级：
`key_env` 环境变量 → `model_secrets.json` → 无（`key_source = "none"`）。

## 2. Python 模块：`mylocalai.llm.model_registry`

新增文件 `src/mylocalai/llm/model_registry.py`。**所有函数不抛异常**（除签名标注 `raises` 的
写入函数在参数非法时抛 `ValueError`），坏配置一律 fail-soft + 告警。

```python
SCHEMA_VERSION = 1
PROTOCOLS = ("openai", "anthropic", "gemini")          # 仅 openai 运行期可执行
RUNTIME_PROTOCOLS = ("openai",)
INPUT_TYPES = ("text", "image")
REASONING_TIERS = ("off", "low", "medium", "high")     # 档位阶梯（UI 下拉用）
DEFAULT_REASONING_PARAM = "reasoning_effort"

class ModelRegistryError(ValueError): ...              # 参数/结构非法

def registry_path() -> Path: ...                       # 见 §1 表
def secrets_path() -> Path: ...
def reset_cache() -> None: ...                         # 清进程内缓存（测试与写入后调用）
def warnings() -> list[str]: ...                       # 加载期告警（空 = 正常）

def view() -> dict: ...            # 见 §3.1，密钥已掩码；含内置提供方与 default_models
def provider_view(pid: str) -> dict | None: ...
def default_model_views(pid: str) -> list[dict]: ...   # 内置默认模型目录（恢复默认模型用）

def upsert_provider(pid: str, payload: dict) -> dict:          # 校验失败抛 ModelRegistryError
def delete_provider(pid: str) -> bool: ...                     # 内置提供方抛 ModelRegistryError
def upsert_model(pid: str, payload: dict) -> dict: ...
def delete_model(pid: str, model_id: str) -> bool: ...
def restore_default_models(pid: str) -> list[dict]: ...        # 写回内置默认目录，返回新目录
def set_secret(pid: str, api_key: str) -> None: ...            # 空串 = 清除已存密钥
def key_status(pid: str) -> dict: ...                          # {"set":bool,"source":"env|stored|none","masked":str}

def set_active(provider: str, model: str | None = None) -> dict: ...
def active() -> dict: ...                                      # {"provider":str,"model":str|None}
def runtime_resolution() -> dict: ...                          # 见 §2.1

def available_models(pid: str, timeout_s: float = 15.0) -> dict: ...
# 真实 GET {base_url}/models（Authorization: Bearer <key>），返回
# {"provider":pid,"base_url":str,"models":[{"id":str,"owned_by":str}],"count":int,"error":str}
# 未授权 → 抛 PrivacyAuthorizationError（由 web 层转 403）；网络/上游失败 → error 非空、models 为空
```

### 2.1 `runtime_resolution()`（llm_client 集成点）

```python
{
  "provider": "deepseek",
  "model": "deepseek-chat",
  "base_url": "https://api.deepseek.com/v1",
  "api_key": "sk-...",           # 仅供 llm_client 内部使用，禁止进任何响应体
  "key_source": "env",           # env | stored | none
  "protocol": "openai",
  "params": {
    "context_window": 65536,     # None = 未声明
    "max_output_tokens": 8192,   # None = 未声明
    "reasoning": {               # None = 未启用推理档位
      "param": "reasoning_effort",
      "tier": "low",
      "api_value": "low"
    }
  }
}
```

优先级（**环境变量优先**，与仓库既有口径一致）：
`LLM_PROVIDER` 环境变量 → `models.json` 的 `active.provider` → `longcat`。
模型同理：提供方自己的 `*_MODEL` 环境变量 → `active.model` → 内置 `providers.json` 的 model。

### 2.2 校验规则（写入时严格执行，违反 = `ModelRegistryError`）

- provider id：`^[a-z][a-z0-9_-]{0,31}$`；最多 50 个提供方。
- `base_url`：`http://` 或 `https://`，有 host，长度 ≤ 512。
- `protocol` ∈ `PROTOCOLS`；`key_env`：空 或 `^[A-Z][A-Z0-9_]{0,63}$`。
- model id：非空、≤ 200 字符、无前后空白；每个提供方最多 200 个模型。
- `context_window`：`None` 或 `1..10_000_000`；`max_output_tokens`：`None` 或 `1..1_000_000`；
  两者都非 `None` 时 `max_output_tokens <= context_window`。
- `input_types`：`INPUT_TYPES` 的非空子集，去重。
- `reasoning.param`：`^[A-Za-z_][A-Za-z0-9_.]{0,39}$`；`tiers` 每项
  `{"tier": REASONING_TIERS 之一, "api_value": None 或 ≤64 字符串}`，`tier` 不得重复；
  `active_tier` 必须出现在 `tiers` 里（`tiers` 为空则强制 `enabled = false`）。
- **未知字段一律拒绝**（400 / `ModelRegistryError`），错误信息里点名是哪个字段。
- `schema_version != 1` 的已存文件：fail-soft 退回内置默认 + 告警，不覆盖原文件。

## 3. HTTP 接口：`src/mylocalai/web/models_api.py`

`router = APIRouter(prefix="/api/models", tags=["models"])`，在 `web/app.py` 里
`app.include_router(models_router)`（紧挨既有 `privacy_router`）。

权限：全部本地接口，无鉴权（与既有 API 一致）；写接口在成功保存后调用
`llm_client.reset_cache()` 与 `model_registry.reset_cache()`。

### 3.1 `GET /api/models`

```json

  "runtime": { "provider": "longcat", "model": "LongCat-2.5-Preview",

               "key_source": "none", "protocol": "openai" },
  "protocols": [ { "id": "openai", "label": "OpenAI Chat Completions", "runtime_supported": true },
                 { "id": "anthropic", "label": "Anthropic Messages", "runtime_supported": false },
                 { "id": "gemini", "label": "Gemini generateContent", "runtime_supported": false } ],
  "input_types": [ { "id": "text", "label": "文本" }, { "id": "image", "label": "图片" } ],
  "reasoning_tiers": [ { "id": "off", "label": "off" }, { "id": "low", "label": "low" },

```

provider view：

```json
{
  "id": "deepseek",
  "display_name": "DeepSeek",

```

### 3.2 写接口一览（全部返回**更新后的 provider view**，删除类返回 `{"deleted": true, "id": ...}`）

| 方法 | 路径 | 请求体 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/models/providers` | `{id, display_name, base_url, protocol, key_env, enabled, api_key?}` | 新建/覆盖提供方；`api_key` 非空则同时写密钥 |
| PUT | `/api/models/providers/{pid}` | `{display_name, base_url, protocol, key_env, enabled}` | 改提供方（不含密钥） |
| DELETE | `/api/models/providers/{pid}` | — | 删自定义提供方；内置 → 400 |
| PUT | `/api/models/providers/{pid}/secret` | `{api_key}` | 写/清密钥（空串 = 清除） |
| POST | `/api/models/providers/{pid}/activate` | `{model?}` | 设为当前提供方（可选指定模型） |
| POST | `/api/models/providers/{pid}/discover` | `{timeout_s?}` | 获取可用模型（真发请求） |
| POST | `/api/models/providers/{pid}/models` | 完整模型对象 | 新增/覆盖模型 |
| DELETE | `/api/models/providers/{pid}/models/{model_id}` | — | 删模型 |
| POST | `/api/models/providers/{pid}/models/restore` | — | 恢复该提供方的默认模型目录 |

状态码：
- 结构/取值非法 → **400**，`detail` 用中文点名字段（透传 `ModelRegistryError`）。
- 未知提供方 / 未知模型 → **404**。
- 删内置提供方、`activate` 一个 `protocol` 非 `openai` 的提供方 → **400**，说明原因。
- `/discover` 未授权外发 → **403**（`PrivacyAuthorizationError`）；上游/网络失败 → **502**。
  上游成功但返回空目录 → 200 且 `models: []`、`count: 0`（诚实报空，不假装有）。
- 文件系统写入失败（OSError）→ **500**，detail 带路径。

### 3.3 `/discover` 响应

```json
{ "provider": "deepseek", "base_url": "https://api.deepseek.com/v1",
  "models": [ { "id": "deepseek-chat", "owned_by": "deepseek" } ], "count": 1, "error": "" }
```

**不会自动写进模型目录**：由用户在 UI 上勾选后再 `POST .../models` 落盘（"获取"与"保存"分开）。

### 4.1 结构（对齐图片二的观感）

- 顶栏 `header-actions` 里、`关于` 按钮**左边**新增
  `<button id="settingsBtn" class="btn-ghost settings-open-btn" type="button" aria-haspopup="dialog" aria-controls="settingsDialog">设置</button>`。
- 弹层：`<div id="settingsDialog" class="settings-dialog hidden" role="dialog" aria-modal="true" aria-labelledby="settingsTitle">`
  - 左栏导航 `#settingsNav`：`模型`（`data-settings-tab="models"`，默认选中）——本规格只要求这一个 Tab；
    允许再放一个跳转「隐私与授权」的外链按钮（可省）。
  - 右侧内容容器 `#settingsPane`：由 `settings.js` 渲染。
  - 右上角 `<button id="settingsCloseBtn">关闭</button>`。

- `settings.js` 暴露 `window.SettingsPanel = { open(), close(), isOpen() }`，`shell.js` 只做绑定。

### 4.2 模型面板（对齐图片二 / 图片三）

顶部按钮：`＋ 新建提供方`、`获取可用模型`、`恢复默认模型`（作用于当前选中的提供方）。

- 提供方列表（左）：显示名称 + Provider ID + 密钥状态徽章（`已配置(环境变量)` / `已配置(本地)` / `未配置`）+ `当前`标记；内置提供方带 `内置` 徽章。
- 提供方表单（右）：`Provider ID`（新建时必填；已存在时只读）、`显示名称`、`API 地址`、
  `API 协议`（下拉，非 openai 的选项要标注「本站运行期不支持」）、`API 密钥`（`type="password"`，
  占位文案「输入 API 密钥」；已配置时显示掩码，留空表示不改）、`启用` 开关。
  按钮：`保存提供方`、`设为当前`、`删除提供方`（内置禁用并给出原因）。
- 模型目录区（图片三）：
  - 标题行：`模型目录` + 状态文案（`已自定义模型目录` / `内置默认模型目录`）+ 右侧 `恢复默认模型`、`获取可用模型`。
  - 每个模型一张卡片：
    - 第一行：模型 ID 输入框、显示名称输入框、`启用` 开关、删除按钮（垃圾桶图标，含 `aria-label`）。
    - 第二行：`上下文窗口`（数字，可填 `1M` / `128K` / `65536`，前端解析成整数）、`最大输出 token 数`（同上）。
    - 第三行：`输入类型` 两个复选框 `文本` / `图片`。
    - 第四行：`推理等级` 开关 +（开启后）档位表：每行 `档位`（下拉 off/low/medium/high）+
      `API 参数值`（文本框，off 档位禁用并提示「关闭思考」）+ 行删除按钮 + `＋ 添加档位`。
  - 底部：`＋ 添加模型`、`保存模型目录`。
  - 「获取可用模型」的结果以**可勾选清单**呈现：勾选后 `导入所选模型` 才写盘；未勾选不落盘。
- 所有写操作成功后重新拉 `GET /api/models` 全量刷新；失败时在弹层内 `#settingsStatus` 区显示中文错误，
  并且**不隐藏**后端给的 detail 原文。
- 无 JS 框架、不用 `innerHTML` 拼接用户输入（一律 `textContent` 或 `escapeHtml` 后再拼）。

## 5. `llm_client` 集成（`src/mylocalai/llm/llm_client.py`）

1. `providers()`：先取 `providers.json` 的底表，再用 `model_registry` 里的提供方**覆盖/新增**
   （`base_url` 用注册表值；`model` 用注册表 `active.model` 或该提供方首个启用模型；
   `key_env` 用注册表声明的名字，未声明则合成 `MYLOCALAI_<PID 大写>_API_KEY`）。
   注册表为空（无 `data/models.json`）→ **表内容与现在逐字节一致**。
2. 密钥解析：新增 `_provider_key(pid, spec)`——环境变量（`key_env`）优先，其次 `model_registry`
   的密钥存储；两者都没有 = 无密钥（保持现有"未配置 X"错误文案）。
3. `_resolve()`：主提供方 = `LLM_PROVIDER` 环境变量 → 注册表 `active.provider` → `longcat`。
   模型 = 该提供方 `*_MODEL` 环境变量 → 注册表 → 内置。
4. 模型参数：
   - `max_tokens` 超过该模型 `max_output_tokens` 时**下调到上限**（不放大）。
   - 模型 `reasoning.enabled` 且 `active_tier` 的 `api_value` 非空时，把
     `{param: api_value}` 合进 `extra_body`；`off` 档位（`api_value` 为 `null`）不额外发参数。
   - **缓存键**：仅当真的会多带参数时，把该参数指纹追加进 `_cache_key`（写法对齐既有
     `namespace`：默认路径不加任何字节，金样本哈希必须不变）。
5. `reset_cache()` 一并清 `model_registry` 缓存。
