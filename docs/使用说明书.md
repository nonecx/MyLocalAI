# MyLocalAI 使用说明书

> 面向使用者（非开发者）的完整操作手册。安装/配置/启动/三个页面用法/命令行/MCP/配置调整/数据备份/常见问题。
> 开发与架构口径见 `README.md`；本文所有入口命令均已实跑验证（2026-11-01）。
>
> 先记住两条设计底线，理解了它们就不会误读任何输出：
> 1. **不判真假，只述证据**——助手汇总可核实的证据与来源立场，给出确定性结论卡片；"是真的/是假的"这句话永远由你自己说。
> 2. **大模型不参与打分**——标签、风险分、置信度、关注度 E 分全部由纯函数从证据本/信号推导，LLM 只负责取证和写叙述。改不了、也买不通。

---

## 1. 它能帮你做什么

把「这条消息是真的吗」从你的负担变成助手的工作：丢进对话框，拿回一张带证据、带置信度、带"什么时候该再看一眼"的卡片；深挖按需。

| 你的问题 | 背后引擎 | 在哪用 |
|---|---|---|
| 真的假的？ | 谣言 Agent（联网取证证据本 + 确定性打分） | 对话 / 命令行 / MCP |
| 为什么有人信、有人传？ | classic 三维分析（情绪/攻击性/逻辑） | 对话（「言论土壤」chip 或直接说） |
| 有多热？ | 关注度确定性公式 + 联网估参 | 对话（「算热度」面板填 x/y/z；话题联网估参走命令行或接口） |
| 大家怎么看？ | 观点光谱 / 背景解读 | 档案库章节（追问时生成） |
| 我查过些什么？ | 参谋三聚合（话术模式库/信源画像/周报） | 左栏「我的画像」或直接说"看看我的画像" |

越用越聪明：你查过的每一条都会沉淀进本地档案库（谣言库指纹秒回、话术模式库、信源画像），全部零 API 成本，数据只来自你自己的使用记录。

## 2. 安装（首次约 10 分钟）

要求：Windows 10/11（macOS/Linux 走 `start.sh`）、Python **3.10-3.14**、无需 GPU；联网取证时需要网络。

```bash
# 在项目根目录 D:\MyLocalAI 下
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pip install -e .
```

配置密钥（唯一必填项）：

```bash
copy .env.example .env        # PowerShell 用 Copy-Item；Git Bash 用 cp
```

编辑 `.env`，最关键两条：

```ini
LLM_PROVIDER=longcat          # 换供应商只改这一行（可选 longcat / deepseek / openai）
LONGCAT_API_KEY=你的密钥      # 密钥、地址、模型名按提供方成组绑定，不会错配
```

> 默认模型名是 `LongCat-2.5-Preview`（英文连字符）。想加备用链路（主提供方挂了自动切换）填 `LLM_FALLBACKS=openai` 并配好对应密钥。

自检 + 第一次分析：

```bash
.venv\Scripts\python.exe tests\smoke_api.py     # 配置自检 + 连通性（会调一次真实 API）
.venv\Scripts\python.exe -m mylocalai.cli --text "气死了！听说自来水被人下毒了，官方根本不敢说！"
```

可选附加功能（按需装）：

| 功能 | 安装命令 |
|---|---|
| 谣言 Agent 联网取证（LangChain 工具轮） | `pip install -e ".[agent]"` |
| 网站服务（fastapi/uvicorn，requirements.txt 已含） | `pip install -e ".[web]"` |
| MCP 服务器（把助手/Agent 接入 MCP 客户端） | `pip install -e ".[mcp]"` |

## 3. 启动与停止（网页）

**最简单**：双击 `my_website\start.bat`。它会自动启动服务、2 秒后打开浏览器 `http://127.0.0.1:8000`。**关掉那个黑窗口就是停止服务**。端口被占用时（服务已在跑）直接访问原地址即可；想换端口先 `set PORT=8010` 再启动。

**命令行方式**（等效）：

```bash
.venv\Scripts\python.exe -m uvicorn mylocalai.web.app:app --host 127.0.0.1 --port 8000
```

常去地址：

| 地址 | 用途 |
|---|---|
| `http://127.0.0.1:8000` | 主页面（单页对话 + 左栏） |
| `http://127.0.0.1:8000/docs` | 交互式 API 文档（可在线试调所有接口） |
| `http://127.0.0.1:8000/api/health` | 健康检查（不碰大模型；`llm` 字段看上游是否可用） |

> 不要直接双击 `static/index.html` 打开页面——file:// 协议下接口全部失效（页面检测到会显示引导横幅）。

## 4. 网页用法（单页对话 + 左栏）

页面只有一个对话流，没有 Tab：**顶栏**（品牌 + 服务状态 + 「关于」）、**左栏**（会话 / 档案库 / 我的画像）、
**消息流**、**composer**（输入框 + 上方的快捷 chips）。原来的「工具模式」「参谋」两个 Tab 已合并进来。

### 4.1 对话（日常用这个）

把消息直接丢进输入框（上限 8000 字），例如：

> 网传喝隔夜茶会致癌，转给家人看看！

**会经历什么**：助手先路由意图，然后按车道响应——

| 车道 | 触发 | 预期等待 | 你会看到 |
|---|---|---|---|
| 秒答 | 追问/闲聊/纯公式算热度/看画像 | 3-8s | 直接回复或一张卡 |
| 快答 | "分析一下这段话的言论土壤" | 10-30s | 进度 → 卡片 → 叙述 |
| 慢查 | "这是真的吗"（联网核查） | 30-120s | **本地初扫**（零成本先出）→ 组件级进度 → 卡片 → 叙述 |

慢查绝不白屏干等：先发"初扫：命中 N 条话术特征"，再逐步报"取证中/整理中"。**等不及随时点"停止"**，服务端协作取消、已有结果照发。单轮总预算默认 180 秒（`assistant_rules.json` 的 `turn_deadline_s`），超时诚实降级。

**结论卡片读法**（三层信息，卡片永远在叙述之前）：

1. 第一眼：**标签 + 置信度**（高/中/低）；
2. 第二眼：证据计数（官方/非官方/未知）、**as_of**（证据截至时间）、降级徽章（有则如实标注）；
3. 展开：证据本前 5 条（标题 + 立场 + 链接，收在「证据本」折叠里）+ 复审条件（"出现官方通报就该再看一眼"这类）。

言论土壤卡把 **classic 完整分析报告**收在「完整分析报告」折叠里；报告过长时后端截断并标注"原文过长，后端已截断"。

**谣言库秒回（先问再查）**：查过的相似说法再出现时，助手会问"查过相似说法，秒回旧结论还是重查？"——你回哪句就执行哪个，绝不擅自断言同一谣言。这个问句只对紧随的下一轮生效，直接发新消息则正常核查。

**只找证据，不判断真假（证据研究）**：说"不要判断真假，只查官方资料 / 只找证据"就走证据研究能力（`collect_evidence`，只读取证）：把原文拆成可核查的主张，只去**已核验信源**（官方机构 / 权威媒体的信源目录）里找**可定位引文**——引文逐字来自实际读取的网页正文，定位不到的引文会被代码丢弃、不当证据。它**不建档、不出真假结论、不给任何分数**；陌生站点自称权威不算数（最多记为"未核验候选"，不进证据检索）。结果是一张 evidence 卡：领域 → 已核验/未核验信源 → 主张 → 证据（关系 + 逐字引文 + 链接 + 时点）→ 缺口与错误 → 卡尾如实写"已执行 N 次搜索、N 次读页、N 次模型调用"。等不及随时点"停止"，已取得的证据照发。注意：读网页需要单独授权"外部取页"（隐私设置里默认只开检索授权时，选站和检索照常可用，读页会如实标注"未授权"，不会假装搜过）。

**左栏**：

- **会话列表**：点"＋ 新建会话"开新对话；每项显示会话累计成本（requests/tokens 真实计数）。历史会话点开即回。
- **档案库**：每次核查自动建档。点开一个档案有**六个章节**：核查结论（版本对比 v1/v2…）、证据批次、言论土壤、热度趋势、观点光谱（追问时才生成）、背景解读（同上）；右上角可**导出 Markdown**（含免责语与 as_of 页脚）。档案**没有删除按钮**（防误删、收窄注入面）。
- **我的画像**（原「参谋」三块）：三个按钮各自在对话流里出一张只读卡——话术模式库（你查过的档案里各话术命中多少、结论分布、常见组合）、信源画像（哪些域名反复提供反驳证据、是否达标增信）、本周简报（近 7 天新档案 / 结论分布 / 真实成本 / 高频话术 / 辟谣主力域名）。零 LLM、零 API，数据只来自本机档案库；空库显示"暂无数据"，不对任何消息或站点判定真假。

**被动提醒**：档案太久没复核或热度变化超阈值时，打开会话会有一行浅色提示。无推送、无通知、不主动打扰。

**这些指令会被直接拒绝**（对话层注入防护，编都编不进去）：改分数/改置信度、删档案、越权导出、"帮我编造谣言/写钓鱼消息/伪造官方通报"等。

### 4.2 快捷 chips（composer 上方）

四个 chip 是"少打字"的入口，行为分两类：

- **核查真伪 / 言论土壤**：只把提示词模板填进输入框（例如"这段是真的吗？"），**不会替你发送**——待核查的原文必须由你自己提供，系统不为用户编造待核查文本；填好后点发送。
- **算热度**：点开 x / y / z 小面板（默认 100 / 100000 / 1000），填完点"计算关注度"，走**确定性公式** `E = 100·(1 − e^(−λS))`，零 LLM 零 API，直接回一张热度卡。这条走的是 `action` 精确通道，数字不会被路由模型解析错。
- **我的画像**：发一轮"看看我的画像"（默认话术模式库），与前文左栏三个按钮等价。

### 4.3 关注度（Attention）读数边界

「算热度」面板算的是"一件事有多少人关注"的确定性分数，**不调用大模型**；`x`=文章数量、`y`=文章阅读量、`z`=文章留言量。

读数边界：E 只适合同口径下的相对排序（没有任何站点公开文章级精确阅读量）；话题联网估参模式下 y/z 是**代理估计值**，卡片会挂"代理/估计值"徽章。`E>66`（严格大于）触发深读解读，解读不参与打分，LLM 不可用时回退本地模板并标"降级"。

话题联网估参（输入一个话题词、真实检索估出 x/y/z）现在只在命令行与接口层提供（见 §5 与 `POST /api/attention/search`），页面上的「算热度」面板是纯公式手动输入。

### 4.4 原来的「工具模式」去哪了

原工具模式页的两条分析链路都已并入对话，能力不丢、契约不变：

| 原功能 | 现在怎么用 |
|---|---|
| 快速分析（三维 + 四档结论 + 完整报告） | 说"分析一下这段话的言论土壤"，或点「言论土壤」chip；报告收在卡片折叠里 |
| 谣言 Agent（联网取证 + 风险分 + 证据本） | 说"这条是真的吗"；证据本前 5 条收在卡片折叠里 |
| 手动算关注度 x/y/z | composer 的「算热度」面板 |
| 分析记录（内存 50 条） | 改为会话消息 + 档案库（持久化，重启还在） |
| 关于系统 | 顶栏「关于」按钮 |

接口 `/api/analyze`、`/api/attention`、`/api/attention/search`、`/api/history` **全部保留**（命令行、脚本、测试仍可用），只是页面不再直接调用它们。

## 5. 命令行用法

全部在项目根目录执行（`.venv\Scripts\python.exe` 下文简写为 `python`）：

| 命令 | 用途 | 示例 |
|---|---|---|
| `python -m mylocalai.cli --text "…"` | classic 三维分析 + 四档结论 | `python -m mylocalai.cli --text "…"` |
| `python -m mylocalai.cli` | 进入交互式输入模式（逐条分析） | 直接运行 |
| `python -m mylocalai.cli --attention-online --text "…"` | 分析时联网估算热度 | |
| `python -m mylocalai.rumor "…"` | 谣言 Agent 联网取证（需 agent extra） | `python -m mylocalai.rumor "网传喝隔夜茶会致癌"` |
| `python -m mylocalai.rumor` | Agent 交互模式（`exit` 退出） | |
| `python -m mylocalai.rumor --json "…"` | 输出完整结构化结果 | |
| `python -m mylocalai.attention.attention --x 1000 --y 1e8 --z 1e6 --json` | 手动算关注度（确定性） | 加 `--profile reachable` 切换参数档位 |
| `python -m mylocalai.attention.deep_read --query "某话题" --x … --y … --z …` | 高关注话题生成深读解读 | 加 `--no-llm` 只用本地模板 |

关注度参数档位：`spec`（默认原始口径）/ `reachable`（拉高可达性）。切档位会改变所有分数，属于显式的口径变更。

## 6. MCP 接入（给其他 AI 客户端用）

先装 MCP 依赖：`pip install -e ".[mcp]"`，然后两个服务器任选：

```bash
python -m mylocalai.assistant.mcp_server   # 智能助手（推荐，与网页对话同核）
python -m mylocalai.rumor.mcp              # 纯谣言 Agent
```

助手 MCP 暴露三个工具：

| 工具 | 用途 |
|---|---|
| `assistant_chat(message, session_id?)` | 与助手对话一回合，同步返回 reply + 结论卡片 + dossier_id + 成本；把返回的 session_id 传回来可延续上下文 |
| `assistant_sessions(limit)` | 列出历史会话 |
| `assistant_dossiers(query?, limit?)` | 列出核查档案 |

MCP 客户端配置示例（stdio 传输；`.env` 与数据库按安装位置自动定位，不依赖启动目录）：

```json
{
  "mcpServers": {
    "mylocalai-assistant": {
      "command": "D:\\MyLocalAI\\.venv\\Scripts\\python.exe",
      "args": ["-m", "mylocalai.assistant.mcp_server"]
    }
  }
}
```

口径：MCP 端与网页端**同一助手核心**，同输入得到同一卡片；助手不判真假、只述证据，降级时如实说明。

## 7. 调整行为（改配置，不改代码）

**换判定口径/换行业**：改 `src/mylocalai/config/` 下的 JSON——`verdict_rules.json`（分层阈值/风险分阈值/话术权重/结论卡片映射）、`sources_registry.json`（信源分级名单与各档角色权重）。档位重命名后记得同步各档角色段（按档名声明）。

**改助手行为**：`src/mylocalai/assistant/assistant_rules.json` ——单轮工具上限（默认 2）、轮预算（180s）、上下文字符预算、指纹阈值、信源画像阈值、拒绝词表、提醒规则；人设与固定话术在 `prompts.json`。

**改取证预算**：`src/mylocalai/assistant/skills/rules.json` ——取证三技能（collect_evidence）的输入长度、主张数、信源数、候选数、搜索/读页/模型调用次数、每主张查询与读页上限、总时长、单次 IO 超时、页面大小与字符上限、重定向跳数、引文长度；领域表在 `skills/taxonomy.json`（12 个领域，分类标签只能从表里选），信源目录在 `skills/sources.json`（20 家机构/媒体，域名锚点由程序独立判定）。改这里不改代码，写坏的值会被夹到安全区间而不是让流程崩掉。

**改模型提供方**：`.env` 的 `LLM_PROVIDER` + 对应密钥三件套；提供方表在 `src/mylocalai/llm/providers.json`（加新家只在那里加一段）。

**改深读/关注度**：`src/mylocalai/attention/` 下 `attn_rules.json`（公式参数与档位）、`deep_read_rules.json`（触发规则与护栏禁词）、`society_issues.json`（封闭议题清单）。

进阶：以上每份配置都支持 `*_PATH` 整套替换 / `*_EXTRA_PATH` 增量覆盖环境变量（见 `.env.example`）。写坏不会崩——不合规段自动退回内置默认并留告警，也不会把官方来源静默降级。

## 8. 数据、成本与备份

- **所有持久化数据都在一个文件**：`data/dossier.db`（SQLite + WAL）——核查档案、六章节、会话、消息、工具运行、成本、指纹库、话术标记。重启全在。
- **备份**：先关服务（关掉 start.bat 窗口），再复制 `data/dossier.db`。不做在线备份。想换位置设 `DOSSIER_DB_PATH` 绝对路径。
- `/api/analyze` 的工具模式历史是内存轻模式（最近 50 条，重启清空），与档案库无关；单页化后页面不再展示它，会话与档案才是持久化入口。
- **成本**：页面上每轮徽章、会话列表累计、档案详情的成本都是**真实上游用量**（缓存命中不计费不计数；tokens 取不到时如实显示 0，不估算）。已知边界：Agent 联网取证的 LangChain 工具轮不经计数控面，这部分不出现在徽章里——成本数字是"下限"而非全额。
- **省配额**：同请求进程内缓存（TTL 默认 900s）、谣言库指纹秒回（不再重复联网）、「我的画像」零 API。

## 9. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 卡在"取证中"很久 | 慢查本来 30-120s。超过 180s 会自动诚实降级收尾；等不及点取消 |
| 报错含 `content=None` / 空回复 | LongCat 上游前科（HTTP 通但返回空），属上游问题，重试或换备用提供方；链路本身没坏 |
| 503 | 同时在跑的分析达到上限（默认 4 个），稍后重试 |
| 400 文本过长 | 上限 8000 字（对话与接口同限）；空文本也会被拒 |
| 页面白屏/接口全失败 | 你是直接双击 index.html 打开的，见 §3 用 start.bat |
| 换了结论还是和上次不一样 | 同进程缓存内必然一致；跨进程/超时后上游有采样漂移（不认 seed），工程上只能收敛。重要结论以卡片 + 证据为准 |
| 档案页某章节显示 absent | 观点光谱/背景解读是追问才生成的懒加载章节，不是故障 |
| 点「算热度」报参数错误 | x/y/z 必须是非负数字；前端先校验一次，后端仍会再校验（非法一律 400） |
| 想改判定标准 | 见 §7，全部改 JSON，不需要动 Python |
| 跑测试 | 离线全量：`.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p "test_*.py"`（1129 用例）；一键 CI：`scripts\ci.cmd`（compileall + 套件 + mock 闸门；本地检验器缺失时第 3 步自动跳过，不耗配额） |

## 10. 边界与免责

- 结论永远不是"真/假"判决，是"证据支持什么/不足什么 + 什么时候该再看"；真伪裁决留给用户。
- 信源名单是人工整理的保守取向：名单外的好来源会被归"未知来源"，可用增量配置补。
- 关注度 E 分只在同口径下可比；话题模式的 y/z 是代理估计值。
- 演示级部署：只监听 127.0.0.1、单进程、无鉴权、无多用户——**不要直接暴露到公网**。
- 真实 API 冒烟依赖提供方状态；离线套件与 mock 闸门才是链路正确性的判定基准。
