## 3. 三类结构问题（与样本量无关）

1. **只有文件没有代码**：`skills/research/agent/SKILL.md`、`skills/authority/agent/SKILL.md` 描述的
   `mode="agent"` 受限循环未实现；`/api/skills/preferences` 路由模块存在但未在 `web/app.py` 挂载（访问 404），
   `tools_composite.py` 读的 `composite.enabled` 也只被未装配的工具消费。本次已在文件头与使用说明书
   里如实标注"预留未接线、改了也不生效"。
2. **注册但不可路由**：`platform_feed`、`collect_and_verify` 由 `register_all` 提供，但 `AssistantLoop.registry`
   没有调用对应模块，`TOOL_ACTIONS` 与角色白名单里也没有它们——**自然语言永远到不了**。
   本次选择：不往 `prompts.json` 的 `router_system` 里加（避免模型幻觉调用），在 README 与本文档注明可达路径。
3. **阈值不可达**：`deep_read` 在 `spec` 档 `E>66` 下实测 5 个真实头部话题 0/5 触发（最高 54.81），
   形同虚设。另一分支（`feature/attention-on-main-path` / `feature/attention-phenomenon`）正在处理：
   前者把 E 挂上结论卡，后者新增确定性"现象判读"，把 x/y/z 的形态变成人能读的一句话。

## 4. 结论

- **能力数量不是价值**。13 项能力里，真正在主路径上被反复使用的只是少数；
  其余多为"按角色裁剪的专用能力"或"低频但成本近似 0"的能力，保留可以，但**不该在答辩里当成数量优势**。
- **两类必须处理**：注册但不可路由（结构性浪费）、只有文件没有代码（会误导使用者与评委）。
- **本机覆盖 2/20 不代表产品无效**，但说明**需要一套真实使用数据**才能判断该砍谁——审计脚本已落地，
  后续每次发版跑一次即可。

## 5. 复现方式

```powershell
.venv\Scripts\python.exe -X utf8 scripts\audit_capability_usage.py
.venv\Scripts\python.exe -X utf8 scripts\audit_capability_usage.py --json
$env:DOSSIER_DB_PATH = "D:\path\to\dossier.db"; .venv\Scripts\python.exe scripts\audit_capability_usage.py
```

脚本只读打开数据库（`mode=ro` + `PRAGMA query_only`），不建表、不写库、不联网；库缺失或损坏时按空库统计并给出中文原因。
