# 监测平台规格（平台化扩展 · P1-P7）

> 日期：2026-11-20　|　状态：**已实现**（feature/platform-monitor 分支，P1-P7 全绿）
> 读者：项目作者、后续执行会话
> 基线：`docs/工作指导-智能助手重塑-2026-10-30.md`（M1-M4+L4 已完成）；本文是平台化扩展的唯一实施依据

---

## 1. 定位与边界

在「智能助手」（等用户发消息 → 核查卡片）之外新增**监测平台**：后台按监控词自动
发现热门信息 → 本地初筛 → 对过门槛候选联网深查 → **纯函数推导传播风险** → 平台页
分级展示与预警。

三条不可违反的边界（从助手继承并全程锁定）：

1. **传播风险分级是纯函数**（`platform/risk.py`），大模型不参与打分；输入只有
   确定性数字与 `rumor.verdict.ALL_LABELS` 封闭标签集——LLM 没有任何写入通道
   （变异测试锁定，见 §8）。
2. **风险分级只描述传播风险，不判定内容真假**。真假仍由 rumor 引擎的证据链负责；
   展示层强制随行 as_of、「代理/估计值」徽章与免责口径。
3. **隐私 fail-closed**：外部检索/抓取未授权 → 整次巡检 skipped，不外发、不落库、
   不静默失败；结果保存关闭 → 只进当次返回不写库。

预警**只在平台页内呈现**（无推送、无通知、无定时打扰之外的任何形式）——打开页面
才看到，延续「不制造新压力」。

## 2. 包结构与依赖方向

```
src/mylocalai/platform/
├── rules.py        platform_rules.json 加载（坏配置段级降级 + 告警，永不抛）
├── platform_rules.json  全部口径外置（开关/间隔/门槛/预算/风险权重/监控词/RSS 源）
├── candidates.py   FeedCandidate 统一形状 + URL 去重 + 标题指纹近似去重（转载识别）
├── sources.py      SearchDiscoveryProvider（包 search_all，授权门逐次检查）
│                   + RssDiscoveryProvider（RSS/Atom 双解析、关键词过滤、
│                     DOCTYPE/ENTITY 剥离 fail-closed、SSRF 防护复用检索层）
├── heat.py         estimate_heat（复用 estimate_from_search + attention_score，
│                   零额外检索）+ relative_change（对称环比口径）
├── risk.py         assess_spread_risk 传播风险分级纯函数（§5）
├── runner.py       PlatformRunner.scan() 两阶段巡检编排（§6）
├── scheduler.py    PlatformScheduler 后台调度（启动即跑一次 + 间隔循环 + 单飞 + 取消）
├── store.py        平台域三表 CRUD（watch_queries / feed_entries / scan_runs）
└── __main__.py     CLI：--once / --query / --status / --serve / --interval / --json
```

依赖方向（`tests/test_import_rules.py` AST 锁定）：
`core ← llm ← retrieval ← {classic, rumor, attention} ← {dossier, assistant, platform}
← web/cli/mcp`。assistant **允许**消费 platform（platform_feed 只读工具）；
platform 不 import web/assistant（不成环）；上游各包一律禁 platform。

数据模型：dossier store **v6 迁移**建三表（`watch_queries` / `feed_entries` /
`scan_runs`；feed URL 唯一约束即跨巡检去重第一道闸，`result_expires_at` 走
「核查结果」保留期，巡检记录 `scan_runs` 是操作元数据不计保留期）。

## 3. 发现源（计划决策：监控词 + 搜索引擎 + RSS 都要）

| 源 | 实现 | 授权 | 降级 |
|---|---|---|---|
| 搜索引擎 | `SearchDiscoveryProvider` 包 `retrieval.search.search_all`（360 主力/百度备用，内置验证码降级） | 逐次检查 `external_allowed("public-search")` | 未授权=degraded+明确原因（不静默）；后端全败=degraded |
| RSS/Atom | `RssDiscoveryProvider`：规则 `rss_sources` 配置，关键词过滤条目；热榜（无公开 API 的源）经 RSSHub 类中转后同样走此 provider | 同左（抓取也属外发） | 单源失败不影响其他源；坏 XML=`xml_parse_error`；DOCTYPE/ENTITY 剥离后未定义实体引用 → 整源拒读（fail-closed） |

安全：RSS 抓取复用检索层 `_host_is_public`（SSRF 防护不重复实现）+ 大小/超时上限；
XML 解析前剥 DOCTYPE/ENTITY。

## 4. 两阶段巡检（成本控制）

```
for each 启用中的监控词（封顶 max_queries_per_scan）:
  阶段一（轻）：多源发现 → URL 去重 → 标题指纹去重（转载只留第一条）
    → 话题级热度估计（从本批结果估 x/y/z 算 E，零额外检索）
    → patterns.scan_markers 本地初扫（零 LLM）
    → 不过门槛（E < heat_screen_e 且无话术命中）只登记 status=new，不深查
  阶段二（重，预算封顶）：过门槛候选 → RumorAgent.analyze(标题+摘要)
    → DossierService 建档（input_kind='topic'，同话题再命中走 recheck 版本化）
    → verdict 回填条目（status=verified）
```

热度是**话题级**（整批共享一个 E：批内有大阅读量文章则全话题变热）——这是
`estimate` 的口径，不是缺陷。预算三重封顶：`max_candidates_per_query`、
`deep_verify.max_per_scan`、`deep_verify.deadline_s`（llm_cache deadline scope，
与 `CHAT_TURN_DEADLINE_S` 同机制，深查前查剩余预算）。

## 5. 传播风险分级算法（`risk.py`，纯函数）

```
score = w_heat·E + w_growth·(环比×100) + w_breadth·覆盖面 + w_rumor·核查风险分
level = 阈值分档 notice/suspect/high/urgent，再应用 floors 保底规则
```

- 四因素各自 0-100：热度 E；环比增幅（`relative_change`，与 reminders 快照变化
  同口径）；覆盖面（独立条目数 / `breadth_full_sources`）；核查风险分
  （`verdict.assess()` 输出，无深查=0）。
- 权重/阈值/广度满值/floors 全部外置 `platform_rules.json` 的 `risk` 段；
  权重不和为 1、阈值不单调 → 整段退内置默认 + 告警。
- floors 例：`{min_rumor_score: 60, min_breadth: 50, level: high}`——核查结论差
  且传播面广时，即使加权分不够也保底抬档；保底只升不降。
- **输入契约即变异测试面**：坏类型/越界/NaN 一律抛；`rumor.label` 锁死
  `ALL_LABELS` 封闭集——大模型文本进不了分级链。
- 档位：`notice` 关注 / `suspect` 疑似 / `high` 高危 / `urgent` 紧急；
  **high 起算「大规模传播风险」**（信息流「预警」筛选 chips 与
  `/api/platform/warnings` 口径；无横幅、无推送）。

## 6. 降级与失败矩阵

| 情况 | 行为 |
|---|---|
| 外部检索未授权 | scan status=skipped + error=external_processing_not_authorized；平台页管理抽屉里出授权引导卡（链到设置弹层） |
| 结果保存关闭 | 条目只进当次 scan 返回，不写库；建档由 DossierService 自行门控 |
| LLM 不可用/深查异常 | 条目保留、status=verify_failed，风险只由热度+来源推导，**不编 verdict** |
| 单源/单监控词失败 | 该源/该词记 degraded + warning，不影响其余 |
| 取消（停机/用户在途删词） | 协作取消：已完成条目保留，scan 记 cancelled/partial；删词导致的外键冲突**不伪装成去重**（前置存在性检查 + 外键冲突原样抛） |
| 预算耗尽 | 停止开新深查，已完成的保留 |
| 记账（scan_runs）失败 | 只留 warning，不影响巡检本身 |

## 7. 接口与入口

REST（`web/platform_api.py`，前缀 `/api/platform`）：`GET /status`（含
`external_authorized`）、`GET /feed?risk=&limit=`、`GET /warnings`、
`GET/POST/DELETE /watch`（409 重复/400 空或过长/404 不存在）、`POST /scan`
（单飞触发，后台执行）、`GET /scans`、`GET /scans/{id}`。

前端（**方案 G：热榜/新闻信息流**，单页双视图）：`platform.js` + `platform.css`，
外加 `cards.js` 的对话内平台卡。

- **通栏 Tab「对话 ｜ 监测平台」**（`mainTabs`，header 正下方，下划线式）切换两个
  `<main>` 视图容器；默认落在对话视图，平台视图由 `platform.js` 接管，`chat.js`
  不参与切换。切换只做显隐（`.hidden`），两个容器都留在 DOM 里。
- **平台页 = 居中单列信息流**（`platform-layout`，最大 820px，无左栏），自上而下：
  1. 状态摘要条（`platformStatusBar`）：状态点三态（未授权 warn > 调度运行 run >
     默认灰）+ 一行诚实话术「监测中 · N 个话题 · 最近巡检 HH:MM（状态） · 高风险
     N 条」，右侧「立即巡检」「管理」两个动作；
  2. 筛选 chips（`platformFilterRow`）：全部 / 预警（`high,urgent`）/ 疑似 / 关注；
  3. 热榜卡片信息流（`platformFeed`）：档位徽章 + 标题 + 摘要 + meta（域名 / 发现
     时间 / E 值 + 「代理/估计」徽章 / 深查结论 / 档案号），点卡展开传播风险理由与
     原文链接；`high`/`urgent` 条目左侧加风险色条；
  4. 空态双引导（`platformEmpty`）：无监控词 → 「去添加」（开抽屉并聚焦输入框）；
     有词无信息 → 「立即巡检一次」。
- **管理抽屉**（右侧 `platformDrawer` + 遮罩 `platformDrawerMask`，Esc / 点遮罩 /
  关闭按钮三途关闭）：「管理」按钮开合，内部分三段——监控词增删查
  （`platformWatchInput` / `platformWatchAddBtn` / `platformWatchList`）、巡检记录
  时间线（`platformScans`：状态徽章 + 时间 + 候选/深查/降级计数 + 失败原因）、
  未授权引导卡（`platformDrawerAuth`：说明外发口径并链到设置弹层；授权后收起）。
- **巡检提示行**（`platformScanHint`）：触发失败 / 单飞 / 巡检中 / 超时等如实提示，
  不弹窗。
- **对话内平台卡**（对话里问「最近有什么预警」）由 `cards.js renderPlatform` 渲染，
  轻量化：条目只有「档位徽章 + 标题 + 单行 meta（E / 结论 / 发现时间）」，风险理由链
  与档案号属重信息，不进对话卡；数据来自助手工具 `platform_feed`
  （kind=warnings/feed/scans，只读零 LLM）。
- 样式只在 `platform.css` 新增 `platform-*` / `main-tab*` / 少量 `chat-platform-*`
  类，设计令牌全部复用 `style.css` 的 `:root` 变量，零框架。

CLI：`python -m mylocalai.platform --once`（可挂 Windows 计划任务；skipped 是
合法退出码 0 并打印授权提示，failed 才退 1）、`--status`、`--serve`。

web 启动：`platform_api.start_scheduler_if_enabled()`——规则 `enabled=false`
（默认）时**不构造**调度器（import 期零副作用）；多 worker 部署不启（每 worker
一个调度器会重复巡检）。

## 9. 已知局限

- 热度 y/z 仍是代理口径（无站点公开文章级精确阅读量），E 只适合同口径相对排序。
- 热榜类源无公开 API，经 RSSHub 等中转接入（配置即接入，无需新代码）。
- 巡检默认关闭；web 不开服务就不巡检（CLI + 计划任务是另一通道）。
- 平台页复用 `style.css` 设计令牌（居中单列信息流，无左栏），但信息流条目暂不内嵌
  证据本展开（深查结论进档案库，档案库页看六章节）。
