## 1. 定位与边界

在「智能助手」（等用户发消息 → 核查卡片）之外新增**监测平台**：后台按监控词自动
发现热门信息 → 本地初筛 → 对过门槛候选联网深查 → **纯函数推导传播风险** → 平台页
分级展示与预警。

三条不可违反的边界（从助手继承并全程锁定）：

1. **传播风险分级是纯函数**（`platform/risk.py`），大模型不参与打分；输入只有
   确定性数字与 `rumor.verdict.ALL_LABELS` 封闭标签集——LLM 没有任何写入通道
   （变异测试锁定，见 §8）。
2. **风险分级只描述传播风险，不判定内容真假**。真假仍由 rumor 引擎的证据链负责；
   展示层强制随行 as_of、「代理/估计值」徽章与免责口径。
3. **隐私 fail-closed**：外部检索/抓取未授权 → 整次巡检 skipped，不外发、不落库、
   不静默失败；结果保存关闭 → 只进当次返回不写库。

预警**只在平台页内呈现**（无推送、无通知、无定时打扰之外的任何形式）——打开页面
才看到，延续「不制造新压力」。

## 2. 包结构与依赖方向

```
src/mylocalai/platform/
├── rules.py        platform_rules.json 加载（坏配置段级降级 + 告警，永不抛）
├── platform_rules.json  全部口径外置（开关/间隔/门槛/预算/风险权重/监控词/RSS 源）
├── candidates.py   FeedCandidate 统一形状 + URL 去重 + 标题指纹近似去重（转载识别）
├── sources.py      SearchDiscoveryProvider（包 search_all，授权门逐次检查）
│                   + RssDiscoveryProvider（RSS/Atom 双解析、关键词过滤、
│                     DOCTYPE/ENTITY 剥离 fail-closed、SSRF 防护复用检索层）
├── domains.py      platform_domains.json 领域表（12 项）+ LLM 领域判定 +
│                   resolve_domain 五级链（永不抛；LLM 不可用不猜领域）
├── platform_domains.json  领域 id/名称/定义/示例/检索提示（口径外置，坏配置退内置默认）
├── heat.py         estimate_heat（复用 estimate_from_search + attention_score，
│                   零额外检索）+ relative_change（对称环比口径）
├── risk.py         assess_spread_risk 传播风险分级纯函数（§5）
├── runner.py       PlatformRunner.scan() 两阶段巡检编排（§6；收尾含报告阶段，v12）
├── report/         巡检报告技能（PatrolReport 三段式：代码汇总 + LLM 一次调用
│                   + 代码校验器；SKILL.md 只做语言组织与逻辑判断，v12）
├── scheduler.py    PlatformScheduler 后台调度（启动即跑一次 + 间隔循环 + 单飞 + 取消）
├── store.py        平台域表 CRUD（watch_queries / feed_entries / scan_runs / scan_reports + patrol_sources）
└── __main__.py     CLI：--once / --query / --status / --serve / --interval / --json
```

依赖方向（`tests/test_import_rules.py` AST 锁定）：
`core ← llm ← retrieval ← {classic, rumor, attention} ← {dossier, assistant, platform}
← web/cli/mcp`。assistant **允许**消费 platform（platform_feed 只读工具）；
platform 不 import web/assistant（不成环）；上游各包一律禁 platform。

数据模型：dossier store **v6 迁移**建三表（`watch_queries` / `feed_entries` /
`scan_runs`；feed URL 唯一约束即跨巡检去重第一道闸，`result_expires_at` 走
「核查结果」保留期，巡检记录 `scan_runs` 是操作元数据不计保留期）。

### 数据模型 v7（用户信息源 + 领域列）

v7 在 v6 三表之上追加（迁移只增不改，老库自动补建）：

| 对象 | 落点 | 口径 |
|---|---|---|
| 用户自建信息源 | `patrol_sources` | `kind` 封闭集 `rss`/`page`（越界即 ValueError）；`url` 唯一约束 = 重复添加的去重闸（`add_patrol_source` 返回 None → 409）；`enabled` 停用不删绑定 |
| 源↔监控词绑定 | `patrol_query_sources` | 多对多；**空绑定 = 全局源**（对所有监控词生效），有绑定 = 显式窄授权（只对绑定的词可见）；删监控词级联消失 |
| 监控词领域三列 | `watch_queries.domain` / `inferred_domain` / `inferred_at` | `domain` 是**用户手设**（空串 = 自动推断）；`inferred_*` 是自动推断缓存；`set_watch_query_domain` 手写即清缓存（防陈旧推断反覆盖用户意图），无触发器 |
| 信息流领域两列 | `feed_entries.topic_domain` / `topic_domain_source` | **契约修正**：`feed_entries.domain` 从 v6 起就是 **URL 主机域**（展示用），领域列另起两列 `topic_domain`（领域 id）/ `topic_domain_source`（`user`/`inferred_text`/`inferred_history`/`none`），两者分列存放、互不覆盖；前端读 `e.topic_domain` / `e.topic_domain_source`，**不读 `domain`** |
| 领域分布 | `domain_histogram()` | 最近 N 条非空 `topic_domain` 计数，供「历史分布」兜底 |

### 数据模型 v12（巡检报告：scan_reports）

v12 在既有各版之上追加**一张表**（迁移只增不改，老库自动补建；口径与 DDL 见
`dossier/store.py` v12 迁移注释）：

| 对象 | 落点 | 口径 |
|---|---|---|
| 每轮巡检一份报告 | `scan_reports` | `scan_id` 唯一约束即**一轮一报**——重复保存走 `platform.store.save_report` 的 upsert（`ON CONFLICT(scan_id) DO UPDATE`）覆盖 title/llm_status/status/payload 四列，行 id 不变、`created_at` 保留首建时刻；`scan_id` 外键 `ON DELETE CASCADE`（删 scan_runs 行时报告一并消失，不留孤儿行） |
| LLM 组织状态 | `scan_reports.llm_status` | 七态封闭集 `ok`/`disabled`/`unavailable`/`budget_exhausted`/`cancelled`/`skipped_empty`/`error`（`platform/store.py` 与 `report/pipeline.py` 逐字同值）；越界值 `save_report` 直接 `ValueError`——**LLM 有没有成功组织报告必须如实** |
| 报告正文 | `scan_reports.payload` | `PatrolReport.build` 产物的 JSON（16 键冻结，见巡检报告技能规格 §4）；读回时坏 JSON 兜底 `{}` |
| 保留期 | **无** `result_expires_at` 列 | 报告与 scan_runs 同属巡检元数据，跟着巡检轮次走，不计入 `purge_expired_feed()` 的核查结果保留期清理 |
| 读取面 | `get_report(scan_id)` / `latest_report()`（id 倒序第一条）/ `list_reports(limit)`（limit 夹取 ≥1） | 同 `latest_scan_run` 口径：`created_at` 在 upsert 覆盖时不改，自增 id 才反映"最近一次落到库里的报告" |

## 3. 发现源（计划决策：监控词 + 搜索引擎 + RSS 都要）

| 源 | 实现 | 授权 | 降级 |
|---|---|---|---|
| 搜索引擎 | `SearchDiscoveryProvider` 包 `retrieval.search.search_all`（360 主力/百度备用，内置验证码降级） | 逐次检查 `external_allowed("public-search")` | 未授权=degraded+明确原因（不静默）；后端全败=degraded |
| RSS/Atom | `RssDiscoveryProvider`：规则 `rss_sources` 配置，关键词过滤条目；热榜（无公开 API 的源）经 RSSHub 类中转后同样走此 provider | 同左（抓取也属外发） | 单源失败不影响其他源；坏 XML=`xml_parse_error`；DOCTYPE/ENTITY 剥离后未定义实体引用 → 整源拒读（fail-closed） |

安全：RSS 抓取复用检索层 `_host_is_public`（SSRF 防护不重复实现）+ 大小/超时上限；
XML 解析前剥 DOCTYPE/ENTITY。

### 用户信息源（v7：`patrol_sources`，rss / page）

在「搜索引擎 + 规则 RSS」之外开放**用户自建信息源**（平台页管理抽屉「信息源」区增删；
`PatrolSourceProvider` 消费，与内置源同一 `ProviderResult` 契约，绝不抛）：

| 类型 | 取数口径 | 反爬与降级 |
|---|---|---|
| `rss` | 复用 `RssDiscoveryProvider` 的抓取/解析路径（RSS 2.0 / Atom），再按 `_split_terms` 过滤条目 | 单源失败只记该源 degraded，不影响其他源；坏 XML / 超限 / 私网主机如实降级 |
| `page` | **页面链接粗糖提取**：安全取页（同 SSRF 防护 + 600KB / 10s 上限）→ `browser.extract_links` 抽链接（只收可靠档位域名、相对地址按 base 绝对化）→ 要求**锚文本命中监控词**（大小写不敏感）→ 上限 20 条 | 不抓正文、不渲染 JS；抽不到链接/无命中 = `no_links_extracted` / `no_matching_links`；反爬拦截（403/验证码页）如实降级为 `http_403` 之类，**绝不伪造候选** |

**全局 / 绑定语义**：源在 `patrol_query_sources` 里**没有任何绑定 = 全局源**（对所有
启用中的监控词生效）；有绑定 = 显式窄授权（只对绑定的词可见，`sources_for_query`
取「全局 ∪ 绑定本词」，仅 `enabled=1`）。绑定是窄授权不是广播：绑给 A 词的源对
B 词不可见。停用不删绑定（`enabled=0` 即对所有词不可见）。

**单源试运行**：`POST /api/platform/sources/{id}/test`（等价写法
`POST /api/platform/sources/{id}`）经 `PatrolSourceProvider.test_source(source, query, k=5)`
对**单个源**跑一次发现逻辑——不走 store 清单，保存前也能先试；`query` 缺省用源名、
再退备注。同步抓取（RSS/网页），超时由 provider 内部控制；返回
`{ok, item_count, sample_titles(前 3 条标题), error}`，`ok` 只表示「源可达且解析
成功」，不保证有匹配项，失败/零匹配如实进 `error`。

## 4. 两阶段巡检（成本控制）

```
for each 启用中的监控词（封顶 max_queries_per_scan）:
  阶段一（轻）：多源发现 → URL 去重 → 标题指纹去重（转载只留第一条）
    → 话题级热度估计（从本批结果估 x/y/z 算 E，零额外检索）
    → patterns.scan_markers 本地初扫（零 LLM）
    → 不过门槛（E < heat_screen_e 且无话术命中）只登记 status=new，不深查
  阶段二（重，预算封顶）：过门槛候选 → RumorAgent.analyze(标题+摘要)
    → DossierService 建档（input_kind='topic'，同话题再命中走 recheck 版本化）
    → verdict 回填条目（status=verified）
报告阶段（v12：status 定稿后、scan_runs 落账前跑一次；契约见巡检报告技能规格 §3）：
  PatrolReport.build(entries, queries, counters, warnings, prev_scan, cancel_check)
    → _aggregate 代码汇总（计数/分布/环比，零 LLM）
    → _narrate LLM 一次调用（预算 report.max_llm_calls 默认 1；
      时限 report.deadline_s 独立预算面，与深查互不占用）
    → 代码校验器（安全闸/截断/白名单，模型越界产物丢弃记 error）
    → summary["report"] 挂载 + scan_reports 落库（save_report upsert，一轮一报）
```

热度是**话题级**（整批共享一个 E：批内有大阅读量文章则全话题变热）——这是
`estimate` 的口径，不是缺陷。预算三重封顶：`max_candidates_per_query`、
`deep_verify.max_per_scan`、`deep_verify.deadline_s`（llm_cache deadline scope，
与 `CHAT_TURN_DEADLINE_S` 同机制，深查前查剩余预算）。

报告阶段是**增益面**（v12）：技能不可用（未注入且 import 失败）→ 只留 warning、
不产报告；`build` 自身承诺永不抛，runner 仍兜最外层异常；落库失败只留
「巡检报告落库失败：…」warning，报告已进 summary 照常呈现——scan 状态与返回
绝不被报告阶段拖累。`skipped`（未授权/无监控词）两条早退路径没有可汇总的一轮，
直接 return 不走到报告阶段。

### 领域查验链（v7：runner 每个监控词解析一次）

领域解析在候选循环**之前**做一次（读监控词整行 → `domains.resolve_domain`），
结果随条目落 `feed_entries.topic_domain` / `topic_domain_source`：

```
user（watch_queries.domain 非空且是已知领域）
  → inferred_text（inferred_domain 在 TTL 内，默认 30 天）
  → inferred_text（classify_domain：LLM 封闭枚举判定，成功即写回缓存）
  → inferred_history（store.domain_histogram() 最高项 ≥ history_min，默认 2）
  → none（""，不猜）
```

- **LLM 不可用就不猜**：`classify_domain` 在调用失败、返回自造领域、返回空串、
  文本为空时一律 None，由上层走历史分布 / none 兜底——与取证文化一致，绝不按
  关键词拍一个领域。领域表（12 项）与 `assistant/skills/taxonomy.json` 对齐，
  换领域只改 `platform_domains.json`。
- 领域解析失败/领域模块不可用 → 该词按「无领域模式」继续巡检并留 warning，
  不阻断巡检（段级降级）。
- **检索提示注入**：深查时 `domain_hints(domain)`（领域 `search_hints` 裸 host 清单）
  经 `RumorAgent.analyze(domain_hints=...)` 注入 rumor 检索一轮 `site:` 定向补搜
  （仅在既有轮次之后、且只在传入非空时生效；不传时行为逐位不变）。提示只用于
  定向检索，**不是权威认定**——资料可不可信仍由证据链负责。

## 5. 传播风险分级算法（`risk.py`，纯函数）

```
score = w_heat·E + w_growth·(环比×100) + w_breadth·覆盖面 + w_rumor·核查风险分
level = 阈值分档 notice/suspect/high/urgent，再应用 floors 保底规则
```

- 四因素各自 0-100：热度 E；环比增幅（`relative_change`，与 reminders 快照变化
  同口径）；覆盖面（独立条目数 / `breadth_full_sources`）；核查风险分
  （`verdict.assess()` 输出，无深查=0）。
- 权重/阈值/广度满值/floors 全部外置 `platform_rules.json` 的 `risk` 段；
  权重不和为 1、阈值不单调 → 整段退内置默认 + 告警。
- floors 例：`{min_rumor_score: 60, min_breadth: 50, level: high}`——核查结论差
  且传播面广时，即使加权分不够也保底抬档；保底只升不降。
- **输入契约即变异测试面**：坏类型/越界/NaN 一律抛；`rumor.label` 锁死
  `ALL_LABELS` 封闭集——大模型文本进不了分级链。
- 档位：`notice` 关注 / `suspect` 疑似 / `high` 高危 / `urgent` 紧急；
  **high 起算「大规模传播风险」**（信息流「预警」筛选 chips 与
  `/api/platform/warnings` 口径；无横幅、无推送）。

## 6. 降级与失败矩阵

| 情况 | 行为 |
|---|---|
| 外部检索未授权 | scan status=skipped + error=external_processing_not_authorized；平台页管理抽屉里出授权引导卡（链到设置弹层） |
| 结果保存关闭 | 条目只进当次 scan 返回，不写库；建档由 DossierService 自行门控 |
| LLM 不可用/深查异常 | 条目保留、status=verify_failed，风险只由热度+来源推导，**不编 verdict** |
| 单源/单监控词失败 | 该源/该词记 degraded + warning，不影响其余 |
| 取消（停机/用户在途删词） | 协作取消：已完成条目保留，scan 记 cancelled/partial；删词导致的外键冲突**不伪装成去重**（前置存在性检查 + 外键冲突原样抛） |
| 预算耗尽 | 停止开新深查，已完成的保留 |
| 记账（scan_runs）失败 | 只留 warning，不影响巡检本身 |
| 报告阶段（v12）：`report.enabled=false` / entries 空 / 生成前取消 | `llm_status=disabled` / `skipped_empty` / `cancelled`，**零 LLM 调用**；报告只有代码汇总（counts/topic_stats/highlights/changes/gaps），gaps 写明原因；零条目是**合法空结果不是失败** |
| 报告 LLM 不可用 / 预算耗尽 / 返回形状不符 / 缺全部关键键 / 调用抛异常 | `llm_status=unavailable` / `budget_exhausted` / `error`，记 error + gaps；title/summary 由代码兜底（「第 N 轮巡检报告」+ 确定性概述），叙事四区为空，代码汇总不受影响 |
| 报告产物命中安全闸 / 白名单外 / 超截断 | **该条丢弃**并记 error，其余字段照常落值；`llm_status` 仍按"模型是否正常组织出报告"如实记账 |
| 报告落库失败（`save_report` 抛：llm_status 越界 / 外键冲突） | 只留 warning「巡检报告落库失败：…」；报告已进 summary 照常呈现，scan 状态与返回不变 |
| 报告技能不可用（未注入且 import 失败） | 只留 warning「巡检报告未生成：报告技能不可用（模块缺失或装配失败）」，不产 report 键 |

## 7. 接口与入口

REST（`web/platform_api.py`，前缀 `/api/platform`）：`GET /status`（含
`external_authorized`）、`GET /feed?risk=&limit=`、`GET /warnings`、
`GET/POST/DELETE /watch`（409 重复/400 空或过长/404 不存在）、`POST /scan`
（单飞触发，后台执行）、`GET /scans`、`GET /scans/{id}`、
`GET /reports?limit=`、`GET /reports/{scan_id}`（v12，见下文）。

v7 新增 8 个端点（信息源 CRUD + 单源试运行 + 领域表 + 监控词领域手设；都不设隐私门
——它们只改本机配置，外发发生在巡检与试运行里，由 provider 自己按授权/SSRF 把关）：

| 方法与路径 | 成功 | 失败 |
|---|---|---|
| `GET /domains` | 200 `{domains:[{id,name,examples}]}`（12 项；加载失败退内置默认） | — |
| `GET /sources` | 200 `{sources:[…]}`（每项含 `query_ids` 绑定） | — |
| `POST /sources` | 201 `{id}` | 400 名称/URL 空或 kind 非 rss/page、400 绑定不存在的监控词、409 URL 重复 |

| `DELETE /sources/{id}` | 200 `{deleted:true}` | 404 |
| `POST /sources/{id}/test`（等价 `POST /sources/{id}`） | 200 `{ok,item_count,sample_titles,error}` | 404 源不存在 |
| `PUT /watch/{id}` | 200 `{updated:true}`（`domain` 空串 = 恢复自动推断，写入即清推断缓存） | 400 领域 id 非法、404 监控词不存在 |

外发授权门在巡检主流程已把关；payload 由 `platform.report.PatrolReport 生成，

|---|---|---|
| `GET /reports` | 200 `{reports:[{id, scan_id, title, llm_status, status, created_at, payload(解析后 dict)}], external_authorized}`（id 倒序；`limit` 夹取 1–50、默认 10；**空库是合法输出** `reports=[]`，前端据此隐藏报告卡，不演成失败行） | — |

平台页报告卡（`#platformReport`）只取 `GET /reports?limit=1` 的最近一份；加载失败与
"没有报告"分开呈现（失败出失败行，没有则隐藏卡片）。`scheduler.status()` 的
`last_summary` 只带 `{"title", "llm_status"}` 两个标量——payload 不背进状态响应，

## 9. 已知局限

- 热度 y/z 仍是代理口径（无站点公开文章级精确阅读量），E 只适合同口径相对排序。
- 热榜类源无公开 API，经 RSSHub 等中转接入（配置即接入，无需新代码）。
- 巡检默认关闭；web 不开服务就不巡检（CLI + 计划任务是另一通道）。
- 平台页复用 `style.css` 设计令牌（居中单列信息流，无左栏），但信息流条目暂不内嵌
  证据本展开（深查结论进档案库，档案库页看六章节）。
- `page` 类信息源是**列表页锚文本粗糖匹配**：不抓正文、不渲染 JS，靠锚文本命中
  监控词；重 JS 渲染的站点与需登录的页面取不到东西，会如实降级
  （`no_links_extracted` / `no_matching_links` / `http_403`），不伪造候选。
- 对话内平台卡的领域后缀读 `topic_domain`，但助手只读工具
  `assistant/tools_platform.py::_entry_view` 尚未透出该字段——字段已在前端就位，
  工具侧透出后对话卡才会显示领域（不猜、不留空徽章）。
- **报告引用的 entry_id 可能随 results 保留期清理失效，报告文本仍有效**：
  `analysis.entry_ids` 指向本轮落库的 `feed_entries.id`，而
  `feed_entries.result_expires_at`（「核查结果」类别，默认 90 天）到期后由
  `purge_expired_feed()` 清理——清理后按 id 回查原条目会查不到，但报告文本仍然
  有效（数字与叙述已冻结在 payload 里），只是"条目回溯"这一环断掉。报告自身
  **不设保留期**（与 scan_runs 同属巡检元数据，跟着巡检轮次走）；删 scan_runs 行
  会级联删掉挂在它上面的报告（v12 外键 `ON DELETE CASCADE`，不留孤儿行）。
