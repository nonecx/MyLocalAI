# 真流式评估（M4，2026-10-31）

> 性质：**只评估，不改主链路**。工作指导 §5.5："M4 评估真流式……**做否另拍板，不为它动主链路**"。
> 本报告给出事实、要动的面、收益与风险，结论段只给建议；拍板权留给作者。

## 1. 现状（M2-M4 的事实基线）

- 叙述采用**分句假流式**（`src/mylocalai/assistant/loop.py` 的 `_say`/`_split_sentences`）：
  `chat_text` 非流式拿全文后按中英文句读切 delta 逐个 emit `narrative` 事件；llm_client 零改动。
- 首字延迟：闲聊车道 ≈ 路由 LLM（1-3s）+ 叙述全文生成（2-6s）≈ **3-8s**；verify 慢查车道的叙述
  在工具完成（30-120s）之后才开始，叙述段本身 3-8s。
- 等待体验已有垫底设计（§5.3）：慢查先发本地初扫 markers（零成本）+ 组件级 progress 事件，
  卡片永远在叙述之前——白屏干等已被消掉，叙述首字只是最后一小段。

## 2. 真流式要动的面（为什么不是"加个 stream=True"）

| 面 | 具体改动 |
| --- | --- |
| llm_client | 新增 `stream=True` 路径：chunk 拼接、`reasoning_content` 增量过滤（LongCat 思维链）、正文/错误判据改为流式形态 |
| 超时/预算 | `llm_cache.attempt_timeout` 目前只约束建连与单次尝试；流式还要约束**读流循环**（每 chunk 前查 `budget_exhausted`），预算耗尽时"已流出部分保留 + 诚实截断" |
| 缓存/单飞 | 缓存只写**完整成功**结果（流完才落缓存）；single-flight 等待者拿到完整结果， leader 流式期间等待者照旧等——语义需测试钉住；缓存键口径不变 |
| 备用链/回落 | extra_body 400 回落必须发生在**首个 chunk 之前**（否则正文已漏出，重试会重复输出）；流中断（读到一半断）不能自动换提供方重发，只能报错收尾——"断流语义"要新定义 |
| 成本计数 | 流式响应 usage 常缺失或需显式开启（`stream_options={"include_usage": true}`）；M4 刚落地的 tokens 真实计数在流式路径可能退化为 0（口径诚实：如实 0，不估算） |
| mock 闸门 | `.tmp/verify-2026-10-22/mock_upstream.py` 需支持 SSE 分块响应，新增流式探针（首 chunk 时延、断流降级、取消中途生效） |
| SSE 端点/前端 | `drain_event_stream`/chat.js 已按 delta 逐帧渲染，**前端零改动**；只是 narrative delta 的来源从分句变成 chunk |
| 退役 | `_say`/`_split_sentences` 分句逻辑退役（或保留为流不可用时的兜底） |

## 3. 收益量化（首字延迟）

| 车道 | 现状首字（叙述首句） | 真流式预期 | 净收益 |
| --- | --- | --- | --- |
| 闲聊/追问 | 3-8s（路由+叙述全文） | ≈2-4s（路由+首 chunk） | **约 1.5-4s** |
| analyze_speech | 13-38s（工具 10-30s + 叙述 3-8s） | 11-31s | 约 2-7s（相对收益 10-20%） |
| verify_claim/recheck | 33-128s（工具 30-120s + 叙述 3-8s） | 31-121s | 约 2-7s（相对收益 **<5%**） |

结论：收益集中在**闲聊车道**的 2-4s；产品首要痛点（慢查 30-120s 的等待）真流式几乎不动——
那是工具执行时间，已有初扫+进度垫底。

## 4. 风险

1. **LongCat SSE 支持未知**（最大不确定项）：`.env` 提供方是否支持 `stream=true`、分块形状、
   思维链增量、流式 usage 是否返回——**只有拿真实密钥实测才知道**，离线无法验证。
2. **备用链在流中断场景的语义**：首 chunk 前可回落（安全）；首 chunk 后断流不可无感重试
   （用户已看到半截话）——要么接受"半截话+报错"，要么为重试引入去重/续写复杂度。
3. 回归面大：llm_client 是全项目唯一构造路径，超时/预算/缓存/回落/计数五件事与流式互相纠缠；
   M4 刚落地的成本真实计数与 CI 闸门也需要同步扩。
4. tokens 计数在流式路径可能拿不到 usage → 成本徽章退化（如实地 0），与 M4"口径诚实"不冲突
   但可观测性变差。

## 5. 结论（建议，不拍板）

**建议 M5 前不做真流式**，理由：
1. 收益错位：真流式改善的是叙述首字（闲聊省 2-4s），而产品定位的核心等待（慢查取证 30-120s）
   它一动不动，且等待体验已被初扫+进度+卡片垫住；
2. 风险/收益比差：要动全项目唯一 LLM 构造路径的超时/预算/缓存/备用链/计数五处语义，还要扩
   mock 闸门，最大不确定项（LongCat SSE 行为）离线不可验证；
3. 时机：M4 的成本计数与 CI 刚落地，应先让主链路在新观测面上稳定一个里程碑。

**给作者的拍板输入**（若要推翻上述建议，先做这两件事）：
- 用 `.env` 的真实密钥对 LongCat 做一次 10 分钟实测：`stream=true` 是否可用、chunk 形状、
  `stream_options` usage 是否返回、思维链增量形状——结果直接决定 §4.1/§4.4 两条风险的成色；
- 若 M5 走 L5（哨兵+降本）路线，真流式可与降本（省 token 的分句截断等）合并评估，一次动
  llm_client 的面摊薄两次改动成本。
