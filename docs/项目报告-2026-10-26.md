## 一、项目概述

**MyLocalAI** 是一套"网络言论智能分析与谣言识别"系统：对一段网络文本（评论、帖子、聊天记录）做多维度分析与风险判定，并提供交互式展示网站和可被 MCP 客户端接入的谣言识别 Agent。全部实现基于**提示词工程 + 大模型 API**，无需 GPU。

### 关注度（Attention）评估（2026-10-26 新增）

新增 `attn_agent/`：把「一件事有多少人关注」变成一个**可离线复现的确定性分数**。

```
E = 100 * (1 - exp(-λ · S))
S = w_x·ln(1+x)/ln(1+x0) + w_y·ln(1+y)/ln(1+y0) + w_z·ln(1+z)/ln(1+z0) + ε
```

- `x` = 文章数量，`y` = 文章阅读量，`z` = 文章留言量
- 默认参数：`x0=100, y0=100000, z0=1000, w_x=0.2, w_y=0.5, w_z=0.3, λ=0.7, ε=1e-6`
- 约束：`w_x+w_y+w_z = 1` 且各权重 `> 0`；`x,y,z ≥ 0`；`E ∈ (0, 100)`
- `E > 66` 进入「高关注」档并触发深读（`deep_read_triggered` 严格大于才算）

**定标点**：`E(100, 100000, 1000) = 50.3415`；`E(0,0,0) ≈ 7.0e-5`（严格 > 0）；
`E(1e12,1e12,1e12) ≈ 91.9385`（永不达到 100）。

**实现中修复的真实缺陷**：直接照写 `100*(1-exp(-λS))` 在双精度下会违反 `0 < E < 100`：
`x=y=z=1e300` 时 `1 - 4.6e-28` 舍入成 `1.0`，E 恰好等于 `100.0`；外置配置给出极小 `ε` 时
又会舍入成 `0.0`；原实现用 `assert` 守边界，在 `python -O` 下被整段剔除、静默返回 `100.0`。
修复为等价的 `100 - 100·exp(exponent)` + `math.nextafter` + 显式 `if` 校验，
正常量级下与原公式偏差 `1.42e-14`（远小于测试容差 `5e-10`）。

**实测结论（5 个真实话题，2026-10-26 取证）**：反解 `E=66` 得 `S66 = 1.541157`。
由于 `ln(1+v0)/w` 三维几乎相等（`H_x=23.076, H_y=23.026, H_z=23.029`，偏差 0.216%），
公式等价于一个**纯乘积预算** `GM(x,y,z) ≥ 138,401`。
本批话题（老干妈 54.81、阿雅 51.56、长鑫 49.82、花生地 46.85、男子出狱 41.75）
**无一达到 66**，缺口 1.36~2.57 个数量级；越过 66 需要 `y` 达 1e8（一亿）量级且 `x`/`z` 同步配合。
详见 [关注度评估报告-2026-10-26.md](关注度评估报告-2026-10-26.md)。

**已知局限**：`attn_agent` 曾只有测试调用方（`main.py` / `core_judge.py` /
`report_generator.py` 均未 import），`E>66` 触发深读是"已实现未接线"的设计意图；
**2026-10-27 已接入网页端**（见下），`main.py` / `core_judge.py` 仍未接入。
且本批 `y` 全部是平台热度指数或转引口径而非真实阅读量（无站点公开精确阅读量），
`E` 只适合同口径下的相对排序。

#### 网页端接入（2026-10-27）

`my_website/start.bat` 打开的页面，首页下方新增「📈 关注度（Attention）评估」面板，
提供三个入口：

| 入口 | 接口 | 行为 |
| --- | --- | --- |
| 🔢 手动输入 x/y/z | `POST /api/attention` | 纯确定性算分，返回 E、S、三个分项、档位、是否触发深读、阈值反解值 `S66=1.541157` |
| 🛰️ 话题联网估参 | `POST /api/attention/search` | 输入话题 → `attn_agent/estimate.py` 走真实检索估出 x/y/z → 算分，并回带证据来源 URL 与取数说明 |
| 分析记录内嵌 | `POST /api/analyze` 的 `attention` 字段 | classic / agent 两种模式都附一个确定性关注度分（估计口径，页面标注徽章） |

新增 `attn_agent/estimate.py`：把一次真实检索转成公式的三个输入。
`x` = 按 URL 去重后的独立文章数；`y`/`z` 从标题与摘要里抽取公开的中文数量词
（「阅读量 4831.6 万」「287 条跟贴」），抽不到则保守兜底并**显式标注 estimated**。

**实现中修掉的两个真实缺陷**（由 `tests/test_website_attention.py` 的用例抓出）：
1. 正则把「22小时前」读成 22 条评论（`_GAP` 允许关键词与数字之间夹非数字字符，
   于是 `评论 22小时前` 中的 22 被捕获）——已加时间词排除，且覆盖「数值在前」的中文语序；
2. 「已有 287 条跟贴」「浏览次数 890 万」这类写法完全漏抽，导致 `z` 被系统性低估。

**读数边界**：话题模式下 `x` 是下限、`y`/`z` 是代理值，页面一律显示
「代理 / 估计值」徽章；`E>66` 时提示深读链路尚未接入网页端，只给分数与分项。


## 三、两条分析路径

| | classic（网站默认 / main.py） | agent（谣言识别） |
| --- | --- | --- |
| 流程 | 情感 + 攻击性 + 逻辑三路并行分析 → 规则引擎四档结论 → 报告 | 七路分析 + 联网搜索证据本 + 受控浏览原文 → 标签 + 0-100 风险分 |
| 结论档位 | 高度疑似水军/煽动、疑似情绪化谣言、理性探讨、情绪化宣泄/普通争论 | 高风险谣言、疑似谣言、存疑待核实、低风险、无可核实陈述 |
| 判定来源 | 代码 if-else 规则引擎（大模型不参与打分） | `verdict.assess` 纯函数（同样大模型不参与打分，注入改不动） |
| 耗时 | 约 10-30 秒（三维并行后单次全链路实测 10.65s） | 约 30-120 秒（含联网） |

两条路径均有降级设计：单模块失败不影响整体，报告回退本地模板，Agent 超时只用已完成组件。

### 10-26 关注度模块的工程收获

1. **实现期就抓出并修复一个真实的浮点缺陷**：直接写 `100*(1-exp(-λS))` 在双精度下，
   `x=y=z=1e300` 时 `1 - 4.6e-28` 舍入成 `1.0`，E 恰好等于 `100.0`，违反 `0 < E < 100` 的硬约束；
   外置配置给出极小 `ε`（如 `1e-20`）时又会舍入成 `0.0`；原实现用 `assert` 守边界，
   在 `python -O` 下被整段剔除、静默返回 `100.0`。改用等价的 `100 - 100·exp(exponent)`
   + `math.nextafter` + 显式 `if` 校验修复。
2. **独立交叉复核抓出 3 类口径错误**：`z` 把网易详情页 JS 未加载的占位 0 当实测值（3 个话题）、
   `x` 五种口径互不兼容（跨平台文章数/单平台条目数/Bing 索引数/热榜条目数/含旧文数）、
   `y` 是随时间漂移的快照（重取无一相同，花生地 +175%）。
3. **阈值标定发现结构性问题**：`ln(1+v0)/w` 三维几乎相等（偏差 0.216%），
   公式等价于纯乘积预算 `GM(x,y,z) ≥ 138,401`；默认参数下 `E>66` 需要 `y` 达 1e8 量级，
   本批 5 个真实头部话题 0/5 触发。
4. **测试有效性经变异测试证明**，不是"为了通过而写"。

## 六、可配置性亮点

判定口径全部外置 JSON，换行业/换标准**不需要改 Python**：

- `rumor_agent/verdict_rules.json` —— 分层阈值、风险分阈值、封顶、抬分锚点、稳定性护栏、话术权重
- `rumor_agent/sources_registry.json` —— 信源分级名单、渠道权重
- `rumor_agent/prompts.json` —— 三模块 System Prompt、报告模板、枚举白名单
- `shared_core/providers.json` —— 提供方表（密钥/地址/模型名成组绑定）
- `attn_agent/attn_rules.json` —— 关注度参数、档位表、深读阈值（写坏退回内置默认并留中文告警，不抛异常）

配置写坏退回默认并留告警，不崩溃、不静默降级。言论分层仅 `tiering.py` 一处实现，classic 与 agent 共用。

## 七、已知局限

1. **单一提供方为默认**（LongCat），备用链路需自填密钥。
2. **本地备选推理不可用**：modelscope 缺 `addict`、HF 模型 config 缺 `model_type`，主链路走 API。
3. **上游模型不认 seed**：temperature=0 仍有采样漂移，复现性靠进程内缓存（TTL 900s），进程重启/多进程部署会重新显现。
4. **`distill/` 蒸馏未跑通**：测试集就绪，缺训练脚本与教师标注规模。
5. **信源名单人工整理**，名单外好来源保守归为"未知来源"。
6. **演示级部署**：网站 127.0.0.1、单进程、无鉴权，历史记录在内存。
7. **CLI 的 `attention` 字段默认仍是占位值**：`core_judge.judge()` 默认不联网，
   返回基准值（E≈50.34），仅表示链路已接通，**不代表真实热度**。加 `--attention-online`
   可联网估参，失败会自动退回占位值；真实量级也可用网页端「🛰️ 话题联网估参」查看。
8. **深读解读的质量取决于 LLM**：`deep_read` 在 `E>66` 时生成三段式解读，但 LLM 不可用时会
   回退到本地模板（只给提问框架，不是实证分析），并以 `degraded: true` 标注。
9. **关注度阈值偏高是结构性问题，已提供 `reachable` 档位作为可选解**：默认 `spec` 档
   （原始参数）下 `E>66` 需 `y` 达 1e8 量级且 `x`/`z` 同步配合，本批 5 个真实头部话题
   0/5 触发（最高 54.81）。根因是 `ln(1+v0)/w` 三维几乎等价格（偏差 0.216%），
   公式等价于纯乘积预算 `GM(x,y,z) ≥ 138401`，任何单项暴涨都被另外两项的稀疏抵消。
   `reachable` 档通过拉大三维"单价"差异（`y0: 1e5→1e6`、`z0: 1e3→300`、`w: (0.2,0.5,0.3)→(0.3,0.4,0.3)`、
   `λ: 0.7→0.8`）把 `y` 项占比从 67.7%~85.2% 压到约 51%~73%，使"千万阅读/千篇/十万留言"级别
   可达标；但低热度话题仍不触发。是否切默认档属产品决策，需业务确认，故保留 `spec` 为默认。
10. **关注度的 `y` 无精确口径可用**：本批 `y` 全部是平台热度指数（头条 HotValue）或转引口径
    （微博话题阅读量），没有任何站点公开文章级精确阅读量；HotValue 还是实时快照
    （重取无一相同，花生地 +175%）。网页端话题模式下 `y` 走检索摘要兜底，
    页面已标注「代理 / 估计值」，但 `E` 仍只适合同口径下的相对排序，不能做绝对解释。
11. **`classify` 与 `deep_read_triggered` 对 66 的语义不一致**：前者用 `>=`（66.0 归"高关注"），
    后者用 `>`（66.0 不触发深读）。修改任一侧都会改变既有行为，故保留现状并在此记录。
