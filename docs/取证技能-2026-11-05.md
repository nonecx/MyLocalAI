## 1. 定位与关键边界

取证三技能位于 `src/mylocalai/assistant/skills/`，是**只读取证**链路，回答三个问题：
这段内容在谈什么、该去哪里查、查到了什么。工具权限 `read`：不写档案、不改评分、
不写回信源目录。

两条关键边界，任何时候都不过界：

- **权威网站身份 ≠ 具体证据**：一个域名是官方权威，只说明它有资格被检索，
  不代表上面某段话就是本案的证据。
- **找到证据 ≠ 证明原文**：证据说明"某信源在某时点这样表述"，与关系标注
  （supports / refutes / partial / background / unclear）一起呈现；真假裁决留给用户。

## 2. 三技能分工

| 技能 | 输入 | 输出 | 不做什么 |
|---|---|---|---|
| 领域识别（domain） | 用户原文 | 主/次领域、核心议题、地区、时间、分类状态 | 不判真假、不联网、不看立场情绪 |
| 信源发现（sources） | 领域 + 议题 + 地区 | 机构官网、适用范围、身份与适用范围核验依据 | 不把搜索排名/域名后缀当权威 |
| 证据检索（evidence） | 原文 + 已核验信源 | 逐条主张的可定位引文、初步关系、局限 | 不给最终真假分、不扩到未核验域名 |

三技能是**执行阶段**，不是面向用户的第五种能力；面向用户的能力层在
`src/mylocalai/assistant/capabilities/`（事实核查 / 证据研究 / 话题理解 / 言论理解）。
取证三技能目前由证据研究能力（evidence-research）经 collect_evidence 工具驱动。

## 3. 目录结构

```
src/mylocalai/assistant/skills/
├── __init__.py          只导出 collect_evidence / EvidenceSkills
├── pipeline.py          确定性编排：三阶段、预算、校验、去重、报告渲染
├── transport.py         安全取页：DNS 钉扎、逐跳重定向复核、体积/时限上限
├── taxonomy.json        领域表（id/定义/示例）
├── sources.json         信源目录（机构/域名/领域/地区/资料类型）
├── rules.json           预算与上限（搜索/读页/模型调用/时长/引文长度）
├── domain/SKILL.md      技能指令：分类口径与边界案例
├── sources/SKILL.md     技能指令：选站与核验口径
└── evidence/SKILL.md    技能指令：主张拆分与引文提取口径
```

`skills/propagation.py` 是既有的传播记录工作流（被 `core/claim_checking.py` 与隐私
偏好门使用），与本次三技能并存，不要混为一谈。

## 4. 执行流程

```
原文
  ├─ 预检：非空、≤ max_input_chars                → 违反：needs_clarification（不检索）
  ├─ 阶段1 领域识别：分类结论 + 标签白名单校验 + 依据原文定位
  │     └─ insufficient/ambiguous/uncovered/multi_topic → needs_clarification（不检索）
  ├─ 阶段2 信源发现：目录候选 + 模型选择 + 一次中性机构搜索
  │     ├─ 读取候选首页（域名允许集限定）
  │     ├─ 模型给身份/适用范围判断，引文必须逐字出现在已读正文
  │     └─ 程序独立判定可信锚点；未核验候选不得进入阶段3
  ├─ 阶段3 证据检索：拆主张（逐字定位原文）→ 逐主张 × 逐已核验信源
  │     └─ site: 限定搜索（代码拼接）→ 读正文 → 模型抽引文 + relation
  ├─ 引文必须逐字定位已读正文，否则记错误并丢弃
  ├─ 去重：正文哈希 + 引文归一化合并为同一证据链（转载不产生新证据）
  └─ 缺口 / 错误 / 预算 / 覆盖 → 确定性报告（render_report）
```

顺序锁定：先分类再选站再取证。阶段1四态与预检失败一律先追问，不带着模糊输入检索；
主张数超过 max_claims 时要求用户缩小范围，保留已拆部分。

## 5. 安全模型（代码约束，不依赖模型判断）

逐条落地，每条都有对应测试锁定：

1. **逐跳重定向复核**：每一跳都重新校验 http(s)、URL 无凭据、主机名非本机/非私网、
   域名在允许集内；超过 max_redirect_hops 跳即失败；Location 缺失或非法记
   redirect_invalid。
2. **DNS 钉扎**：连接前解析全部 IP，任一为私网/环回/链路本地/保留/组播即失败；
   公网私网混合解析直接失败；连到校验过的 IP，TLS 仍按原主机名校验。
3. **域名允许集**：证据检索只能读已核验信源的域名；`site:` 由代码拼接；模型生成的
   `site:`/`inurl:`/`intitle:`/`filetype:` 等范围操作符一律剥掉。
4. **正文可定位**：引文必须逐字出现在已抓取正文里，并记录归一化字符偏移；否则丢弃，
   不用模型转述补位。搜索摘要、截图本身不是已核验证据。
5. **来源不自我认证**：陌生域名即使页面自称权威、模型也说"匹配"，最多记为
   unverified_candidate，不能进入证据检索。可信锚点只有两类来路：目录 anchor 声明，
   或已核验站点页面直接给出的链接（链接抽取用代码，不靠模型）。
6. **外发脱敏**：邮箱、手机号、身份证号、URL 在生成检索词前剥离（strip_pii）。
7. **渲染转义**：报告走确定性纯文本渲染，无 HTML、无 markdown 链接语法风险，
   避免注入 GUI。
8. **不扩权**：工具权限 read，不写档案、不改评分、不写回信源目录。
9. **取消与死线**：取消后不发起新网络/模型调用；单次 IO 有 io_timeout_s，
   整个任务有 total_deadline_s，到点即停但保留已取得证据。

## 6. 状态取值

执行状态（status）六种，封闭集合：

```
completed / partial / needs_clarification / failed / cancelled / budget_exhausted
```

判定口径：

- `cancelled`：cancel_check 命中即停（保留已取得证据，状态=cancelled）；
- `budget_exhausted`：任一项预算或死线到顶即停（保留已取得证据）；
- `needs_clarification`：预检失败 / 阶段1 分类四态 / 主张超限（回复说明缺什么）；
- `failed`：连阶段1 都进不去（如 LLM 完全不可用且无缓存分类），或全程无任何有效
  产物且不属上面三类；
- `partial`：有产物但有错误/缺口/覆盖不全（最常见）；
- `completed`：走完全部计划步骤且无未消化错误。

任务状态（task_status）与执行状态分开记录：`completed` / `no_factual_claim` /
`needs_clarification`。其中 **no_factual_claim 表示原文没有可核查事实主张，
status=completed——没有可核查主张不是失败**。

取消与预算耗尽都保留已取得的证据，绝不整批丢弃。错误、预算耗尽、取消、空结果、
未开始必须区分，不用单一 degraded 覆盖。

## 7. 预算与可观测

`src/mylocalai/assistant/skills/rules.json` 控制全部上限，键名锁定
（默认值为整理时口径，改这里不改代码）：

| 键 | 默认 | 管什么 |
|---|---|---|
| `max_input_chars` | 4000 | 原文长度上限，超出 needs_clarification |
| `max_claims` | 5 | 可拆主张数上限，超出要求缩小范围 |
| `max_sources` | 6 | 进入证据检索的已核验信源数 |
| `max_candidates` | 8 | 阶段2 候选信源数 |
| `max_searches` | 12 | 全任务搜索次数 |
| `max_pages` | 12 | 全任务读页次数 |
| `max_llm_calls` | 20 | 全任务模型调用次数 |
| `per_claim_max_queries` | 2 | 单主张检索词个数 |
| `per_claim_max_pages` | 3 | 单主张读页个数 |
| `max_followup_rounds` | 1 | 补充检索轮次 |
| `total_deadline_s` | 90 | 整个任务死线（秒） |
| `io_timeout_s` | 10 | 单次网络 IO 超时（秒） |
| `max_page_bytes` | 1500000 | 单页正文字节上限（解压后） |
| `max_text_chars` | 20000 | 单页正文保留字符上限 |
| `max_redirect_hops` | 3 | 重定向跳数上限 |
| `max_quote_chars` | 300 | 单条引文长度上限 |

每次任务记录三段可观测数据：

- `audit`：每次 search / fetch / llm 操作的目标与成败；
- `budget`：已消耗量与各项上限的对照；
- `errors`：阶段（precheck / domain / sources / evidence / dedup）+ 类别 + 简述。

报告末尾如实写明"已执行 N 次搜索、N 次读页、N 次模型调用"。

## 8. 与用户能力层的接口

- 证据研究能力（`capabilities/evidence_research/SKILL.md`）经工具 `collect_evidence`
  驱动本流水线：`collect_evidence → assistant.skills.pipeline`。
- 工具注册、权限（read）、成本（heavy）、预估耗时（30-120s）以
  `src/mylocalai/assistant/registry.py` 注册表为唯一规范来源；`assistant_rules.json`
  的 tool_allowlist 控制放行。
- 返回形状（status / task_status / data / gaps / errors / audit / budget / report）
  见 pipeline.py；本文件不复制，避免双维护。

## 9. 局限

1. **权威网站身份 ≠ 具体证据**。目录 anchor 与已核验站点链接只决定"有资格被查"，
   不决定查到的内容可用；每一条证据仍要逐字定位实际读取的正文。
2. **找到证据 ≠ 证明原文**。引文加关系标注只呈现"某信源在某时点这样表述"；
   不输出真假判定，不输出数值评分。
3. **不解析 PDF**。`application/pdf` 一律记 unsupported_type，如实记错误，不当正文。
4. **转载不产生新证据**。同正文哈希/归一化引文合并为同一证据链，不按数量虚增。
5. **覆盖受预算硬约束**。搜索/读页/模型调用/时长到顶即停，保留部分结果并如实标注
   未完成阶段；部分完成不是完整成功。
6. **单次中性机构搜索**。阶段2 只做一次中性机构搜索补候选，不做开放式全网爬取。
7. **不判真假**。报告全文不得出现真假判定词；"辟谣/证伪"只可作为来源性质描述出现，
   结论区一律只述证据。
