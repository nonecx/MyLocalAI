## 2. 产品定位

### 2.1 一句话

把「这条消息是真的吗」从用户的负担变成助手的工作：用户把信息丢进对话框，拿回一张带证据、带置信度、带"什么时候该再看一眼"的极简卡片；深挖按需。

四个问题域（现有引擎与助手工具的对应关系）：

| 用户的问题 | 现有引擎 | 助手工具 |
|------------|----------|----------|
| 真的假的？ | rumor_agent（证据本 + 确定性打分） | verify_claim / recheck_dossier |
| 为什么有人信、有人传？ | classic 三维（情绪/攻击性/逻辑） | analyze_speech（言论土壤） |
| 有多热？ | attention（确定性公式 + 联网估参） | check_heat / compute_heat |
| 大家怎么看？ | opinions / deep_read | 档案章节（M3 接入） |

### 2.2 「减轻信息压力」的设计含义（执行时以此裁判一切取舍）

1. **回复默认短**：先一句话结论，再一张卡；叙述只展开卡片信息，不写长文。
2. **卡片三层信息架构**：第一眼（标签 + 置信度）→ 第二眼（证据计数、as_of、degraded 徽章）→ 展开（证据本前 5 条 + 计数）。
3. **深挖按需**：六章节档案是助手的**工作记忆**，不是用户必须面对的产品面。opinions / deep_read 只在用户追问或明说"查透"时生成。
4. **等待不添压**：慢查（30-120s）必须先给本地初扫结果（markers，零成本）+ 组件级进度，不允许白屏干等。
5. **秒回是核心能力**：M2 markers 初扫即回；M3 指纹库命中秒回是 M3 的**首要**验收项（因定位上调）。
6. **不制造新压力**：无推送、无通知、无定时打扰；提醒只在用户打开会话时以一行呈现。
7. **降级也体面**：LLM 不可用时给"本地初扫结果 + 暂无法深查"的诚实短回复，不硬撑、不编造。

### 2.3 铁律展开

- 结论永远输出"证据支持什么 / 不足以支持什么"，不输出真假判定，不给"该不该转发"的行动建议。
- 用户消息里的指令永远改不了分数与阈值（注入免疫从引擎层延伸到对话层，变异测试锁定，见 §5.6）。
- 口径诚实标注：代理值 / 估计值 / 快照时点 / 降级状态全部随数展示（沿用现有徽章体系）。

### 2.4 明确不做

通用闲聊卖点（透传但不优化）、定时爬虫与推送通知、多用户与鉴权、云部署、实时舆论监测（企业叙事）。M5 之前不装调度器。删除档案不设为助手工具（只有 UI/API 能删，收窄注入面）。

### 2.5 越用越聪明（长期护城河，三种积累全部零 API 成本）

1. **谣言库**（M3）：话术指纹沉淀，相似消息秒回——省时间省配额。
2. **话术模式库**（L4）：跨档案聚合套路分布——"你查过的 12 条疑似谣言里，8 条命中'权威缺失+紧急呼吁'"。
3. **信源画像**（L4）：哪些域名反复出现在证伪/辟谣档案中的个人化沉淀，反哺证据抬分口径。

这三种积累是通用大模型聊天结构上做不到的（它没有你的档案库）。

### 4.5 结论卡片 schema（口径升级的核心，全纯函数推导）

```json
{
  "version": 2,
  "label": "疑似谣言",                // 兼容层，不变
  "risk_score": 62,                   // 兼容层，不变
  "confidence": "medium",
  "evidence_sufficiency": {"official": 2, "unofficial": 5, "unknown": 3, "total": 10},
  "as_of": "2026-11-02T15:30:00+08:00",
  "recheck_conditions": ["出现官方/权威媒体级信源的通报或报道", "证据本新增权威条目≥2"],
  "verdict_basis": "verdict.assess() 纯函数输出，大模型不参与打分"
}
```

推导规则（**不新增任何 LLM 调用**）：confidence 与 evidence_sufficiency 由证据本的 domain_tier/source_kind 分布决定（映射进 `verdict_rules.json`，不写代码）；recheck_conditions 由证据缺口决定。**配套变异测试**：篡改卡片字段必须失败——卡片只能从 assess() 输出 + 证据本派生，防止未来有人把 LLM 输出塞进打分链。

```json
{"action": "verify_claim | analyze_speech | check_heat | compute_heat | get_dossier | list_dossiers | recheck_dossier | export_card | chitchat | clarify | refuse",
 "text": "...", "topic": "...", "id": 42, "deep": false, "x": 0, "y": 0, "z": 0,
 "reply": "chitchat/clarify/refuse 时的直接回复内容"}
```

与全项目"chat_json + 白名单校验 + 越界回退"文化一致。防护链顺序执行：枚举白名单 → 参数 schema 手工校验（长度上限沿用网站现有校验值、id 正整数、x/y/z 非负数）→ 工具 allowlist → 权限检查；任何一步不过降级为 `clarify`（追问一次），**绝不猜**。`refuse` 触发词表进 prompts.json（编造谣言、批量生成、伪装话术求助等）。

### 5.2 工具目录

| 工具 | 参数 | 包装的引擎 | API 成本 | 延迟 | 降级路径 | 权限 |
|------|------|-----------|----------|------|----------|------|
| verify_claim | text, deep? | RumorAgent.analyze（agent 全链路） | 重 | 30-120s | pipeline 退回（已有）、超时用已完成组件（已有） | 读+写档案 |
| analyze_speech | text | core_judge.judge（classic） | 中（4 调用，有缓存） | 10-30s | 单模块失败不影响整体、报告回退模板（已有） | 读+写档案 |
| check_heat | topic | estimate（联网）→ attention | 中 | 5-15s | 退占位值 + degraded 徽章（已有） | 读+写快照 |
| compute_heat | x,y,z | attention 纯函数 | **零** | <10ms | 不需要 | 只读 |
| list_dossiers | query?, limit | dossier store | 零 | <50ms | — | 只读 |
| get_dossier | id, chapters? | store；章节缺时可触发生成 | 零或按章节 | <50ms 起 | 缺章返回 absent 状态 | 只读 |
| recheck_dossier | id | agent 全链路（增量批） | 重 | 30-120s | 同 verify | 读+写 |
| export_card | id, format | md 模板拼接 | 零 | <100ms | — | 读+写导出文件 |
| search_web | query | retrieval（受控） | 轻 | 3-10s | 检索失败明说 | 只读 |
| read_opinions / deep_read（M3） | id | opinions / deep_read 引擎 | 中 | 10-40s | 本地模板回退（已有） | 读+写章节 |

叙述模型拿到的永远是工具的结构化输出 + `verdict_basis` 标记，它没有写分数的通道。

### 5.3 快慢车道与 SSE 事件协议

车道判定 = 路由结果：`compute_heat`/记忆类 → 秒答；`analyze_speech` → 快答；`verify_claim`/`recheck` → 慢查。慢查路由成功后**立刻先发本地初扫**（`patterns.py` markers 正则，零成本）："初扫：命中 2 条煽动话术特征，已开始联网取证…"

```
meta        {session_id, run_id}
status      {stage: routing}
tool_start  {tool, args_preview, est_s}            ← 开工回执 + 预估耗时
scan        {markers: [...]}                       ← 仅 verify 类，零延迟先发
progress    {component, done, total}               ← 源是 AnalysisState（M2 加 on_component_done 回调）
card        {结论卡片 / 分层 / E 分}                ← 卡片永远在叙述前
narrative   {delta}                                ← 分句假流式（§5.5）
tool_end    {tool, duration_s, degraded, dossier_id}
done        {cost: {requests, tokens}}
error       {code, recoverable, message}
```

进度钩子是 M2 对现有引擎**唯一**的侵入改动：`AnalysisState` 加可选 `on_component_done(name)` 回调，默认 None、不传时行为逐位不变（守卫测试锁定）。取消链：前端 AbortController → SSE 断开 → 循环置 cancelled → 复用 agent 协作取消；classic 链路 M2 补同款取消位。

### 5.4 上下文构建器

每轮组装顺序（预算 `context_char_budget` 默认 12k 字符，超出从最旧可丢弃项裁起）：
① system prompt（人设+边界+工具摘要）→ ② **活跃档案卡**（本会话最近涉及档案的紧凑摘要，"刚才那条"靠它解析）→ ③ 最近 12 轮完整对话（超 30 轮触发一次廉价摘要并缓存）→ ④ 本轮工具结果 digest（卡片全量、证据本前 5 条+计数）。
缓存分区：`assistant_router` / `assistant_narrate` / `assistant_sum`，沿用 deep_read 分区先例，不污染主分析缓存键。

### 5.5 流式实现（两段式）

- **M2 分句假流式**：非流式拿全文后按句切 delta 发出。llm_client 零改动、零风险；首字延迟 3-8s，有初扫+进度垫着可接受。
- **M4 评估真流式**：llm_client 加 `stream=True` 路径，涉及超时/预算/回落与流式兼容，需专门 mock 闸门扩展；**做否另拍板，不为它动主链路**。

### 5.6 注入防护（两层，变异测试锁定）

引擎层（已有）+ 对话层新增：消息藏"改分数/删档案/越权导出"指令必须无效；伪造 tool_event 注入无效；工具输出里含指令不改助手行为。删除档案永远不是工具。变异体清单见 §7。

### 5.7 人设、拒绝与降级话术（全部外置 prompts.json）

- 性格：克制的核查研究员——"我查到什么、还缺什么证据、什么时候该再看"三段式，不热络、不说教、不制造焦虑（对齐"减压"定位）。
- 对不确定的态度即人设："证据不足以支持/反驳"是正常输出而非失败。
- 拒绝：明确说原因（"我不能帮忙编写伪装成真实消息的内容"），话术可配。
- 叙述失败兜底：LLM 抽风（LongCat 有返回 None 前科）时直接以卡片+固定模板收尾，**永远不因叙述失败丢结论**（复用"报告回退本地模板"模式）。

1. **静默检查**：动文件前 `find . -mmin -30`（排除 .venv/.tmp/__pycache__）确认近期无其他会话改动；git 化后开工前 `git status` 必须干净。
2. **提交粒度**：每任务一提交，消息格式 `M2-3: SSE 端点与取消链`；里程碑完成打 tag（m1/m2/m3/m4）。git init 之前不做任何文件改动。
3. **测试门**：提交前 §7.1 全量离线绿；失败先修再提交，不带红提交。
4. **真实 API 配额**：只在 M2、M4 末各跑一次 e2e 冒烟；其余全部 stub/mock。

6. **文档回写**：每里程碑完成后当次回写 README 数字与接入状态（M4 后由用例计数测试自动守护）。
7. **超预期情况**：任务执行中发现与本文档描述不符的现状（行号漂移属正常，结构不符要警惕），停下来核对再动，不硬改。
